# G4 actual-code exploratory protocol v1

This run is authorized by the researcher's current local-only G4 instructions. It is exploratory: the eight existing source families and published answers are development material, with no unused holdout. No human cohort is reanalysed or combined. No performance target is invented.

Base revisions: codex 76bd22d; handcaptcha b4d96d1. The original checkout remains untouched. Source data is read from a separate read-only working copy; private local path configuration and detailed rows stay in ignored data/. No commit/push occurred during the experiment. The researcher subsequently authorized publication of code, documentation and deidentified aggregates.

CPU only. Fixed seed 20261028. One deterministic response per source/attack, no query optimisation or retries. Nine predefined generators on eight known sources, plus every different library source (56 wrong-source pairings). Operational input limits are resource guards, not scientific thresholds. Existing .25 score threshold, 38 degree gate and 200ms hold are read directly from the actual HTML and remain unchanged.

The computation channel extracts the exact ang/pp/rs/mA/mDA/mAc/es/computeScores and onRes function bodies from the actual HTML without executing page startup, CDN, fetch, upload or camera code. Scoring uses the actual within-clip keyframes with shared boundary frames, partitioning replay by phase/index. These partitions are fixtures rather than observed UI callback segments. Raw oracle input preserves source frame indices and nulls; generated complete-coordinate attacks use detected-source times. Gate callbacks advance actual keyframe targets with rendering/video scheduling stubbed. Submitted replay times feed the fake clock. Therefore this is an offline computation/input assay, not a full two-clip browser session, real-time camera evaluation or trusted capture proof.

Outcomes: actual raw/estimated/final score and .25 pass; actual onRes matching gate separately; validation rejection separately; new loopback-only server protected test action separately. Original system L3 remains NOT_TESTED because no historical protected endpoint is established. A new local server must recompute results from input, bind issued challenge to cookie session/action, expire challenges, and consume an accepted grant only once. It does not establish camera provenance.

Additional explorations: fixed vs almost-fixed input to test stationary rejection; known-library wrong answers; circle/metadata channel ablation where actual video decoding is available. No reuse of these development results as unseen validation. Success is a reproducible outcome with complete logs; research efficacy and human usability remain inconclusive without independent data. Failed defenses are retained and reported.

# G4 실제 코드 탐색 연구 보고 — 2026-10-28

기존 합성 프로토콜 모형을 넘어 실제 최신 CAPTCHA HTML 함수, 공개 landmark·MP4 및 신규 loopback 서버를 연결해 공격·방어 실험을 수행했다. 현재 결과는 알려진 8개 source와 좌표 replay 채널에 한정된 탐색 증거다. 원래 전체 UI/카메라/과거 L3 또는 새로운 사람·동작의 보안성은 확증하지 않았다.

## 무엇이 실제로 성공했는가

원 궤적 후보만의 closed-set 조회가 8/8 source를 식별했다. 공개 영상의 바이트 캐시는 파일명을 숨긴 신규 서버에서도 8/8을 식별했고, 선택한 공개 기준 궤적이 실제 score와 offline gate를 통과해 테스트 보호 action까지 8/8 허용됐다. 배정 순서를 비공개로 무작위화한 별도 run에서도 결과가 유지됐다. 이 성공은 신뢰 카메라를 통과한 인증이 아니라, 서버가 허용하는 오프라인 landmark 입력의 replay다.

실제 계산에서는 다른 동작 library 56개 모두가 score .25를 넘었고 37개는 offline gate와 local action도 통과했다. 시작/끝 보간은 8/8, 고정 자세는 종류별 5/8·6/8·5/8 local action을 통과했다. 목표 pose 정보가 없는 uniform 좌표는 0/8이었다. 공격자의 사전 정보가 서로 다르므로 하나의 성공률로 합치지 않았다.

현재 pool 밖의 공개 legacy 기준 6건에도 24개 입력을 보충 검사했다. 고정 첫 자세는 score 6/6이지만 gate 0/6이었고, 시작/끝 보간과 현재 pool의 한 다른 궤적은 각각 gate 2/6이었다. 이는 gate 저항이 source에 따라 달라짐을 보이며, 이 이전 자료들도 독립 holdout의 계보는 없다.

## 가림이 난도를 높였는가

판단할 수 없다. 동일 source의 무가림/가림·정규화된 화면 조건을 대응시키는 인과 대조는 없다. 오히려 이 작은 알려진 풀에서는 실제 영상의 원 후보 궤적과 frame count가 source 식별에 쓰였다. 그 관측으로 가림 일반의 효과나 새로운 source 공격 성능을 추정하지 않는다.

## 방어는 무엇을 바꾸었는가

새 서버는 실제 HTML 산식을 다시 계산하고, 정답 route를 제공하지 않으며, client passed/score를 거부한다. 쿠키 세션·challenge·만료·일회성 action의 검사를 구현했고 동시 재사용 검사도 통과했다. 입력 validator는 Boolean 숫자·잘못된 shape·비유한 값·시간 역전·퇴화 손을 거부한다. 그러나 공개 정답 재생은 8/8 통과해 입력 출처 보호와 풀 비밀성 문제는 남는다. 과거 시스템에는 확인된 L3가 없어 “과거 L3가 몇 % 개선됐다”는 계산은 할 수 없다.

정확히 고정된 pose를 차단하는 후보는 작은 잡음 반례에서 5/8 local action을 허용해 폐기했다. 임계값을 test에 맞춰 올리는 방식은 채택하지 않았다.

실제 Stage6 가림 함수의 누락 처리도 조사했다. 실제 영상 first 3 decoded frames에 mask 누락/짧은 mapping/z 변경을 주입해 입력 프레임 무변경 전달·stale mask·혼합 차원 반경 변화를 재현했다. 로컬 strict wrapper는 누락을 출력 전 전체 거부로 처리하고 2D 계산·입력 보존을 검사했다. 이 결과는 해당 함수의 기계적 방어이며 실제 배포 MP4가 무가림 원영상을 노출했다는 증거는 아니다.

## 정상 입력과 새로운 자료에서는 유지되는가

정답 replay fixture 8/8과 정상 mask 3프레임은 유지됐다. 이는 사람의 수행 오차·지연·접근성·검출 실패에 대한 평가가 아니다. 기존 인간 기록은 challenge/build/방향 대응이 불충분해 이번 분모에 합치지 않았다. 새 source나 미사용 holdout은 없어 일반화 효과는 자료 부족이다. 별도 검토자의 Python 검산은 136개에서 불일치 0/최대 오차 2.22e-16이었지만 같은 개발 자료의 산식 검증이다.

## 가장 중요한 남은 위험과 다음 연구

핵심은 공개된 작은 answer library, 올바른 모양의 위조 입력을 구분하지 못하는 경계, 오답도 넓게 통과하는 gate/score 조합이다. 경로 은닉·서버 재계산·정지 탐지만으로 해결되지 않았다. Source 다양화는 실제 미사용 원본과 계보 관리가 필요하고, 입력 보호는 실제 캡처와 challenge를 결합하는 별도 검증이 필요하다. 기존 .25/38°/200ms 및 가중치의 정상/오답 판별력은 독립 정상 자료와 validation/test 분리를 갖춰 평가해야 한다.

연구를 계속할 근거는 재현 가능한 반례와 확인된 구현 결함이다. 현재 방식의 운영 보안 제품화·인간 우위·가림의 추가 가치·경제성은 뒷받침되지 않았다. 다음 연구는 새 source와 입력 신뢰 경계, 정상 수행 허용오차, 보호 action의 지속·원자 기록을 확보하는 데 한정하는 것이 타당하다. 현재 자료로 반복 tuning을 해 성공률을 만드는 것은 후속 확증을 대신하지 못한다.

## 판정

- **확인됨:** 실제 함수 호출, known-source 채널별 결과, 신규 loopback 경계 검사, Stage6 fault-injection 및 국소 방어.
- **조건부 재현:** 현재 입력·source revision·offline 구간/시계 조건의 점수·관문 결과.
- **탐색적 관측:** 원 후보 lookup 8/8, frame-count singleton 6/8, 다양한 오답 통과.
- **반박됨:** exact-stationary 후보가 작은 변형에도 견고하다는 주장.
- **불확정:** 가림의 추가 효과, 입력 보호의 보안 이득, 사람 성능, 실용화·비용 비대칭.
- **자료 부족:** 독립 source/참가자 holdout, 대응 인간 평가, 원래 운영 L3 및 신뢰 카메라.

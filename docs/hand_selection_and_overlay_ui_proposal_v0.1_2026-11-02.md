# 손 선택과 과제 이해를 개선하기 위한 기능 제안 v0.1

- 작성일: 2026-11-02
- 제안자: 조영준
- 상태: 요구사항 초안 / 구현·비교 실험 전
- 대상: `mukgore/handcaptcha`의 손 입력 선택과 과제 안내 UI
- 이번 범위: 사용자가 이번에 말한 두 가지 개선안을 구체화해 보존한다. 기존 장기 로드맵 전체의 재확인이나 실행을 뜻하지 않는다.
- 저장 위치: 현재 handcaptcha 쓰기 권한 제한으로 codex에 기록한다. 기능 구현 시 handcaptcha의 실제 대상 파일과 연결한다.

## 1. 출발점과 목표

### 사용자가 설명한 현재 동작

현재는 가장 먼저 인식된 손 한 개를 자동으로 사용한다. 여러 사람의 손이 화면에 들어오면 사용자와 비사용자의 손동작을 구분하기 어렵다. 이 설명은 이번 사용자 제보에 근거하며, 이 문서를 작성하기 위해 현재 코드를 재조사하지 않았다.

### 사용자가 직접 관찰한 문제

가려진 손동작 영상을 보고 무엇을 어떻게 해야 하는지 이해하지 못하는 사람이 여러 번 있었다. 이는 연구자의 실제 관찰이다. 관찰 인원·빈도·발생 조건은 현재 제시되지 않았으므로 정량적 비율이나 원인 확정으로 표현하지 않는다.

### 이번에 원하는 변화

1. 여러 손이 검출되면 **가장 크게 보이는 손을 먼저 선택하고 그 손으로 인식을 시작**한다.
2. **가려진 문제 영상과 사용자 카메라를 한 화면에 겹쳐 보여주는 방식**을 우선 후보로 만든다.
3. 다른 안내 방식도 AI를 활용해 제안·비교하고 연구자가 선택해 발전시킨다.

두 개선은 구분해 평가한다. 손 선택 개선이 안내 이해도를 높였다고, 안내 개선이 손 소유자를 식별한다고 해석하지 않는다.

## 2. 기능 A — 가장 큰 손으로 시작하기

### A-01. '가장 큰 손'의 초기 정의

- 손 검출기는 여러 손을 반환할 수 있도록 설정한다. 한 손만 반환하는 설정이라면 검출 이후 정렬만 추가해도 요구사항을 만족할 수 없다.
- 초기 후보는 **화면에서 손 랜드마크 전체를 감싸는 2D 경계상자 면적**이다.
- 카메라 프레임 크기를 W, H, 정규화 좌표를 x, y라 할 때, 손별 너비는 W × (max x − min x), 높이는 H × (max y − min y), 면적은 너비 × 높이로 계산한다.
- 비교 좌표는 같은 원본 카메라 프레임 기준으로 통일한다. 화면 배치·미러 표시·정규화된 채점 좌표와 혼용하지 않는다.
- 유효한 랜드마크와 양의 면적이 있는 검출 결과만 후보로 사용한다. 화면 밖 좌표·부분 잘림·낮은 품질은 명시적 정책으로 다루고, 잘못 큰 면적 때문에 선택되지 않도록 검토한다.
- 손가락을 펴거나 손을 회전하면 면적도 달라질 수 있다. 경계상자 면적이 불안정하면 손바닥 기준 크기 또는 여러 프레임의 대표 면적과 비교한다. 대체 기준을 쓸 경우 명칭·계산식·선택 결과를 기록한다.

'가장 큰 손'은 사용자 손을 고르는 **편의상 휴리스틱**이다. 실제 사람의 신원이나 손 소유자를 인증하지 않으며, 가까이 들어온 다른 사람의 손이 더 크면 잘못 고를 수 있다.

### A-02. 시작할 때 선택하고 수행 중에는 유지하기

매 프레임 가장 큰 손으로 바꾸면 도중에 다른 사람의 손이 입력될 수 있다. 따라서 다음 동작을 초기 설계로 제안한다.

| 상태 | 동작 | 다음 상태 |
|---|---|---|
| 대기 | 여러 손의 크기를 비교하고 가장 큰 후보를 표시 | 선택 안정화 |
| 선택 안정화 | 짧은 연속 관측으로 같은 후보가 유지되는지 확인. 후보가 자주 바뀌면 대기 유지 | 손 선택 완료 |
| 손 선택 완료 | 선택 손을 테두리/강조 표시하고 해당 좌우손으로 문제·가이드를 설정 | 과제 수행 |
| 과제 수행 | 선택 손을 위치·형태의 시간적 연속성으로 추적. 다른 손이 더 커져도 자동 전환하지 않음 | 수행 유지 또는 추적 보류 |
| 추적 보류 | 선택 손이 사라지거나 연결이 불확실하면 새 좌표의 채점 반영을 보류하고 복귀 안내 | 재연결 또는 다시 선택 |
| 다시 선택 | 명시적 다시 선택 조작이나 재시작으로 초기 큰 손 선택을 수행 | 대기 |

- 검출 결과의 배열 순번이나 좌/우손 라벨만으로 동일 손이라고 판단하지 않는다. 검출 순서 변화와 두 사람의 같은 쪽 손을 고려한다.
- 재연결은 짧은 시간·거리 안에서 같은 손이라고 연결할 근거가 있을 때만 한다. 교차·가림 등으로 모호하면 조용히 다른 손에 연결하지 말고 다시 선택을 요구한다.
- 손 재선택으로 사람이 달라질 가능성이 있으면 진행 중 시도를 중단·초기화한다. 앞사람과 뒷사람의 좌표를 한 시도에 이어 붙이지 않는다.
- 추적 보류 시 문제 재생·관문 타이머·전체 제한시간을 어떻게 처리할지는 함께 정한다. 기존 미검출 감점과 새 보류 처리가 이중 적용되거나 무제한 대기로 이어지지 않도록 별도 기록한다.
- 안정화 시간, 동률 범위, 추적 허용 거리·소실 시간은 조정 가능한 설정으로 둔다. 현재 문서에서 임의의 값을 연구 기준으로 확정하지 않는다.

### A-03. 사용자에게 보일 안내 초안

- 시작 전: “사용할 손을 카메라 가까이에 보여 주세요.”
- 선택 완료: “표시된 손으로 시작합니다.”
- 손 소실: “선택한 손을 다시 보여 주세요.”
- 보조 조작: “손 다시 선택”

안내 문구는 UI 후보이며, 가장 큰 손 선택을 이해하기 쉬운지 함께 확인한다.

### A-04. 구현 수용 사례

1. 작은 손이 먼저 검출되고 큰 손이 나중에 나타나도 시작 시 큰 손이 선택된다.
2. 검출 배열 순서가 바뀌어도 선택 손은 유지된다.
3. 수행 중 다른 손이 잠깐 더 커져도 입력이 바뀌지 않는다.
4. 두 손의 크기가 비슷하거나 서로 교차해 연결이 모호하면 임의 전환하지 않는다.
5. 선택 손이 화면 밖으로 나가도 남은 비사용자 손의 좌표로 계속 채점하지 않는다.
6. 재선택한 손의 좌우손·문제 방향·관문·기록이 일관되게 초기화된다.
7. 한 손만 보일 때 기존 수행 흐름이 유지된다.

## 3. 기능 B — 문제 영상과 카메라의 중첩 화면

### B-01. 사용자의 원안

현재 따로 보이는 가려진 문제 영상과 사용자 카메라를 하나의 화면에 겹친다. 사용자는 자신의 손을 보면서 같은 화면 안에서 목표 동작을 추정하고 따라 한다.

검증할 가설은 “시선 이동과 두 화면 사이의 대응 부담을 줄이면 처음 보는 사람이 수행 방법을 더 쉽게 이해한다”이다. 중첩이 가림·배경 혼잡을 늘릴 수도 있으므로 효과는 아직 미확인이다.

### B-02. 첫 프로토타입 구성 제안

- 사용자 카메라를 기본 화면으로 표시한다.
- 그 위에 **기존 가림이 적용된 문제 영상**을 반투명하게 표시한다.
- 문제 영상 레이어의 투명도는 설정으로 조절하고 비교 시 값을 고정한다. 두 손이 동시에 보이는 정도와 가림의 시인성을 함께 확인한다.
- 문제 영상과 카메라의 종횡비를 유지한다. 문제 영상의 잘림·늘어남으로 손 자세나 보이는 단서가 바뀌지 않게 한다.
- 미러 표시·좌우손·회전 기준을 통일한다. 사용자가 화면상 어느 방향으로 움직여야 하는지 사전 점검한다.
- 초기 배치는 고정 위치·크기 정렬로 시작한다. 필요하면 사용자가 자신의 손을 지정 영역에 맞추도록 안내한다.
- 선택된 사용자 손에 테두리 등 최소한의 강조를 적용한다. 여러 손이 보일 때 어느 손이 입력인지 알 수 있어야 한다.
- 기본 채점에는 혼합된 화면을 사용하지 않는다. **손 검출에는 원래 카메라 입력을 사용**하고, 문제 영상이 검출기로 들어가 목표 손을 사용자 손으로 잘못 인식하는 일을 막는다.
- 가림막과 사용자 손이 시각적으로 겹쳐도 카메라 원본·검출·점수 입력은 별도로 유지한다.

첫 비교에서는 UI만 바꾸고 문제 영상, 가림 정보, 채점식, 관문, 시간 조건은 가능한 한 동일하게 유지한다.

### B-03. 중첩 때문에 생길 수 있는 혼동과 대응

| 예상 문제 | 검토할 대응 |
|---|---|
| 두 손이 겹쳐 어느 것이 내 손인지 모름 | 사용자 손 강조, 문제 영상 투명도 조정, 짧은 범례 |
| 가림막이 내 손까지 가려 보임 | 가림막의 표시 방식과 카메라 가시성 비교. 정답 단서를 추가하지 않는 범위에서 조정 |
| 손 위치·크기를 영상과 정확히 맞추는 과제로 오해 | “같은 손모양과 움직임을 따라 하세요” 안내. 위치 맞추기가 실제 채점 대상인지 구별 |
| 배경까지 겹쳐 복잡해짐 | 처음에는 단순한 촬영 배경 안내, 이후 문제 영상의 비정답 배경 처리 후보 검토 |
| 미러/좌우 불일치 | 두 입력의 좌표 변환을 명시하고 좌/우손 각각 점검 |
| 실시간 위치 보정이 목표 움직임을 지워버림 | 자동 추적 정렬을 첫 버전에서 분리. 도입 시 목표 궤적과 힌트 변화 여부를 검증 |

원래 보이지 않던 손 관절·정답 윤곽·추정 정답을 겹침 안내로 추가하지 않는다. 문제 영상을 움직이거나 정렬하는 기능이 가림의 의미나 정답 단서를 바꾸면 단순 UI 변경과 다른 실험 조건으로 기록한다.

## 4. AI로 추가 생성·탐색할 안내 후보

다음은 사용자 원안과 구별되는 **AI 제안 후보**다. 모두 채택하거나 구현하기로 정한 기능은 아니다.

| 후보 | 구체적 형태 | 검증할 이점 | 예상 부담 |
|---|---|---|---|
| 짧은 시작 시범 | 본 문제와 다른 연습 동작으로 “보고 → 따라 하기 → 다음 구간” 시범 | 해야 할 행동과 진행 구조 이해 | 연습 시간·학습 효과 |
| 단계별 한 문장 안내 | 현재 상태에 맞춰 “손 보여주기”, “보이는 움직임 따라 하기”, “자세 잠깐 유지” 표시 | 지금 무엇을 해야 하는지 명확화 | 글 읽기·주의 분산 |
| 큰 주 화면과 작은 보조 화면 | 카메라 또는 문제 영상을 크게, 다른 쪽을 작은 창으로 유지 | 중첩 혼잡을 줄이면서 시선 이동 감소 | 두 화면 대응 부담 잔존 |
| 주목 대상 강조 | 현재 선택 손·문제 재생 구간·정지 관문을 테두리/진행 표시로 강조 | 어느 손·어느 순간을 봐야 하는지 이해 | 화면 요소 증가 |
| 별도 연습 모드 | 채점 결과를 설명하는 짧은 연습을 본 시도 전에 제공 | 본 과제 이해와 검출 실패 구별 | 실제 사용의 시간 증가 |
| 선택형 도움말 | 막혔을 때 짧은 설명 또는 시범을 사용자가 요청 | 숙련 사용자 부담 감소 | 도움말 사용자가 원래 더 어려웠다는 선택 편향 |

AI 탐색 절차:

1. “무엇을 해야 하는지”, “어느 방향인지”, “어느 손이 내 입력인지”, “왜 진행이 멈췄는지” 등 혼동을 구분한 문제 목록을 만든다. 원인은 관찰 전 확정하지 않는다.
2. AI로 각 혼동을 겨냥한 문구·배치·시범 후보를 생성한다.
3. 정답 노출, 접근성, 화면 혼잡, 구현 비용, 기존 조건 유지 여부로 후보를 검토한다.
4. 연구자가 중첩안을 포함한 소수 후보를 선택한다.
5. 선택한 후보를 비교하고 관찰 결과를 바탕으로 다음 버전을 정한다.

AI가 “이 UI가 좋다”고 평가한 결과를 실제 사용자 이해도 개선의 증거로 쓰지 않는다.

## 5. 비교·평가 계획 초안

### A와 B의 영향을 나누어 보기

- **손 선택 검증:** 같은 UI에서 먼저 검출된 손 방식과 가장 큰 손으로 시작하는 방식을 비교한다. 시작 순서, 상대 크기, 손 교차·소실, 좌우손과 검출 순서 변화 사례를 포함한다.
- **안내 UI 검증:** 동일한 손 선택 정책 아래 기존 분리 화면, 중첩 화면, 연구자가 고른 다른 안내 후보를 비교한다.
- 첫 비교에서 두 기능을 동시에 바꾸면 어떤 변화가 원인인지 분리하기 어렵다. 개별 동작을 확인한 뒤 결합 상태를 확인한다.

### 기록할 지표

| 대상 | 주로 기록할 항목 |
|---|---|
| 손 선택 | 의도한 손 선택 여부, 잘못된 손 전환, 시작까지 시간, 재선택 횟수, 선택 손 소실과 복구 |
| 과제 이해 | 별도 설명 없이 시작 가능한지, 첫 올바른 시도까지 시간, 도움 요청·잘못된 수행 유형 |
| 실제 수행 | 관문 진행·완료, 전체 완료 시간, 중단, 검출 실패, 최종 점수 |
| 경험 | 어느 화면·안내가 헷갈렸는지, 화면 피로와 선호 이유 |

“올바른 시도”는 모집 전에 관찰 가능한 행동으로 정의한다. 높은 점수만으로 방법을 이해했다고 판단하지 않는다. 큰 손 선택의 정답은 사전에 지정한 수행자의 손이며, 자동 선택 결과 자체를 정답으로 삼지 않는다.

UI 순서·연습·동작 난도·장치·화면 크기·좌우손 영향을 고려한다. 반복 측정 시 순서와 학습 효과를 통제하고 참가자 내 비교인지 구분한다. 표본 수와 시간·성공률 기준은 작은 예비 확인과 연구 목적에 맞춰 사전 결정한다. 원영상 저장이나 새 참가자 모집은 별도 계획·동의 절차를 정한 뒤 진행한다.

| 작업 | 산출물 | 완료 판단 |

| B2 안내 후보 설계 | AI 후보 목록과 연구자 선택 기록 | 각 후보가 해결하려는 혼동과 비교 조건 명시 |

추적 기록은 설정 버전, UI 조건, 선택/소실/재선택 이벤트, 소요 시간과 비식별 집계를 중심으로 설계한다. 얼굴·원영상·개별 좌표를 공개 Git에 추가하지 않는다.

## 7. 이번 결정과 남은 선택

- **사용자가 요청한 방향:** 가장 큰 손으로 인식 시작, 중첩 화면을 우선 후보로 검토, AI를 통한 대안 탐색.
- **이 문서의 구체화 제안:** 경계상자 면적의 초기 기준, 시작 후 손 고정·추적 보류, 원본 카메라와 합성 화면 분리, 개별 비교 후 결합 검증.
- **추후 선택:** 크기 기준의 최종 채택, 추적·안정화 설정값, 중첩 투명도·정렬·가림 표시, 추가 비교 UI, 표본·수용 기준.
- **지금 실행한 것:** 기능 제안서 작성 및 Git 기록. 현재 CAPTCHA 코드 수정·실험·배포는 포함하지 않는다.

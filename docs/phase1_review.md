# 1차 연구 검토 — 2026-10-02 기준

## 사용자 검토가 필요한 요점

기존 결과는 재현 가능한 저장 점수/공격 분석에서는 상당한 취약 신호를 보인다. 특히 최종 조건의 저장 HaMeR 점수는 28개 조합 모두 0.25를 넘지만, 그 28개 모두 38° 포인트 관문을 통과한 것은 아니다. 연구의 일반적인 “사람 우위/보안 향상” 결론은 현재 증거가 뒷받침하지 않으며, 일부는 직접 결과와 반대다. **이것은 1차 검토용 분석**이다. 아래 계획으로 과거 누락 원자료 회수·동일조건 검증을 계속할지 검토가 필요하다.

## 무엇을 실제로 다시 계산했나

- `reports/phase1_aggregates.json`은 18명 session JSON과 28 HaMeR 조합에 저장된 raw 원오차·감지율로 최종 점수를 가중합부터 다시 계산했다. 저장 score와 차이는 부동소수점 오차 수준(최대 1.11×10⁻¹⁶). 원시 좌표 21점을 통한 각도/리샘플 원오차의 완전 재구현은 아니다.
- 사람 최종 score 평균 .6631, median .7001, 표본 SD .1874; 17/18이 ≥.25, 사람 단위 Wilson 95% 참고 범위 .742–.990.
- HaMeR 28 score 평균 .7218, median .7021, 표본 SD .0763; 28/28 ≥.25. 조합은 8 gesture를 공유하므로 단순 독립표본률은 일반화 추정치가 아니다.
- HaMeR 224개 gate 중 189개 성공, 모든 gate를 통과한 조합은 10/28. 저장 `passed`는 문자열이고 `stop_on_fail=false`. 따라서 점수 기준 28/28은 포인트 gate 포함 운영 흐름 전체의 성공률이 아니다.
- 사람 8,782 segment-frame 중 명시적 null 141개(1.61%); score 계산은 원래 detection rate penalty를 포함한다. 검출된 프레임만 평가하는 sensitivity mean .6686, 통과 17/18. 영상 부재로 실패가 어려운 자세에 몰렸는지 판단할 수 없다.
- 10명 SUS 58.75 (95% mean t interval 46.15–71.35), α=.819. 21명 SUS 73.33 (63.85–82.82), α=.823. 원응답 결측 없음. 표본이 서로 다르고 ID가 없어 전후 개인 향상으로 해석하지 않는다.
- 제공 `circle_edge_attack` 저장 관측으로 matcher/score 평가를 다시 실행해 summary와 일치시켰다: top-1 14/16(동점 0), replay score 16/16, 평균 .9737. 기초 픽셀 추출·영상 runtime은 재실행하지 못했고, 공격은 원 주변 피부의 fingertip visibility와 offline answer library를 사용한다.
- 원 고정 IK 결과는 저장 산출물 집계만 확인했다. 원본 공격 영상 추론이나 MediaPipe 재인식 전체 pipeline을 재실행하지 않았다.

## 핵심 불일치와 판정

1. **0.493 vs 0.557:** .493은 보고서상 n=4 초기 실험에서 “레벨 3” 사람 평균이고, .557은 표 10의 지표 평균 `.747/.464/.337`에 `.44/.31/.25`를 적용한 `.55677`과 맞는다. 표10 표본/실험 버전이 본문에서 명확하지 않아 둘의 차이는 아직 설명 불가다. 다른 모집단/버전이라는 것은 가능성일 뿐 확인된 사실이 아니다.
2. **10명 A/B와 p≈.012:** 설문 원응답만 남고 paired A/B score와 순서 기록이 없어 재현 불가다. 독립 혹은 paired 검정을 선택하거나 새 p값을 만들지 않았다.
3. **threshold/gate:** final threshold .25 및 초기 일부 주장 .2가 서로 다른 연구 단계에 나온다. 기준을 정한 평가자료 자체에서 결과를 다시 보고 threshold를 선택했는지 확인되지 않았다. 저장 HaMeR의 포인트 gate 실패는 최종점수 통과와 별도 처리해야 한다.
4. **시간점수:** 12.70초는 `segments[].duration` 합 평균이며 21.57초는 첫 sessionLog event에서 마지막까지다. 두 번째 값은 탐색/대기 구간의 영향, 한 세션 최대 110.91초가 있어 “총 인증시간” 정의를 명시해야 한다. HaMeR 시간은 보고서가 약 10시간과 21분을 모두 적으며 원 타이머 로그가 없어 비교 불가다.
5. **SUS:** 73.3은 계산 재현되지만 n=10과 n=21 서로 다른 참여자 표본의 서술 결과다. 높은 Cronbach α는 문항 내 일관성만 측정한다. reCAPTCHA 타 연구와의 SUS 수치 차는 다른 표본 비교다.
6. **가림/인지 기제:** 저장 점수는 인지 추론 + 동작 수행 + 카메라/landmark 추적을 합친다. 사람 원영상 부재로 기여 분해 불가. predictive coding을 측정한 것이 아니므로 현 결과만으로 인지기제를 사실처럼 말할 수 없다.
7. **공격:** 눈에 보이는 원의 위치/크기만 사용한다는 사용자 보고, 노출된 피부 bit 조회, IK 좌표 복원은 별개로 명명한다. 저장 공개 reference 8개를 사전 보유한 공격과 임의의 새 gesture 공격의 난이도도 다르다.
8. **신규성·제품 주장:** CHGR과 Lenovo gesture patent가 손동작 CAPTCHA 일반 형태와 겹친다. Usuzaki visual-completion 논문은 가려진 텍스트 과제이며 비교 근거로만 쓸 수 있다. Meta 인용 공식 글은 얼굴인식 영상 셀카 계정복구이지 CAPTCHA가 아니다. '최초/유일'과 Meta CAPTCHA는 현재 근거로 지지되지 않는다.

## 다음 결정을 위한 우선 계획

1. F0 자료 회수: 초기 n=4 raw, 10명 A/B 참가자×조건 점수·순서, 표10 생성 workbook, HaMeR 실행 정보가 남아 있는지 아카이브를 조사한다. 없으면 해당 과거 결과는 보고된 수치로 한정한다.
2. F1 동일 입력 end-to-end: 원본을 held-out 원본 단위로 분할하고 동일한 영상/전환·gate·threshold에서 사람/공격을 비교한다. gate, 점수, 보호 기능 성공률을 별도로 기록한다.
3. F2 정보 누설 분해: 원 중심·크기만, 원 밖 피부 bit만, 나머지 visible frame, metadata, 저장답 재생을 따로 시험하고 어떤 입력이 원 공격 결과를 설명하는지 정한다.
4. F3 score 고정·일반화: 개발/검증 split을 원본 gesture 단위로 분리하고 threshold/가중치/E_max를 검증자료를 보기 전에 고정한다. 공유 clip의 28 pair를 독립 표본으로 취급하지 않는다.
5. F4 인지와 수행·검출 분해는 위의 결과를 본 후 필요할 때만 제안하며 새 참여자 연구는 지도교사·학교 절차와 사용자 승인 후 시행한다.

실험 카드의 가설·측정·분모·실패 해석은 [followup_experiments.md](followup_experiments.md), 상세 주장별 상태는 [claim_evidence_matrix.md](claim_evidence_matrix.md), 각 저장 결과 재현 범위는 [reproduction.md](reproduction.md)에 있다.

## 현재 판정

자료로 직접 확인된 결론은 **이 선정된 데이터와 브라우저 점수식에서 가림 영상의 공개/사전 계산 단서로 구성한 저비용 공격이 높은 점수를 만들었고, HaMeR 저장 점수는 .25 기준으로 사람 집단과 겹치며 평균이 더 높다**는 조건부 결과다. 사람과 AI 일반 전체에 대한 우열, 인지기제, 서비스 전체 인증 방어력, 비용 비대칭, 독립적인 신규성은 입증되지 않았다. 안전한 결론이 “현재 방어 주장 반박”이어도 유효한 연구결과다.

## 사용자 검토 질문

- F0에서 오래된 4명/10명 raw evidence를 먼저 회수하고, 없으면 과거 A/B 주장은 재현 불가로 확정할지?
- 후속 평가는 최종 브라우저 점수 외에 38° 포인트 gate의 실제 fail-fast 동작을 포함한 end-to-end 단계별 성공을 우선할지?
- F2에서 원-only 정보와 피부-edge bit 정보를 분리해 공격을 새로 명명/비교할지?

사용자의 명시 검토·승인 전 새 후보 CAPTCHA, 입력 방식, 서비스, 참여자 모집은 시작하지 않는다.

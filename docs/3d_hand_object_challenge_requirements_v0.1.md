# 3D 손·물체 상호작용 CAPTCHA 설계 후보 및 검증 요구사항 v0.1

- 작성일: 2026-10-26.
- 기존 [영상 풀·가림·송출 요구사항 v0.4](video_pool_occlusion_delivery_requirements_v0.4.md), [실용성 검증 v0.3](practical_validation_requirements_v0.3.md), [채점 전환 v0.3](scoring_standardization_v0.3.md)에 붙는 **신규 설계 후보**.
- 상태: PROPOSED / NOT_TESTED. 3D 생성 코드, 인간 실험, 공격 실험, 상업 권리 검토 완료를 뜻하지 않는다.
- 목표: 손의 보이는 지점만 이어 빈 부분을 채우는 공격이 손·물체의 기하와 접촉 제약까지 만족해야 하는지 검증한다. 그 제약은 공격자도 사용할 수 있으므로 안전성이 자동으로 높아진다고 가정하지 않는다.

## 1. 10살에게 설명

손이 컵을 잡는 장면에서 가려진 손가락은 어디 있을까? 사람은 컵의 크기와 손이 닿는 곳을 보고 짐작할 수 있다. 컴퓨터에도 그 힌트를 준다. 그래서 단순히 손끝을 선으로 잇는 공격이 실패하는지 시험한다. 다만 컴퓨터도 컵 모양을 아니까, 실제로 어느 쪽이 더 잘 맞히는지 비교해야 한다.

## 2. 기존 설계에서 바뀌는 부분

| 축 | 기존 동작 영상 | 신규 후보 |
|---|---|---|
| 문제 원천 | 촬영/데이터셋 손 영상 풀 | 제약이 있는 3D 손·물체·동작 생성기로 만든 scene family |
| 사용자의 추론 | 가려진 손 자세·시간 변화 | 손 자세·접촉 위치·물체 반응의 일관성 |
| 생성 | 원본 프레임 선택 후 가림 | 손·물체 상태 생성 → 물리·해부학 검사 → 렌더 → 가림 → 최종 출력 검사 |
| 채점 참조 | 2D 기준 landmark와 phase | 3D 손 관절·물체 자세·접촉 사건·투영된 2D 참조 |
| 공격 | 원 궤적·피부색·기존 영상 매칭 | 위 공격 + 3D fitting/IK·접촉 추론·렌더러 역추정·생성기 재구현 |
| 풀 단위 | 고유 촬영 source family | 고유 물체 형상/기능 × 동작 궤적 × 접촉 계획 × 시점 family |

단순한 장면 파라미터 조합 수를 보안 entropy로 쓰지 않는다. 공개 화면에서 구별 가능한 문제인지, 같은 물체·접촉 계획을 얼마나 쉽게 군집화하는지가 관건이다. 3D를 만들었다는 사실만으로 사람/AI 분리 성능이나 특허 신규성을 주장하지 않는다.

## 3. 반드시 먼저 결정할 과제 의미

'컵을 잡는 영상 보고 손을 흉내 내기'와 '실제로 컵을 잡기'는 다르다.

| 모드 | 정상 사용자 행동 | 카메라가 확인할 수 있는 사실 | 제약 |
|---|---|---|---|
| G0 공중 모사 | 물건 없이 잡는 손모양·방향 재현 | 손 자세·시간만 | 실제 접촉·힘·안정성은 검증 불가 |
| G1 화면 위 가상 물체 | 카메라의 손을 화면 물체에 정렬하며 손모양 재현 | 손과 화면상 가상 물체의 추정 정렬 | 단안 깊이 모호성, 기기 보정·UX 부담 |
| G2 실제 소품 | 지시된 물체를 실제로 잡기 | 물체/손의 공동 움직임 일부 | 소품 보유·접근성·객체 검출·카메라 가림 부담 |

초기 파일럿은 G0. 물리 제약은 **문제 생성과 사용자 추론을 설계하는 조건**으로 사용한다. G0에서 실제 접촉을 관측했다고 채점하지 않는다. G1/G2는 별도 실험 및 사용자 부담을 평가한 후에만 후보로 추가한다.

## 4. 생성 계약 GEN3D

### GEN3D-01 장면 변수와 재현성

서버가 seed와 generator_version으로 다음을 결정하되 raw seed와 정답을 브라우저에 보내지 않는다:
hand morphology 범위, handedness, object mesh/크기/질량 근사, 카메라 내·외부 파라미터, 조명,
초기/목표 자세, finger joint trajectory, grasp type, 목표 접촉 패치, 접촉·해제 사건 시각,
물체 자세 trajectory, occluder mask/보이는 영역, renderer/encoder version.
seed를 숨기는 것이 생성 규칙을 숨긴다는 뜻은 아니다. 공격자는 코드와 분포를 안다는 조건도 시험한다.

### GEN3D-02 사람이 실제로 할 수 있는 동작

- 인체 손 크기, 관절 각도·연동, 관절 변화속도·안전한 가동 범위, 손가락 자기 관통 금지를 확인한다.
- 손·물체의 비관통, 접촉면, grasp 유지 시간과 물체의 중력·지지/회전 반응을 단순화한 물리 조건으로 검사한다.
- '시뮬레이터 합격'과 '사람이 편하게 흉내 냄'은 별개다. 실제 사용자 파일럿으로 확인한다.
- 관절 한계를 숫자로 임의 확정하지 않는다. 모델 근거·개인차·통증 없는 수행 기준을 기록한다.
- 자유도를 완전 무작위로 뽑지 않는다. 인간 수행 가능한 접촉 계획을 먼저 고르고 그 주변에서 제한된 변형을 생성한다.
- 랜더링 전 3D 접촉/가림, 렌더링 후 화면 2D 단서와 실제 가려진 부위를 모두 검사한다.

### GEN3D-03 물체 추론이 진짜 필요한가

시작 동작은 한 손/한 물체, 저렴한 primitive 형상(원기둥·손잡이 있는 물체·상자)과
안정적인 grasp/접촉→이동→해제처럼 짧은 사건으로 제한한다.
다음 쌍을 생성한다: 보이는 손 움직임과 가림 원 궤적은 최대한 비슷하나 물체 형상·접촉 위치가 달라
가려진 손가락 관절/엄지 반대각 또는 접촉 순서의 정답이 달라지는 문제.
보이는 물체 위치·움직임·접촉 흔적이 두 답을 구분하는 단서인지 사람 파일럿으로 검사한다.
단서가 없으면 찍기 문제가 되고, 손만 보아도 답이 같으면 물체가 장식일 뿐이다.
물체의 텍스처/색깔/ID가 정답을 외우는 지름길이 되지 않도록 통제한다.

### GEN3D-04 가림과 출력 보안

- 손끝만 가렸더니 물체 표면에 그림자·반사·관통 또는 손 모양 실루엣이 그대로 남는지 검사한다.
- 물체를 전부 가리면 접촉 추론 과제가 사라질 수 있다. 손/물체 가림 비율을 따로 설계한다.
- 배경, occluder 이동, 물체 trajectory가 정답 클래스를 예고하는 지름길인지 각각 분리 시험한다.
- 브라우저에는 최종 가려진 렌더만 송출한다. 3D skeleton, mesh animation, contact map, depth buffer, 손 원본 렌더, 정답 seed를 내려보내지 않는다.
- 사전 생성 MP4, 요청 시 생성, 선택적 캐시를 모두 후보로 둔다. GPU 없는 환경에서는 짧은 저다각형·낮은 해상도·오프라인 검사를 기본 파일럿으로 측정하고, 실시간 생성을 요구사항으로 확정하지 않는다.
- 기존 v0.4의 마스크 누락 fail-closed·최종 바이트 재검사·비공개 정답·권리 대장을 그대로 적용한다.

## 5. 입력과 채점 SCORE3D

- 장면 정답은 3D지만 일반 웹캠의 단안 영상에서 사용자 손의 진짜 3D 관절과 접촉 힘을 직접 측정할 수 없다. 3D를 정답으로 만들었다고 3D 실측 점수가 생기지 않는다.
- G0 첫 실험은 화면의 투영 2D 키포인트/각도와 시간 순서를 기존 baseline으로 채점하고, 물체가 바꾼 손모양/엄지 위치/phase의 구분력을 별도 특징으로 평가한다.
- 3D 손 추정기를 사용하면 깊이·종횡비·좌우손·보정 불확실성을 보고하며, 그 출력은 추정치라고 기록한다. object contact는 G0에서 기준 장면의 속성일 뿐 사용자 실측 접촉 점수가 아니다.
- 여러 그럴듯한 grasp 정답이 있는 물체는 하나의 정답 궤적만 강요하지 않는다. 허용 가능한 자세 집합/접촉 영역 또는 여러 정답을 사람 데이터로 정의한다.
- 유사도 점수와 '사람 인증'을 분리한다. 서버 판정, 입력 위조/가상 카메라/통과 신호 우회 실험은 기존 V1–V3를 유지한다.

## 6. 공격 및 비교 실험 EVAL3D

| 조건 | 비교 목적 |
|---|---|
| B0 기존 2D 손동작·가림 | 시간과 입력 장치를 맞춘 baseline |
| B1 3D 손만 렌더·가림 | 3D 렌더 효과 |
| B2 같은 손·물체 렌더, 물체 단서 숨김 | 물체 단서의 인과효과 |
| B3 같은 손·물체 렌더, 물체 단서 표시 | 사용자 제안의 전체 효과 |
| A1 단순 손끝 잇기/2D 보간 | 구체적 공격 가설 |
| A2 화면만 보는 3D pose fitting + IK/물체 충돌·접촉 제약 | 물리 지식을 가진 강한 공격 |
| A3 공개 생성기·object family·시드 분포로 합성 학습한 추정기 | 생성 기반 공격 |
| A4 가림/물체 움직임/렌더 artifact만, 반복 수집·유사 장면 lookup | 지름길·반복노출 공격 |

- B2/B3는 같은 scene seed의 대응쌍을 쓰되 사람에게 반복 기억 효과가 생기지 않도록 조건 순서·노출 관리.
- dev/test는 seed뿐 아니라 물체 형상 family, grasp/contact plan, 동작 trajectory family, camera/renderer 설정을 기준으로 분리한다. 보지 않은 seed만으로 held-out이라고 하지 않는다.
- 공격자에게 같은 영상, 같은 풀이 시간, 재시도 예산과 생성기 공개/비공개 조건을 명시한다.
- 주 지표는 사전 지정한 **보호 동작까지의 공격 성공률**과 정상 사용자 성공률 차이. 공격별 단순 관절 복원 오차, 추론 시간·GPU/CPU, completion time, 접근성, 가림 프레임 실패, 생성·송출 비용을 보조 지표로 기록.
- 단순 A1이 실패해도 A2/A3가 성공하면 보안 차별성은 미확인. B3가 B1보다 사람에게는 도움이 되면서 강한 공격에는 덜 도움이 되는지 핵심 비교.
- 랜덤 생성 문제라도 다수 장면의 공통 skeleton/접촉 템플릿을 외울 수 있으므로 조건부 공격과 반복노출을 본다.

## 7. 도입 관문과 비용

1. 소규모 자체 제작 primitive 손/물체와 제한된 grasp 두 종류로 **합성 fixture** 제작. 기존 2D 보간이 구분 못하는 쌍과 3D 제약도 구분 못하는 쌍을 둘 다 넣어 오탐을 확인한다.
2. 렌더·마스크·출력 검증, 다른 seed에서 재현성 확인. hand/object/PTS/occlusion 상태가 불일치하면 발급 금지.
3. G0 인간 파일럿으로 '물체 단서를 이해할 수 있는지, 실제로 따라 할 수 있는지' 확인. 표본과 성공 기준은 모집 전에 잠근다.
4. A1/A2/A3/A4를 같은 예산에서 실행. 3D 최적화가 단순 연결보다 강해질 수 있으므로 강한 공격을 생략하지 않는다.
5. B0–B3의 보안 이득 대비 정상 사람 시간, 렌더 비용, 권리, 기기 부담을 비교해 CONTINUE / MODIFY / STOP / INCONCLUSIVE 중 하나로 기록.
6. G0가 유망할 때에만 G1/G2의 실제 상호작용 판정을 설계. 입력 신뢰성을 해결하지 못하면 보안 제품 출시는 별도 BLOCKED.

## 8. 외부 연구와 사용권

- [D-Grasp, CVPR 2022](https://openaccess.thecvf.com/content/CVPR2022/html/Christen_D-Grasp_Physically_Plausible_Dynamic_Grasp_Synthesis_for_Hand-Object_Interactions_CVPR_2022_paper.html): 물리적으로 그럴듯한 동적 grasp 합성의 연구 예. 즉시 사용 가능한 서비스 코드·권리의 증거는 아님.
- [DeepSimHO, NeurIPS 2023](https://papers.nips.cc/paper/2023/hash/fbdaea4878318e214c0577dae4b8bc43-Abstract-Conference.html): 손·물체 자세 추정에 grasp 안정성의 물리 조건을 사용하는 연구. 공격자 역시 유사한 조건을 쓸 수 있음을 고려.
- [OakInk 공식 프로젝트](https://oakink.net/): 손·물체 영상/자세와 3D grasp 후보. 영상/mesh/모델/인물 권리 각각 확인 전에는 운영 자산으로 전용 금지.
- [DexYCB 공식 프로젝트](https://dex-ycb.github.io/): 손·물체 자세 평가용 데이터. 공개 라이선스 CC BY-NC 4.0; 상업 송출 후보로 자동 채택 금지.
- [MANO 공식 라이선스](https://mano.is.tue.mpg.de/license.html), [GRAB 라이선스](https://github.com/otaheri/GRAB/blob/master/LICENSE): 공개 조건은 비상업 연구 중심이고 제3자 제공에도 제한이 있다. 상업 서비스와 그 산출물의 권리 근거로 삼지 않는다. 독자 모델/자산 또는 별도 허가가 필요하다.

## 9. 기존 문서와 연결할 실행 입력

- POOL-01: `origin_type=generated_3d`, model/mesh/texture/renderer/learned-weight의 권리 record 및 family 계보 추가.
- POOL-02: 고유 family와 유효 문제 수의 정의를 scene/contact/geometry 수준으로 확장.
- MASK-03: 원본 3D/render pass의 미가림 누출 검사, 물체 단서의 필요성 및 답 누출 검사.
- SERVE-01: 오프라인 렌더, 요청 시 렌더, 지연 캐시의 비용 비교. 매 문제 MP4를 의무화하지 않음.
- V1/V2/V3: 기존 점수·인간·공격/입력 위조 평가와 동등 조건 비교. 별도 성능 결과와 혼합 금지.

# 기존 연구 설명·발표용 검토 초안

## 동기와 구현

일부가 가려진 손동작을 사람이 추정해 따라 하는 과제를 CAPTCHA 후보로 만들었다. 가림은 손목과 중지 MCP의 위치를 기준으로 한 원으로 생성한다. 구현 버전마다 중심·크기 계산이 달라 원안과 현재 파이프라인을 같은 수식이라고 묶지 않는다. 파이프라인의 가림과 손목 가시성 요구에는 알려진 충돌도 있다.

카메라 손 좌표를 비교할 때는 손목을 원점으로 옮기고 손목–중지 MCP 길이로 크기를 정규화한다. 화면 위치·손 크기 차이를 줄이지만 실제 사람 신원이나 입력 출처를 확인하는 절차는 아니다. 선형 보간은 두 관측 사이를 연결하는 계산이며 가려진 실제 관절 상태의 정답을 복구했다는 뜻이 아니다.

현재 prod 계열은 중간 자세의 각도 오차와 유지 시간을 확인하는 관문, 최종 시계열 점수를 사용한다. 저장된 `dtw_angle`은 일반 DTW가 아니라 늘린 시계열의 sliding-window 각도 비교다. `accel`은 frame-index의 이차 차분에 기반하므로 timestamp 기반 물리 가속도라고 부르지 않는다. 새 수학 primitive는 별도 비교 후보로 유지한다.

## 확인한 결과

기존 사람 18세션의 저장 최종 점수는 재계산으로 재현됐고, 평균 약 .6631·17/18이 .25 이상이었다. 저장 HaMeR 28조합의 점수는 모두 .25 이상, 평균 약 .7218이었다. 그러나 모든 자세 관문이 성공한 조합은 10/28이며 `stop_on_fail=false`였으므로 ‘28/28 전체 인증 성공’으로 설명하지 않는다. 28조합은 8개 동작을 공유하므로 독립 28개 원동작도 아니다.

G3의 A/B 분석과 조건부 좌표 재현은 연구자가 현 범위 완료로 수용했다. 과거 세션별 실행 build가 확인된 것은 아니고, 과거 보고 p≈.012와 후속 분석의 출처 차이는 남아 있다. FR5의 기준은 이전 인간 단계 전체를 사용해 정하고 다음 단계에 그대로 적용했다는 연구자 설명이며, 이전 단계에 독립 holdout이 있었다고 말하지 않는다. 사후 13개 민감도 시나리오는 연구자 결정으로 연구 범위에서 제외됐다.

G4에서는 현재 공개된 작은 영상·정답 풀과 실제 HTML 함수, 새 localhost 서버를 연결해 취약 신호와 국소 방어를 탐색했다. 알려진 영상/원 단서 lookup과 저장 답 재생은 위협으로 남았으며, 경로 은닉·서버 재계산·정지 탐지만으로 이를 해결하지 못했다. 신규 loopback 서버의 세션·만료·일회 소비 검사는 과거 운영 서버 보안이나 신뢰 카메라를 입증하지 않는다.

## 결론과 한계

현재 자료는 ‘사람이 AI보다 우세하다’거나 ‘실제 CAPTCHA 보안이 향상됐다’는 일반 결론을 지지하지 않는다. 재현 가능한 범위와 취약 반례를 확인했다는 결과로 설명한다. 과거 사람 촬영 원영상은 사용자 보고상 없어 수행 오류와 tracker 실패의 완전 분해가 어렵다. source·참가자 독립성, 미사용 자료에서의 판별력, 동일 challenge의 정상/공격 비교, 실제 입력 경계·사용성·비용은 후속 검증이다.

최근 요청의 큰 손 선택과 중첩 화면은 이 한계 중 입력 선택·과제 이해를 개선하려는 후보로 설명한다. 구현과 합성 검사가 사람 이해도 향상 증거를 대신하지 않는다. 3D 손·물체 생성도 아직 후보이며, 물체 단서는 공격자에게도 도움이 될 수 있다. 후속 질문은 가림의 모호성과 사람이 편하게 수행할 수 있는 조건부터 좁혀 검토한다.

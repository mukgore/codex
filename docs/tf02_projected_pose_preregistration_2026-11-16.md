# TF-02P 고정 모델 제약으로 수정하는 자세 제안 — 사전등록 v1

**분리 작업트리 참고 사본:** 원래 동시 작업 흐름의 명세와 후속 기록을 보존했다. 아래 TF-02P 실패/감사 계획은 원작성 흐름의 기록이며 이 분리 흐름에서 해당 receipt를 검증하거나 재실행한 결과는 아니다. 감사 도구는 이 분리 브랜치에 포함하지 않았으므로 파일 이름만 참고한다.


등록 시점은 무수정 TF-02의 검산된 B0/32 결과를 확인한 뒤이며 TF-02P 실행 전이다. 기존 A/B/U와 거부된 동시변경 실행을 보존한다. 이는 TF-02의 새로운 수정 경로이고 TF-03 동작 생성이 아니다.

입력은 성공한 `tf02_entropy62026_20261116_v1`의 B32 자세/계수와 양손 basis다. 새 난수·원형·시간곡선을 뽑지 않는다. 각 실제 full_pose를 현재 해부학적 Euler XYZ로 분해하고 [TF-01의 고정 저자 모델 구간](tf01_constraint_application_2026-11-16.md)에 축별 직교 투영(clamp)한다. 허용 구간을 넓히거나 벌점기준·epsilon을 바꾸지 않는다. 이 직교 투영은 프로젝트 공학 수정법이며 논문의 생성 알고리즘 재현이나 임상 안전 보장이 아니다.

**고정 예산:** B32 모두 한 번 수정해 실제 SDK32회, 양손neutral/basis 검산2회 =34회. Torch1thread·기존17pin·600초. 각손 모델/실제neutral에서 다시 구성한 basis가 부모 basis와 최대절대차1e-6 이내인지 확인한다. 각 실제 반환 pose의 해부학적 재추출/재합성이1e-6 이내여야 한다. 실패하면 해당 실행은 오류로 남긴다. 제약에 맞춰 scale·원형·seed를 바꾸거나 성공 수를 채우는 재시도는 하지 않는다.

**저장:** 원계수·원 pose/각도·투영각도·수정벡터·고정 구간·수정된축 수와 최대/L2각도수정량, 실제SDK pose/16관절/표면tip/778정점, strict/zero-mask후 모델 벌점, 표면교차·퇴화, 정적BMC feature와 계산불가 상태를 비공개 보존한다. beta/root는0으로 고정한다. 부모의 A/B/U 측정과 수정 결과를 분모32로 비교하되 공유 부모/계수를 독립 자료로 세지 않는다.

**중복과 손실:** 실제 vertex/joint payload의 정확한 중복을 묶고, neutral과 같아졌는지/움직임 진폭이 사라졌는지를 별도 센다. 제약에 맞는 정적 자세 수를 고유 동작 수나 보안 entropy로 부르지 않는다. 수정된 각도 수·수정 크기도 함께 제시해 거의 모든 제안을 크게 바꾼 사실을 숨기지 않는다.

**격리:** 모델 prior·샘플표면 지표가0이어도 `MODEL_CONSTRAINED_RESEARCH_ONLY`, `release_allowed=false`다. 여섯 생체한계·SI단위·연동의 인간 타당성·물리/연속충돌/편안함·최종가림/사람/보안은 미검증이다. 정적자세에 가짜 timestamp를 만들지 않고 속도/가속도는 N/A로 남긴다. TF-03은 유효 후보와 실제 수정 영향을 확인한 뒤 별도 경로/시간 명세로 진행한다.

전체 worktree와 현재 코드/명세·부모 receipt/모든 출력·모델/범위·고정원문·SDK/worker/환경을 사전 snapshot에 연결하고 새 immutable 출력/기록 root만 사용한다. 실패/부분 출력·실제 UTC/wall/자체CPU를 남기고 실행 중 편집/커밋은 하지 않는다. 실제 촬영/사람 입력이 들어오면 원래 앞 단계가 우선이다.

## 계산 완료 후 집계 오류와 별도 검산 계획

`tf02_projected_record_20261116_v1`은 SDK34회·32사례 저장·journal `COMPLETED` 이후 최종 요약에서 `surface_state` 필드 누락으로 `PROCESS_ERROR`가 됐다. 해당138개 출력과 stdout/stderr·receipt를 보존한다. 원실행의 실패 상태를 성공으로 바꾸거나 모델 계산을 재실행하지 않는다.

별도 `analysis/audit_projected_pose_outputs.py`는 실패 receipt의 전체 출력/기록과 당시 snapshot 일치를 요구하고,32개 실제 파일에서 고정 투영·원모델 벌점·왕복·수정/판정·표면 상태·중복을 대조한다. 누락 필드는 기존 표면QA에서 새 감사 출력으로만 재구성한다. 새 SDK계산/난수/영상은0이다. 새 실행 ID/명세/snapshot·출력3개를 별도 기록하고 원생산자의 `PROCESS_ERROR`와 감사 실행 결과를 함께 보고한다. 이 계획은 감사 실행 전에 추가했다.

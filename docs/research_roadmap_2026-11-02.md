# 후속 연구·개발 로드맵 — 2026-11-02

이 문서는 조영준 연구자가 이전 대화에서 희망한 후속 방향과 저장소의 현재 근거를 연결한 계획이다. **계획 기록이며 새 실험·참여자 모집·배포의 실행 승인이 아니다.** 확정한 순서, 검토할 후보, 아직 답하지 못한 질문을 구별한다. 기존 명세와 결과를 대체하지 않으며 실제 단계 전환은 연구자 검토 후 진행한다.

## 1. 먼저 일차 연구와 발표를 마무리한다

- 기존 작품설명서의 동기 → 설계 발전 → 실험 → 한계 → 후속 연구 흐름을 정리한다.
- 가림 생성, 손목 원점 이동·크기 정규화, 선형 보간, 관문과 최종 점수의 차이를 예시로 설명할 수 있게 한다.
- MediaPipe·HaMeR 실험 과정은 핵심 결과와 변화 정도 중심으로 압축한다.
- 기존 결과의 방어보다 타당성을 높일 검증을 우선한다. 확인 결과·연구자 설명·추정·미확인을 분리한다.
- 발표 전 마무리와 장기 확장을 구분하고, 새 실험을 현재 발표의 완료 조건으로 추가하지 않는다.

## 2. 현재 근거와 출발점

| 항목 | 현재 기록에서 확인한 범위 | 후속 과제 |
|---|---|---|
| G3 | 연구자가 현재 범위 종료를 선언. 기존 A/B 분석과 조건부 좌표 재생 수용 | 과거 세션별 실행 build, 기준 잠금 기록 및 표본 독립성 한계를 유지 |
| G4 | 2026-10-28 실제 HTML 함수·공개 영상·신규 loopback 서버의 탐색과 국소 방어 수행 | 전체 G4 확증, 실제 카메라·새 사람·독립 source·과거 운영 L3 검증과 구별 |
| 알려진 풀 | 원 후보 조회·공개 답 재생, 오답의 넓은 통과 등 반례 확인 | 풀 비밀성, 채점 판별력, 입력 출처 보호를 각각 검증 |
| 3D 손·물체 | 요구사항 문서가 있는 설계 후보 | 구현·사람 수행 가능성·강한 공격 대비 이득·비용은 미검증 |

오래된 상태 파일만 보고 완료 항목을 다시 미완료로 되돌리지 않는다. 반대로 조건부 재현을 과거 실행 계보 입증이나 독립 보안 검증으로 확대하지 않는다.

## 3. 다음에 연구자가 선택할 질문

| 후보 질문 | 알고 싶은 것 | 핵심 반례·한계 |
|---|---|---|
| 가림의 모호성 | 보이는 정보만으로 답이 얼마나 정해지는가? | 서로 다른 손동작이 같은 화면과 양립하면 하나의 정답을 강요하기 어려움 |
| 사람 수행 가능성 | 사람이 의도를 이해하고 편하게 따라 할 수 있는 조건은 무엇인가? | 생성기의 관절 제한 통과만으로 사람의 이해·편안함을 보장하지 못함 |
| 모방 충실도·과제 수행 | 관절 궤적 일치와 의도한 동작 완료가 같은가? | 낮은 좌표 오차가 과제 이해나 실제 접촉 수행을 뜻하지 않음 |
| 사람·AI 판별 및 인증 | 같은 조건에서 정상 사용자를 허용하고 공격을 거부하는가? | 점수 통과와 관문 통과, 보호 동작 허용은 서로 다른 종점 |

이 가운데 어느 질문을 주 질문으로 삼을지는 아직 확정하지 않는다. 손동작 자체의 판별력과 전체 웹 인증의 보안성을 병렬로 구분하는 방안도 검토한다.

특히 연구자는 **가림 시 모호성과 사람 수행 가능성을 작은 실험으로 확인**하는 데 관심이 있다. 현재 영상 제작·선별 과정이 무의식적으로 사람에게 가능한 문제를 골랐을 가능성도 가설로 남긴다. “가림 추정 연구와 무가림 모방 연구는 있지만 둘을 결합한 CAPTCHA 선행은 없다”는 결론은 확인된 사실로 채택하지 않는다.

## 4. 우선순위와 완료 조건

### P0 — 기존 검증 정리와 후속 실험 설계

- 현재 G3/G4 근거와 v0.2 요구사항의 충족·제한·보류 상태를 연결한다. 이미 수용된 범위를 반복 복구하려고 전체 작업을 지연하지 않는다.
- 가림 모호성·사람 수행 가능성 실험 카드를 작성한다. 지각 오류, 운동 재현 오류, 추적기 오류를 가능한 범위에서 분리한다.
- 동일 화면에 여러 답이 가능할 때 허용 답 집합과 채점 방식이 필요한지 검토한다.
- 순서·기억·영상 노출량·동작 난도·카메라 조건을 통제하고, 참가자와 원동작을 분석 단위로 정한다.
- 원 중심·크기, 경계 피부·손끝 노출, 파일·길이 단서, 저장 답 재사용을 별도 채널로 정의한다.
- **완료 조건:** 연구자가 질문·조건·기준·자료 요구사항·해석 한계를 검토할 수 있는 실험 카드와 기존 근거표. 이 단계에서 새 실험을 자동 실행하지 않는다.

### P1 — 유망 후보와 실제 인증 흐름의 분리 검증

- 정상 답/오답/보간/정지/다른 동작이 어떻게 판정되는지 검토하고, 역사적 채점과 표준 수학 기반 후보를 별도 버전으로 비교한다.
- 실제 DTW, timestamp를 반영한 시간 미분, 검출 실패 처리, 임계값 선택을 검토한다. 기존 sliding-window를 일반 DTW, 이차 차분을 물리 가속도로 부르지 않는다.
- 개발·검증·최종 평가를 source family와 참가자 단위로 나누고, 평가 전에 점수·관문·임계값·공격 예산을 잠근다. 같은 동작의 미러·역재생·재인코딩을 독립 원본으로 세지 않는다.
- 소유자 승인 격리 환경에서 서버 발급·세션 결합·만료·일회 사용·서버 판정을 검증한다. 기존 localhost 구현을 출발점으로 검토하며 배포 완료로 간주하지 않는다.
- OBS 등 가상 카메라·영상 재생, 좌표 위조, 작업 생략·통과 신호 위조를 구별한다. 장치명 검사만으로 가상 카메라를 확실하게 차단한다고 가정하지 않는다.
- **완료 조건:** 관문/점수/보호 동작별 정상·공격 결과, 독립 평가 여부, 자원·실패·불확정 기록. 사이트 작동과 CAPTCHA 보안 입증을 구별한다.

### P2 — 문제 생성·고급 후보와 실용성

- 촬영·외부 데이터셋 기반 영상 풀과 3D 손·물체 생성 후보를 비교한다. 자산 사용권·중복·계보·최종 가림 누락 검사부터 확보한다.
- 서버가 문제·정답을 정하고 브라우저에 최종 가린 화면만 제공하는 방향을 검토한다. 정답·원본·관절·seed를 클라이언트에 내려보내지 않는다.
- 요청 시 생성부터 지연·CPU 비용·품질을 측정하고, 사전 생성/캐시와 비교한 뒤 실시간 송출 필요성을 정한다. “비저장”의 대상과 재현성 로그 보관 범위를 구체화한다.
- 3D 후보는 사람의 관절·접촉 제약을 만족하는 장면을 만들고, 초기에는 물건 없이 손모양을 따라 하는 G0를 검토한다. 가상 장면의 접촉을 사용자가 실제로 수행했다고 채점하지 않는다.
- 전체 순간 가림, 여러 가림막·타이밍 변화, 잡기/치기·랜덤 힌트 등은 비교 후보다. 모두 구현하기로 확정한 기능 목록이 아니다.
- 물체 단서는 AI에도 도움이 될 수 있다. 단순 보간뿐 아니라 3D fitting·IK·생성기 기반 공격과 같은 조건에서 비교한다.
- **완료 조건:** 사람 성공률·소요 시간·접근성·강한 공격 성공률·생성/송출 비용을 함께 보고 CONTINUE / MODIFY / STOP / INCONCLUSIVE 결정. 목표 미달이면 연구 시연이나 실패 결과로 마무리할 수 있다.

## 5. 실험 실행 전에 채울 항목

1. 주 질문과 허용할 결론, 비교 조건 및 최소 의미 있는 효과.
2. 참가자/source 단위, 표본 수 또는 목표 정밀도의 근거, split과 중복 검사.
3. 사람이 보는 화면과 공격자 정보·도구·시간·재시도 예산.
4. 정답/허용 답, 채점 버전, 관문, 종점과 실패·기술 오류·불확정 분모.
5. 자료 보관·동의·중단 절차, 기기·접근성 조건.
6. 변경을 멈출 시점, 독립 검산 방법, 결과를 보고한 뒤 연구자의 다음 단계 검토.

표본 수·성공률 목표·임계값을 이 문서에서 임의로 확정하지 않는다.

## 6. 저장소 역할과 작업 경계

- **codex:** 근거·분석·실험 프로토콜·독립 검산·채점 후보와 비식별 집계.
- **handcaptcha:** [반영 대기 중인 구현 로드맵](handcaptcha_implementation_roadmap_2026-11-02.md), 기존 시제품과 영상 처리·가림·입력 구현. 검증 전 production 교체를 피하고 비교 가능한 버전을 유지한다.
- 무료·CPU 우선. GPU·유료 서비스가 필요한 항목은 필요 자원과 실행 불가 이유를 기록한다.
- 공개 저장소에는 연구 문서·코드·비식별 집계만 선별한다. 참여자 원자료·개별 좌표·식별 영상·비밀 정답 풀·키는 커밋하지 않는다.
- 원본 보고서·원자료 보존, 새 보안 설계/후속 실험/외부 서비스 연결·공개 배포 전 연구자 검토 원칙을 유지한다.
- 이번 요청의 범위는 계획 문서와 README 연결의 커밋이다. 새로운 공격 실행·방어 배포·사람 실험은 수행하지 않는다.

# 3D로 만든 문제는 어떻게 채점할까 — 2026-11-14

사용자 질문에 따라 **현재 prod의 채점**, **3D 첫 실험 계획**, **추가 3D 채점 후보**를 구분한다. 기존 [SCORE3D](3d_hand_object_challenge_requirements_v0.1.md#5-입력과-채점-score3d)와 연구 우선순위를 따른다. 새 3D 채점기를 구현·배포했다는 뜻은 아니다.

## 현재 코드

handcaptcha `hand_captcha_prod.html`의 `pp`/`ppSingle`은 손목 위치를 빼고 손목–중지 MCP 길이로 크기를 맞춘다. `ang`/`mA`는 XY 관절 각도, `mDA`는 재표본화/구간 이동을 통한 각도 차이, `mAc`는 정규화 XY의 프레임 차분을 비교한다. 최종 점수에 MediaPipe의 z를 쓰지 않는다.

따라서 ‘21개 점의 위치 오차를 그대로 평균’하는 채점은 아니다. 이름이 `dtw_angle`인 legacy `mDA`는 실제 DTW가 아닌 sliding-window 방식이다. 별도 3B 후보의 실제 DTW와 구분한다. legacy 차분도 실제 초 단위 가속도와 구분한다. 이 문서는 수식을 바꾸지 않는다.

현재 가중치는 각도 0.25·구간 이동 각도 0.38·차분 0.37이고, 검출 비율을 반영한다. 자세 유지 관문과 최종 점수는 별개다. 기존 0.25 통과 기준을 새 3D 문제에서 독립 보정된 기준으로 취급하지 않는다.

## 3D 첫 실험에서의 정답 경로

| 부분 | 계획과 의미 |
|---|---|
| 생성기의 답 | 관절·장면·사건 시각을 보존. 생성기/관절 대응이 정의한 기준이며 실제 사람의 3D 실측은 아님 |
| 화면 기준 | 검증한 카메라 투영으로 생성 좌표를 2D로 옮기고 최종 영상·시각·미러/화면 크기와 연결 |
| 사용자 입력 | 웹캠의 MediaPipe 2D 추정과 원래 시각·검출 실패를 기록 |
| 첫 비교 | 기존 2D 각도/움직임 baseline을 유지하고, 손모양·엄지·순서/횟수·phase의 구분력을 별도 평가 |
| 3D 후보 | 사용자 3D 추정기를 쓰면 깊이/형태/좌우손/보정 불확실성을 포함한 추정 비교. 실제 깊이 실측이라고 하지 않음 |
| 실제 3D 실측 | 깊이/여러 카메라 등 별도 장비·보정·독립 기준 필요. 현재 준비된 경로가 아님 |

3D로 문제를 만들었다는 사실만으로 사용자의 깊이를 정확히 알 수는 없다. 현재의 물건 없이 손모양을 따라 하는 G0에서는 사용자 접촉 힘을 점수로 세지 않는다. 실제 3D 채점 기능과 사용자 실험 연결은 아직 미구현이다.

손목을 빼는 정규화는 손 전체의 이동도 제거한다. 따라서 기존 점수만으로 ‘손 전체를 지정된 경로로 옮겼다’고 인정하지 않는다. 문제마다 꼭 맞혀야 하는 손모양·순서·횟수·방향/이동·깊이 항목을 먼저 정하고, 관측할 수 있는 증거와 점수/관문을 연결해야 한다.

## 같은 화면의 다른 답

서로 다른 3D 자세가 같은 최종 화면으로 보이면 2D 점수로 그 깊이를 구분할 수 없다. [표면 실험](deliveries/2026-11-14_surface_depth_cues.md)에서 이런 대안을 확인했다. 단서를 추가하거나, 허용 답 집합을 정의하거나, 문제를 제외해야 한다. 참가자가 알 수 없는 단일 깊이 정답을 강요하지 않는다.

실제 모방 성공/정지·유사 오답 거부, 추적 실패와 시간 초과를 각각 기록한다. 독립 참가자/장면 family로 보정·평가한 뒤 채점 후보를 채택한다. 3D 기준 좌표·mesh/depth/정답 seed는 비공개로 유지하며, 유사도 점수·자세 관문·보호 동작의 인증 결과를 별도 보고한다.

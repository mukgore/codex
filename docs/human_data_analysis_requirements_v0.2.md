# 가려진 손동작 CAPTCHA — 데이터 분석 확장 요구사항 명세서 v0.2

> **상태:** 제안 명세 / 실행 승인 전 · **기준일:** 2026-10-19  
> **대상:** `mukgore/codex` 연구·검증 저장소. 초기 구현의 기준 저장소는 `mukgore/handcaptcha`.  
> **이력:** 기존 「가려진 손동작 캡차 — 데이터 분석 확장 요구사항 명세서」 v0.1의 DR1–DR3, FR1–FR6, NFR1–NFR4, 학습 요구사항을 계승하고, 2026-10-17까지의 Codex 1차 감사 결과를 반영한 *새 버전*. v0.1 파일 자체를 수정하지 않는다.  
> **권한 경계:** 이 문서를 저장소에 등록하는 행위는 새로운 연구 단계·실험·서비스·인간 대상 조사 또는 가중치 배포를 승인하지 않는다.

## 1. 목적과 검증 질문

### 1.1 A단계: 기존 인간 n=18 데이터의 심층 분석
기존 `hand_captcha_*.json` 18세션에서 검출 누락, 이상치, 지표 분포와 중복성, 통계적 불확실성, 점수식 민감도를 분석한다. **인간 데이터만으로 최적 CAPTCHA 보안 가중치를 주장하지 않는다.** 현재 자료가 지지하는 결론과 지지하지 못하는 결론을 구분한다.

### 1.2 B단계: 후속 인간–공격 비교의 분석 준비
인간과 HaMeR/원 주변 정보 공격/원 궤적 공격 등의 성능을 비교하기 위한 **평가 설계만 제안**한다. 개발·검증 데이터 분리, 동일 challenge, 공격자의 정보·자원, gate/score/전체 인증을 분리하도록 명세한다. B단계의 신규 실행과 방어 구현은 별도 승인 후 진행한다.

### 1.3 연구 질문
- RQ1. 손 랜드마크 미검출과 시간적 누락은 어떤 분포를 보이며, 점수에 얼마나 영향을 주는가?
- RQ2. 저장된 세 가지 채택 지표(angle, dtw_angle, accel)의 분포·상관·중복성은 어떠한가? 나머지 네 지표는 실제 코드·좌표로 신뢰성 있게 재계산할 수 있는가?
- RQ3. 인간 점수 및 각 지표의 추정 불확실성과 가중치·정규화 상수 변화에 대한 민감도는 어느 정도인가?
- RQ4(후속). 인간 통과율을 유지하며 공격 통과율을 낮출 수 있는 평가식이나 CAPTCHA 방식이 존재하는가? 이를 홀드아웃에서 재현하는가?

## 3. 데이터 요구사항 (DR)

- **DR1 스키마 검증:** `experimentInfo`, `keyframes`, `segments`, `segments[].frames[].{t,lm}`, `scores.{raw,estimated,captcha,threshold,passed,weights}`, `sessionLog`를 파싱한다. 관측된 버전과 개수는 검증하되, 8 keyframe/7 segment 등을 모든 미래 버전에 무조건 강요하지 않는다. 실제 차이는 보고서에 남긴다.
- **DR2 결측 구분:** `segments[].frames[].lm == null`만 기록된 프레임의 명시적 검출 실패로 센다. `sessionLog`의 `detecting_hand`/`matching`/`recording`/`done`은 따로 집계한다. 기록 자체가 없는 시간 틈은 자동으로 결측 프레임 수에 넣지 않는다.
- **DR3 프레임 분모와 경계:** 현재 세그먼트 프레임 8,782개와 recording phase의 sessionLog 프레임 8,764개가 다른 사실을 재확인하고, 단계 경계·기록 코드와 대조한다. 원인 확인 전 추측을 사실로 쓰지 않는다.
- **DR4 지표 계보:** 채택 세 지표는 저장된 `raw`와 구현 코드를 대응시키고, 나머지 4개 후보(거리, DTW-거리, 위치 경향성, 궤적 유지성)는 정의·필요 데이터·구현 상태를 먼저 검토한다. 결손 입력이 있으면 **계산 불가**로 기록하고 값을 만들어 넣지 않는다.
- **DR5 명칭 정확성:** `dtw_angle`이 실제 일반 DTW인지 확인한다. 기존 감사에서는 sliding-window angle match라고 보고했다. `accel`은 timestamp 기반 물리 가속도로 해석하지 않는다.
- **DR6 계보와 재현성:** 분석마다 입력 스냅샷, 코드 revision, 스키마/채점식 버전, 파라미터, random seed, 제외 규칙 및 생성 파일을 기록한다. 공개 결과는 비식별 집계만 남긴다.

## 4. 기능 요구사항 (FR) / 수용 기준

### FR1 결측 심층 분석 — 기존 감사 위에 추가
- 참가자·segment·phase별 기록 분모와 null 개수, 결측 연속 길이(run length) 및 구간별 시간 분포를 요약한다.
- 결측/검출률과 관측된 지표·점수·손 선택·시간 사이의 관계를 탐색한다. 반복 비교는 탐색적 결과임을 표기한다.
- MCAR/MAR/MNAR는 **관측 자료만으로 확정하지 않는다**. 검증 가능한 보조 가정, 관측 불가능한 요인과 민감도 분석 한계를 기술한다.
- **수용:** 18세션 전원 집계 확인(비공개), 공개용 비식별 요약·연속 결측 분포·메커니즘 식별 한계·분모 차이 조사 결과.

### FR2 이상치·품질 분석
- 세션별 score, 총 기록 프레임, 각 지표 원오차, recording 시간, 전체 sessionLog 범위, 결측 비율에 대해 IQR 후보를 표시한다.
- 점수 이상치와 시간 이상치가 다른 사례를 설명한다. 기존 v0.1의 특정 참가자 사례는 *검토할 가설*이지 자동 제외 규칙이 아니다.
- 원천 기록 오류가 입증되지 않은 낮은 점수·긴 수행·인식 실패는 유지한다. 전체 포함 분석과 적절한 민감도 분석을 별도로 보고한다.
- **수용:** 지표별 이상치 후보 수, 오류 증거, 처리 사유, 원자료 포함 결과와 민감도 결과(개인별 표는 비공개).

### FR3 지표 분포·상관·중복성 분석
- 우선 저장된 세 지표 `angle`, `dtw_angle`, `accel`의 raw/estimated 분포를 구별해 분석한다. 가능할 때만 나머지 네 지표로 확장한다.
- Pearson/Spearman의 적용 조건, 상관계수와 표본 수, 산점도/행렬, 다중 비교와 큰 불확실성(소표본)을 기록한다. `|r| ≥ 0.7`은 탐색 플래그일 뿐 절대적 판정 규칙이 아니다.
- 상관이 낮다는 사실을 판별 성능이 좋다는 근거로 사용하지 않는다. 결측률이 공통 승수인 `estimated`의 상관은 `raw`와 구별한다.
- **수용:** 3지표부터 시작하는 재현 가능한 상관행렬, 원자료 가용성표, 중복 지표 후보와 대안 해석.

### FR4 추정 불확실성
- 참가자/세션 수준으로 점수와 세 지표의 평균, 중앙값, SD 및 95% 신뢰구간을 계산한다. 재표집은 최소 1,000회, 권장 10,000회 및 seed 고정.
- bootstrap 방식, 표본 단위, percentile 방식 한계 및 분포 모양을 명시한다. 통과 비율은 분모와 적절한 구간(Wilson 등)을 함께 표시한다.
- 18명을 대표 모집단으로 확정하거나, 같은 clip의 frame을 독립 bootstrap 대상으로 삼지 않는다.
- **수용:** 변수별 표본 수·점추정·불확실성 표 + 사용한 함수/seed·검증 테스트.

### FR5 가중치·정규화·판정 민감도와 일반화 한계
- 기존 가중치 `dtw_angle=.38, accel=.37, angle=.25`, threshold `.25`, 정규화 `E_max`를 **기준값**으로 고정한다. 해당 값의 원래 선정 정당성은 검증 상태를 별도 표시한다.
- 사전에 정의한 제한된 시나리오에서 가중치·정규화 상수·threshold를 **분석상 변화**시키고, 인간 점수/통과율·순위 변화를 측정한다. 기존 결과와 새 계산 결과를 구분한다.
- CV는 평균이 0 부근이거나 척도상 적합하지 않으면 쓰지 않으며, CV가 작다는 이유만으로 새로운 사람에게 일반화된다고 주장하지 않는다.
- **수용:** 기준 대비 민감도 표, 변경 시나리오와 선정 이유, n=18 및 클립 다양성 한계를 포함한 해석. **실제 CAPTCHA 채점값은 변경하지 않는다.**

### FR6 공격 판별력 비교 — 설계 선행 / 실행 승인 별도
- 공격 종류별 관측 가능 정보(원 중심·크기, 원 가장자리 피부-bit, 파일 메타데이터, 저장 정답 library, 모델 추론)와 계산 자원을 표기한다.
- 인간/공격자에게 동일한 challenge/판정 환경을 맞추거나 차이를 독립 변수로 통제한다.
- **gate 성공**, **최종 score 기준 통과**, **실제 전체 인증 흐름 통과**를 서로 다른 결과로 기록한다. `stop_on_fail=false` 결과를 전체 통과로 합치지 않는다.
- 개발/검증 분할은 원본 gesture/clip 기준으로 하며 변형·미러·반복 세션이 다른 분할에 섞이지 않도록 한다. threshold 조정은 hold-out 평가 전에 중단한다.
- **수용(현재):** 실행 계획, 공격 모델, 분할·지표 정의, 사전 실패/성공 기준 초안. **실제 새 실험/판별모델 훈련은 승인 전 금지.**

## 5. 비기능 요구사항 (NFR)
- **NFR1 보존:** 원본 연구보고서, v0.1 명세, 실험 원자료, 기존 집계 파일을 덮어쓰지 않는다. 별도 새 출력만 생성한다.
- **NFR2 검증:** 구현/통계 계산 담당자와 독립 검증 담당자를 분리한다. 테스트는 원자료 불변, 분모 일치, seed 고정, 결측/Boolean 예외 및 재실행 결과 일치를 확인한다.
- **NFR3 결과 구분:** *확인됨 / 재현됨 / 탐색적 / 미확인 / 자료 부족 / 제안* 상태를 표시한다. 통계적 유의성이 실제 공격 저항과 동의어가 아님을 명시한다.
- **NFR4 프라이버시:** 공개 저장소에는 집계와 코드만 선택적 반영, gitignore 및 개인정보 누출 검사, `git add .` 지양.
- **NFR5 자원:** 기본은 무료·CPU 분석, GPU/유료 API가 필요한 작업은 사전 보고.
- **NFR6 단계 승인:** 원자료 추가 탐색 범위 확대, 신규 데이터 생성, 사람 모집, 새로운 CAPTCHA 구현·배포, 가중치 변경 및 새 공격 실험은 해당 단계 승인 후 진행한다.

## 6. 학습과 연구자 판단 (LR)
- **LR1:** 결측→이상치→상관→추론→일반화→선택적 판별모델 순으로 개념 요약을 학습한다. 주당 약 3시간은 v0.1의 계획상 가정이지 강제 일정이 아니다.
- **LR2:** 에이전트는 계산·진단·반증과 근거를 제공한다. 연구 결론의 최종 해석과 논증은 연구자가 직접 검토한다.
- **LR3:** 각 단계에 “내 해석 / 검증 에이전트의 반론 / 추가 확인 항목”을 함께 기록한다. 연구자가 승인할 때 다음 단계로 간다.

| FR6 | `docs/threat_model.md`, `docs/followup_experiments.md` | 설계 문서 존재, 신규 비교 실험은 미승인 |

위 상태는 저장소 코드/문서 검토에 따른 *잠정 작업 분류*다. 구현을 실행해 검증한 새 결과가 아니며, Codex가 실행 시 변경 사항과 실제 입력을 확인해야 한다.

## 8. 산출물 및 단계 게이트

| 게이트 | 산출물 | 허용 상태 |

## 9. Codex 에이전트 연결 정책
- **main/orchestrator:** 프로젝트 상태·승인 경계 확인, 기존 규칙 중복 회피, 검증자 반론과 작업별 완료 근거 통합.
- **captcha-data-auditor:** DR1–DR6, FR1의 입력 품질·결측·계보 / 읽기 우선.
- **captcha-data-analyst:** FR2–FR5 통계 계산 및 단계별 산출물 / 기존 결과와 새 분석 분리.
- **captcha-analysis-verifier:** 각 계산 독립 재현, 표본 단위·누출·과도한 주장 검토. 개발자의 성공 주장 검증 없이 통과시키지 않음.
- **captcha-research-reporter:** 근거 매핑/결과와 해석 분리/연구자 결론 작성 여지 보존.
- **captcha-developer / captcha-tester:** 분석 자료 요구가 있는 경우 자문만; G4 승인 전 새로운 CAPTCHA 방식 개발·공격 실행 금지.
- 로컬 `.codex/agents/*.toml` 및 `AGENTS.md` 규칙이 이미 있으면 **병합**한다. 새 규칙을 덮어씌워 역할·권한·승인 경계를 잃지 않는다.

# 촬영 손동작 풀과 표준 3D 생성 방법 비교·재현 요구사항 v0.1

- 작성일: 2026-10-26. 상태: **설계/문헌 검토만 완료, 생성 모델 재현·촬영·인간/공격 시험은 NOT TESTED**.
- 연결: [영상 풀 v0.4](video_pool_occlusion_delivery_requirements_v0.4.md), [3D 후보 v0.1](3d_hand_object_challenge_requirements_v0.1.md), [실용성 검증 v0.3](practical_validation_requirements_v0.3.md).
- 결정: **촬영 영상 기반의 작은 공정한 baseline을 먼저 만들고**, 같은 과제의 표준 3D 생성 연구를 연구용으로 재현하여 비교한다. 촬영을 생략하거나 3D가 우월하다고 미리 가정하지 않는다.

## 1. 질문과 판단

생성의 이점은 원본 영상의 **개수**가 아니라 독립적이고 사람이 풀 수 있으며 공격자에게도 어려운 **새 동작 family**를 얼마나 낮은 비용으로 공급하는가에 달린다. 이미 나온 영상은 촬영과 생성 모두 복제된다. 생성 규칙이 알려져도 성립하는 공격 실험이 필요하다. 사람의 3D 손 모델과 물체를 만든다고 통과 입력의 진위를 검증할 수 있는 것은 아니다.

### 1.1 동작을 무엇으로 셀 것인가

하나의 문제를 `(사용자가 해야 할 일, 접촉/전환 순서, 필요한 가려진 자세, 관측 가능한 차이)`로 기술한다. 아래는 **설계 후보 분류**이며 기존 pool의 실제 보유 수량을 뜻하지 않는다.

| 동작군 예시 | 촬영과 가림 | 제약된 3D 생성의 잠재 이점 | G0: 물건 없는 사용자에게 요구할 수 있는 일과 위험 |
|---|---|---|---|
| 손 펴기·주먹·개별 손가락 접기 | 한 번 촬영하면 다른 손/속도 take 확보가 쉬움 | 관절·형태 변형은 쉬우나 의미 있는 새 답의 수는 적음 | 쉬운 출발점, 손끝 정보가 안 보이면 애매한 답에 유의 |
| 손가락의 순차 굽힘·펴기 | 여러 순서와 전환을 촬영할 수 있음; 직접 촬영이 자연스러움 | 길이·순서·속도 조건을 많이 제어 가능 | 너무 빠른 전환, 비독립 손가락 동작을 제거 |
| 엄지 대립·집기(pinch)·손가락 접촉 | 손가락 짝과 접촉 순서를 달리 촬영 | 손가락 조합/접촉 계획을 통제 가능 | 세밀한 엄지·손끝 인식 실패와 개인차 |
| 손목 이동·회전 + 자세 전환 | 다양한 시간 궤적을 촬영 가능 | 연속 궤적 변화 가능 | 가림 원 궤적만으로 정답을 식별하는 지름길 차단 필요 |
| 원통형·구형·평판형·손잡이형 물체 잡기 | 실제 물체와 손의 상호작용을 촬영하면 자연성과 물체 단서가 강함 | 물체 크기·접촉점·시점 변형 가능 | **실제 물체 없이** 힘·접촉을 확인할 수 없음; 흉내 가능한 손모양만 채점 |
| 집기→움직이기→놓기·재파지 | 여러 물체/행동과 연속 동작을 촬영하면 표현력 높음 | 접촉 사건·물체 경로 조합 가능, 생성/검수 난도 높음 | 빈손 모사가 부자연스럽고 단안 카메라 관측이 어려울 수 있음 |

**촬영 쪽에서 가능한 실제 다양성:** 손의 형상·개인차, 습관적인 관절 연동, 작은 흔들림, 접촉 타이밍, 여러 물체가 저절로 주어진다. 새 행동 family를 직접 시연하고 촬영해야 하며, 가린 후에는 가려진 관절의 믿을 만한 정답 좌표가 없을 수 있다. 같은 사람의 같은 동작을 좌우 반전·배속·재인코딩·마스크 위치로 바꾸는 것은 새로운 family가 아니다. 현재 공개 8 clip과 과거 자료를 비공개 신규 풀로 계산하지 않는다.

**생성 쪽에서 가능한 다양성:** 같은 접촉 계획에 대해 손 크기·물체 형태·시점·이동 경로·속도·가림을 통제하고 대응쌍을 만들 수 있다. 하지만 많은 seed가 거의 같은 동작으로 보이거나 사람에게 불가능하거나, 생성기/렌더 특성으로 같은 정답을 드러내면 유효한 문제 수는 늘지 않는다. 물체의 정확한 접촉을 주장하려면 G1/G2가 필요하고 G0에서는 추정·모사만 다룬다.

**잠정 선택:** 연구 초기에는 직접 촬영이 자연성·권리·CPU 비용의 기준선으로 더 유리하다. 같은 동작군에서 촬영을 계속 추가할 때의 고유 family 확보 비용과 생성 후보의 검사 통과율을 측정한 후, 생성이 반복 보충에 이익이 있는지 결정한다. 이 비교는 비용/다양성의 판단이며 보안 우위를 뜻하지 않는다.

### 1.2 계수·중단 기준

- 원본 수, 고유 사람/물체/촬영 session 수, 동작/접촉 family 수, 마스크 후 시각적으로 구별 가능한 문제 수, 사람 재현 가능 수, 강한 공격 평가까지 통과한 수를 각각 센다.
- 같은 capture에서 파생된 crop, mirror, speed, noise, 다른 seed는 출처와 동작 family를 이어서 기록한다. 계보를 모르면 독립 문제로 인정하지 않는다.
- `유효 수율 = 사람이 이해·재현하고 최종 가림/누출 검사를 통과한 고유 문제 수 / 후보 수`; `고유 family당 총 비용 = 수집/학습 + annotation + 렌더 + 검수 + 송출`. 둘 다 **사전 등록할 측정값**이지 아직 관측값이 아니다.
- 촬영 우선 가설을 뒤집을 증거: 생성이 새 family를 더 싸게 내면서 인간 성공·완료 시간·접근성을 악화시키지 않고, 동일 공격 예산에서 보호 동작까지의 공격 성공률을 낮춘다. 셋 중 하나만 좋아서는 보안상 우위로 판정하지 않는다.

## 2. 표준 연구 방법: 무엇을 그대로 재현하고 무엇을 바꾸는가

여기서 `재현`은 저자의 공개 데이터·코드·가중치와 평가 설정을 허가 범위에서 사용해 **원 논문 과제**를 반복하는 것이다. `전용`은 CAPTCHA의 G0, 가림, 서버 판정, 비공개 송출을 새로 붙이는 별도 실험이다. 전용 결과를 원 연구의 재현 성능이라고 부르지 않는다.

| 축 | 검증된 원 연구의 방법 | 우리 연구에서의 위치 | 현실적 제약 |
|---|---|---|---|
| 실제 분포/접촉 | GRAB(ECCV 2020): 실제 사람의 손·몸·물체 시간 자세와 mesh로 접촉 도출 | 자연성 기준 및 별도 연구용 train/test 후보 | 비상업 연구 제한; 우리 촬영 원본/동의 대신 사용 불가 |
| 손 형상/자세 | MANO(SIGGRAPH Asia 2017): 실제 손 스캔으로 학습한 저차원 관절/형상 모델과 자세 연동 | 연구 재현에서 원 저자의 hand representation 유지 | 상업 서비스·상업용 산출물에 모델 그대로 사용 금지 |
| **주 기준 생성** | **Text2HOI(CVPR 2024): text+물체 mesh→VAE 접촉 확률→Transformer diffusion 시간 동작→접촉 안정성/관통 보정** | 논문 방법을 가장 가깝게 재현할 연구 경로; 물체별/행동별 생성 다양성 평가 | H2O/GRAB/ARCTIC/MANO와 checkpoint의 권리, GPU/학습 비용 확인 필요 |
| 목표 파지→전환 | GOAL(CVPR 2022): GNet 목표 grasp, MNet 시작→목표 동작 | 과제 분해와 모션 자연성 비교. 전체 몸/머리 요구는 G0에 불필요 | GRAB/SMPL-X 모델·가중치 등록/제약 |
| 물리 접촉 기반 동작 | D-Grasp(CVPR 2022): 물리 시뮬레이터 + 계층적 RL의 low-level grasp, high-level object motion | 물체를 안정적으로 움직이는 생성의 **강한 연구 비교군** | RaiSim license/activation, 과거 공식 실행 환경에 GPU 2080 Ti 사용; 무료 CPU 실시간 가정 금지 |

### 2.1 Text2HOI 원형을 따르는 연구용 재현 순서 (R1)

1. **재현 전제 확인:** 저자 논문 버전, 공식 코드 commit, checkpoint 버전, H2O/GRAB/ARCTIC 각 데이터 약관, MANO 약관, mesh 권리와 실행 환경을 manifest에 기록한다. 허가 없이 연구 데이터/가중치를 공개 Git·상업 웹서비스에 올리지 않는다. 저자의 공식 README에서 demo, 전처리, 학습 명령을 확인한다.
2. **원본 전처리:** 원 저장소가 요구하는 시간 동작, 손/물체 표현, 물체 mesh를 그대로 준비한다. GRAB 물체 mesh를 4,000 vertices로 축소하는 저자 절차와 `preprocessing_grab_object.py`, `preprocessing.py`를 원형 연구 환경에서 실행한다. 임의로 2D MediaPipe 21점을 3D GT로 취급하지 않는다.
3. **원 모델:** 텍스트/물체 mesh 조건부 VAE로 손·물체 표면 contact probability를 얻고, 그 contact map을 조건으로 Transformer diffusion이 시간에 따른 손·물체 3D 동작을 생성한다. 저자 hand refiner로 접촉 거리, 시간 안정성, 관통을 보정한다. 직접 만든 선형 보간기를 Text2HOI 재현이라 부르지 않는다.
4. **원 평가를 먼저:** 저자 공식 demo/checkpoint의 산출과 논문/저자 평가 방법을 같은 데이터 분할에서 확인한다. 객체 미관찰 분할, 샘플 다양성, 운동 자연성, 접촉 안정성, 관통을 보고하고 공개 구현과 재현 설정의 차이를 기록한다. 성공률을 원 논문의 CAPTCHA 성능처럼 인용하지 않는다.
5. **그 후 별도 CAPTCHA 전용:** 모델 출력→캡처 가능한 단일 손 G0 과제 필터→카메라/조명 설정→서버에서 최종 가림 렌더→최종 바이트 검사→세션 발급. 이 후처리나 모델 재학습이 들어가면 `adaptation` 버전으로 표시한다. 원 생성 모델을 브라우저에 제공하지 않는다.

공식 코드 README의 `scripts/demo.sh`, `scripts/train/train_texthom.sh`, `scripts/train/train_refiner.sh`는 재현 경로의 출처다. **이번 커밋에서 다운로드·실행하지 않았으며** checkpoint, GPU, 권리 동의를 확보했다고 간주하지 않는다. MIT인 공개 **코드**와 외부 데이터·MANO·weights·generated media의 허가를 분리한다.

### 2.2 별도 저비용 파일럿 (P1: 논문 재현 아님)

GPU/사용권의 제약 아래 촬영한 동작 2~3 family를 자체 기본 손 skeleton과 primitive 물체로 옮긴다. 촬영된 동작의 시간/접촉 사건을 보존하고, 관절/속도/물체 크기를 **그 사람의 관측 범위 주변에서만** 변형한다. 접촉 계획을 먼저 정하고 동작을 생성한다는 점은 Text2HOI/GOAL의 분해와 닮았지만, VAE/diffusion/학습된 MANO prior/물리 RL을 구현하지 않았으므로 해당 모델의 '복제'라고 표현하지 않는다.

이 파일럿의 목표는 동일 가족 변형의 수율/지연/가림 유효성과 공격 경로를 빨리 측정하는 것. 직접 촬영 baseline(B0)과 나란히 평가하고 결과가 나오면 R1의 연구용 재현 또는 라이선스가 명확한 자체 모델 개발로 갈지 결정한다.

## 3. 생성 동작 채택 계약

### 3.1 후보 레코드 (외부에는 비공개)

`generator_name, paper/code/checkpoint_hash, model_asset_licenses, source_family_id, subject_or_template_id, action_family_id, object_family_id, grasp_type, contact_plan_id, trajectory_family_id, seed, hand_shape, handedness, camera_family_id, t_i, q_i, object_pose_i, contact_i, mask_i, rendered_asset_hash, gate_versions, rejection_reasons`.

R1 재현용 레코드와 P1 자체 레코드를 분리한다. 모델/객체 family가 다른 seed여도 동일 훈련 family면 미관찰 객체 시험이라고 하지 않는다. 정답 및 원본 3D 데이터는 공개 정적 경로에 두지 않는다.

### 3.2 자동 검사와 인간 검사

| 단계 | 검사와 실패 처리 | 근거/주의 |
|---|---|---|
| 3D 구조 | 관절 범위·연동 prior·손 형상, 손/물체 및 손가락 자기 관통, 길이/좌우 일관성 | 수치 범위는 인체 근거/자료 분포와 버전으로 고정; 임의 보편값 금지 |
| 시간 | 실제 `t_i`로 속도/가속도/불연속 검사, reach→contact→release 순서 | 부드러운 궤적만으로 실제 사람 가능성이 보장되지 않음 |
| 접촉 | 의도된 손가락/물체 표면 거리와 유지 시간, 상대 미끄러짐; G0는 **기준 장면**만 검사 | 사용자 웹캠으로 힘·실제 접촉을 검증했다는 주장 금지 |
| 렌더/가림 | 모든 표시 프레임 mask 유효, 손/물체 단서 유지, 그림자·반사·buffer·metadata의 가려진 답 누출 없음 | 최종 디코딩·가림 검사에 실패하면 발급 금지 |
| 사람 | 가림을 보고 과제 설명, 재현 성공, 소요시간, 통증/불편·기기/손 차이 확인 | 소규모 파일럿은 일반화가 아닌 reject gate |
| 공격 | 마스크 궤적·lookup·보이는 픽셀 추정, 공개 생성기·물리/IK/접촉 추론, 출력 위조 | 강한 공격이 통과하면 '3D라 안전' 결론 금지 |

고정 임계값은 **사전 실험 전** 근거와 선택 자료 split을 기록한다. 임계값을 시험 자료 성능에 맞게 뒤늦게 조정하지 않는다. 후보가 fail하면 거부하고 새로운 후보를 발급한다. 일정 횟수 연속 실패 시 생성 중단과 사용 가능한 다른 과제로 fallback; fallback도 같은 서버 판정/가림 규칙 적용.

### 3.3 비교 실험과 가설

| 군 | 원천/제시 | 검증할 효과 |
|---|---|---|
| V0 | 직접 촬영, 원래 동작/물체, 동일 가림 정책 | 자연성과 수집 비용의 기준 |
| V1 | V0의 제한된 기하/시간 변형 | 얕은 변형으로 유효 family 증가 여부 |
| V2 | P1 자체 skeleton·접촉 계획의 제약된 생성 | 저비용 합성의 수율과 사람 모사 가능성 |
| V3 | R1 Text2HOI 연구용 출력(권리 허용 범위에서만) | 표준 생성 모델의 자연성/다양성/공격 난도. 공개 서비스 출하 시험 아님 |

- 동일 화면 크기/과제 길이/가림 정도/카메라 요구와 동일 채점 규칙에서 비교. V0의 실제 촬영 프레임과 V3의 렌더 프레임은 외관 차이가 있으므로 그 차이만 쓰는 공격도 별도 보고한다.
- 원천 source/capture, 사람, 물체 **형상 family**, 접촉 계획, 동작 family를 기준으로 train/dev/test를 갈라 새 seed만으로 미관찰 문제라고 하지 않는다. 사람에게 같은 답을 여러 번 보여 학습 효과를 만드는 순서를 피한다.
- 정답이 한 가지가 아닌 물체/자세에는 허용 가능한 손모양 집합을 정의하고, 사람 다양성과 모델 오차를 구분한다. 3D 좌표 GT와 웹캠에서 추정한 2D landmark를 같은 정확도로 취급하지 않는다.
- 사전 등록한 일차 결과는 서버가 실제 보호 동작을 허용한 인간/공격 성공률과 걸린 시간. 보조 결과는 고유 family 수율, 품질 탈락 사유, 촬영/생성/검수 비용, 생성·송출 지연 및 접근성.
- V2/V3가 V0보다 수율이 높아도 사람 실패나 공격 성공이 늘면 운영 이점과 보안 효과를 따로 결론 낸다. 신뢰구간과 표본 단위를 명시하고 작은 차이를 확정하지 않는다.

## 4. 실행 순서 및 완료 정의

1. **준비:** G0에서 가능한 동작 family를 촬영 대상별로 확정. 직접 촬영과 synthetic의 물체·그립·시점을 맞추고 권리 대장 작성. 원 영상과 대응하는 기준 자세/시간/가림 정보가 없으면 그 셀을 BLOCKED로 둔다.
2. **baseline:** V0 촬영→최종 가림 산출→사람 파일럿→기존/강한 공격. 실제 source를 보존하고 중복 family를 제거한다.
3. **저비용 생성:** P1 제작 및 V1/V2의 유효 수율, CPU 비용, 탈락 사유 측정. 단순 코드 제약은 진짜 인간 수행 실험으로 검증.
4. **원형 재현:** 필요한 연구용 사용권과 환경을 별도 확보한 경우에 한해 R1 실행. 저자 환경/분할/모델/로그·재현 차이를 저장한다. 없는 상태에서는 재현 완료로 표기하지 않는다.
5. **서비스 경계:** 후보가 유망하면 서버가 문제와 정답을 비공개 발급·검증하고 브라우저에 가려진 최종 출력만 전송. 입력 위조/가상 카메라, 반복노출, lookup까지 다시 시험한다.

현재 DONE은 **문헌 검토와 실험 설계**뿐이다. V0–V3의 수율/성능, 원형 코드 실행, 비공개 서버와 상업 라이선스는 미완료다. 장래 사업화에는 연구용 MANO/GRAB/SMPL-X에 의존하지 않는 자산/모델을 만들거나 개별 상업 허가를 확보해야 한다.

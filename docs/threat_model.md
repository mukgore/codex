# 기존 시스템의 위협 모델과 평가 경계

## 자산·판정 지점

현재 제공 HTML은 브라우저에서 동작하는 연구용 과제다. 목표 클립/랜드마크 pool은 정적 파일로 불러온다. 브라우저는 사용자가 촬영한 손 좌표를 읽고, 클라이언트에서 keyframe 자세 관문과 전체 score를 계산한다. `passed` 결과는 브라우저 세션 JSON 및 외부 업로드 설정에 기록된다. 제공 자료에서는 신뢰받는 별도 CAPTCHA 서버가 challenge/answer/one-time token을 검증하는 구조를 확인하지 못했다.

| 평가 층 | 정의 | 현재 증거 |
|---|---|---|
| L1 인식/재구성 | 제시된 프레임에서 손 관절 좌표를 추정 | HaMeR 저장 좌표, visibility/IK 공격 산출물 |
| L2 점수 제출 | 추정 좌표가 계산 점수/관문을 통과 | Python/JS 로컬 채점기와 저장 결과 |
| L3 전체 웹 인증 | challenge 발급→카메라/모델→브라우저 입력→서버 검증→보호 동작 | 검증 증거 없음. 서버·보호 API와 실제 인증 토큰이 범위 자료에서 확인되지 않음 |

L1/L2 성공을 L3 서비스 우회로 보고하지 않는다. 브라우저에서 계산되는 score/threshold/landmarks의 직접 변조 위험은 HTML 코드의 구조상 연구 문제지만, 요청 조작을 실행해 외부 시스템에서 인증된 것으로 확인하지 않았다.

## 공격자 가정별 현재 평가

| 공격자에게 허용된 정보/비용 | 제공 평가 | 해석 |
|---|---|---|
| 공개 HTML, challenge 영상·배경·클립 메타데이터 | 운영 HTML과 pool manifest가 존재 | 파일 이름/클립 ID/URL/길이·메타데이터 활용 공격은 체계적으로 평가되지 않음 |
| 원본 동작 library/landmark를 사전 확보 | `circle_edge_attack` reference_library에 명시 | 높은 사전지식의 lookup 상한. 비공개 정답 DB 유출이 없는 위협모델이라고 일반화하지 않음 |
| challenge의 원 궤적·반지름 정보 이용 | 별도 사용자 보고 공격, circle/IK 관련 명세·결과 | 서로 다른 공격으로 구분. 사용자 보고 결과 원자료와 프로토콜이 없어 수치 재현 불가 |
| 단일프레임 HaMeR 추정, 클립 전환 fade 합성 | 저장된 8 custom의 28 무순서 pair 프레임 | 실제 사용자가 보는 프레임 전환과 공격자 합성 fade가 달랐다는 보고서 한계. 38° gate fail에도 계속 실행 |
| 프레임 추적 MediaPipe 파라미터 조정 | 보고서 표 값·설명만 | 재현 가능한 개별 좌표/로그 미확인 |
| 규칙기반 색상/원 경계 및 5bit matching | 원 공격 코드/저장 관측/참조 library | 딥러닝 불필요 lookup성 공격의 강한 증거. 성공 단위는 영상/방향 16종이며 새로운 참여자·클립 일반화 아님 |
| 생체 제약 IK 및 렌더+MediaPipe | 저장 결과, 8 warped MP4 및 summary | 채널 A는 좌표 oracle 상한, 채널 B는 특정 합성 렌더러/MediaPipe 설정. 실제 virtual camera/network 입력이 아님 |
| 반복 시도, timeout/캐시/batch/offline 계산 | 정보 불충분 | 재시도/시간제한 정책과 서비스 비용 미확인. 준비비용/반복비용 분리 결과 없음 |

## 해석 시 경계

- 모든 model/attack은 특정 8개 클립 및 보이는 단서·화면비·배경에 조건화되어 있다. 새로운 손/동작/조명/카메라/국소 occlusion 일반화는 입증되지 않았다.
- HaMeR 조합 28개는 8개의 원본 gesture가 조합 안에 중복 등장하고 좌우 손은 오른손 clip을 중심으로 평가했다. 통계 독립 표본 28개로 처리해 모집단 공격 성공률 신뢰구간을 내지 않는다.
- human n=18의 독립 단위는 참가자 세션이며 frame 8,782개를 사람 표본 수로 보고하지 않는다.
- 원 관문/점수 기준은 운영 코드와 맞춰지더라도 점수식/기준값 선택이 최종 평가에서 독립되어 있다는 근거가 아직 없다.
- 손 감지 실패, 손 자세 추정오차, 사람의 운동 구현 및 자세 매칭을 각각 독립적으로 계량한 기준영상이 없다.
- 브라우저 장치명이나 영상 입력 provenance를 확인한 적이 없다. 카메라가 물리 장치라고 증명하거나 가상 카메라 공격을 방어한다는 주장은 미검증.
- 손 또는 카메라를 쓸 수 없는 사용자, 장애/접근성, 개인정보·영상 전송·보관, 실제 무료 서버의 비용/한도는 1차 검증 범위 밖이다.

## 아직 시험하지 않은 저비용 baseline

보기만 가능한 프레임/파일/전환시간으로 challenge 식별, 고정·마지막·평균 자세 재생, 앞/뒤 프레임 보간, 소수 프레임 처리 후 보간, gesture pair 순서 차이, 브라우저 직접 score/passed 조작, API 직접 호출은 현재 자료의 결과로는 판단할 수 없다. 성공/실패 방어로 표현하지 않고 미검증으로 유지한다.

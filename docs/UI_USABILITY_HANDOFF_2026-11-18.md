# 현재 핵심 작업: prod 복사본 기반 손 모방 UI·손 선택 개선

작성: 2026-11-18 / 사용자 최신 지시 / 새 Codex CLI 세션의 첫 실행 문서

## 1. 목적과 우선순위

연구자가 학업과 병행하며 하루 5~10분 실행·확인하고, 인간 사용자로서 피드백을 주면 AI 개발자가 같은 실행본을 개선하는 작업 방식이다.

**현재 핵심 할 일은 사람이 손동작을 따라 하는 UI와 사용자 손 인식·선택 과정의 사용성 개선이다. 첫 전달물은 실제 prod에서 복사한 실행 가능한 개선본 하나다.**

이 지시는 기존 전체 백로그 자동 진행 및 3D/통계/runtime 등의 다음 작업보다 우선한다. 기존 연구 결과와 미완료 목록은 보존하지만 이번 세션에서 범위를 넓혀 실행하지 않는다. 원본·개인자료 보호 규칙은 유지한다. 과거 문서의 "새 UI 구현 승인 전" 같은 제한은 이번 명시적 UI 구현 요청의 범위에서는 해소되었다. 운영 배포나 새 참가자 모집까지 승인한 것으로 해석하지 않는다.

첫 전달물의 필수 기능:
1. 목표 손 영상과 사용자 카메라 화면을 겹친 주화면.
2. 여러 검출 손 중 일정 크기 이상이며 카메라에 가장 가까운 것으로 추정되는 손의 선택, 안정적 유지, 해당 손 데이터만 CAPTCHA에 연결.
3. 기존 prod의 문제 재생 → 시작/수행 → 관문·채점 → 결과·저장을 실제로 실행할 수 있는 흐름.

## 3. prod 복사본 원칙과 단일 실행본

- 현재 handcaptcha의 prod를 복사하여 격리된 실험 경로에서 개발한다. 예: experiments/prod_usability/ (실제 구조에 맞춰 한 경로로 확정).
- 원본 prod와 공개 운영본을 덮어쓰지 않는다. 모든 후속 피드백도 이 prod 유래의 동일 개선본에 누적 반영한다.
- 첫 단계에서 새로운 UI 조합 페이지·다수 HTML 변형·64조합 탐색을 만들지 않는다. 사용자에게 전달하는 기본 실행 URL은 하나다.
- 기준 prod는 내부 회귀 비교용으로 유지할 수 있다. 사용자가 여러 기준본을 번갈아 실행해야 하는 구조로 만들지 않는다.
- 문제 선택·영상/정답 로딩·카메라·추론·관문·채점·결과 저장은 기존 흐름을 유지한다. 손 선택 결과를 연결하기 위한 변경만 명시적으로 반영한다. 점수 공식·가중치·통과 기준·문제 내용은 이번 범위에서 변경하지 않는다.
- 정적 화면, mock 카메라, 독립 overlay 데모만으로 완료 처리하지 않는다. 누락 자산이 있으면 정상 prod 자산을 재사용하고 경로를 연결한다. 실제 자산 확보가 막히면 무엇이 필요한지 정확히 보고한다. 가짜 결과로 대체하지 않는다.

## 4. 기능 A — 목표 손 영상과 카메라 중첩

- 하나의 주화면에 사용자 카메라와 기존 가림 목표 영상을 겹쳐 동시에 볼 수 있게 한다.
- 카메라와 목표 손을 구별할 수 있는 합리적인 기본 투명도, 간단한 라벨, 필요 최소한의 투명도 조절만 제공한다. 기존 분리 화면으로 돌아가는 단일 토글은 비교가 필요할 때만 둔다.
- 원본 영상 종횡비를 유지하며 프레임 잘림·늘어짐을 점검한다. 가림 영역의 단서나 숨겨진 목표 손을 추가로 노출하지 않는다.
- 불투명 배경 때문에 한쪽 손이 가려지는지 실제 자산으로 확인한다. 단순히 video 두 개를 쌓는 것으로 끝내지 않는다. 배경 처리 등 필요 변경은 표시 계층에만 적용하고 방법·한계를 기록한다.
- 카메라/목표의 좌우 반전, 표시 크기, 위치 기준을 명시한다. 시각적 반전이나 확대를 채점 좌표에 중복 적용하지 않는다.
- 손 인식 입력은 원본 카메라 프레임이다. 목표 영상·안내선·합성 화면을 손 인식기로 다시 넣지 않는다.
- 카메라 입력 해상도/FPS와 화면 크기를 구분한다. 사용자의 손을 어디에 두어야 하는지 짧게 안내하고 선택된 손을 가벼운 테두리 등으로 표시한다.
- 자동 손 정렬·새 자세 교정·여러 신규 안내 방식은 첫 전달물의 필수 범위가 아니다.

## 5. 기능 B — 충분히 크고 가까운 손 선택

### 가까움의 정의
일반 단안 웹캠에서 실제 거리나 사용자 신원을 보장할 수 없다. 첫 구현에서는 **화면에서 차지하는 정규화 손 크기**를 가까움의 대용값으로 사용한다. "가장 가까운 손"의 구현은 "최소 크기를 만족하는 유효 후보 중 화면상 가장 큰 손"이다. 이 한계를 README에 명시하고 상대 landmark z를 절대 카메라 거리로 취급하지 않는다.

### 후보와 선택
- 검출기의 다중 손 설정을 확인하고 복수 후보를 실제 반환할 수 있게 한다.
- 유효한 21개 landmark, 유한 수치, 유효 영역 등 기존 검사와 호환되는 후보 판정을 사용한다.
- 최소 크기는 해상도와 무관한 값으로 정의한다. 예: bbox 면적 / 카메라 프레임 면적. 산식·임시 기본값·단위·설정 위치를 기록한다.
- 자세에 따른 bbox 변화의 한계는 기록하되 첫 버전을 복잡한 거리 추정 연구로 확장하지 않는다.
- 후보가 없으면 "손을 조금 더 가까이 보여 주세요"처럼 구체적으로 안내하고 임의의 작은 손을 선택하지 않는다.
- 초기 선택은 최소 크기를 넘는 가장 큰 후보가 일정 시간 안정적으로 유지될 때 확정한다. 임시 크기/시간 기준은 개발자가 합리적으로 정하고 사용자의 실제 피드백으로 조정한다. 과학적으로 검증된 기준이라고 표현하지 않는다.
- 동률·교차·추적 불확실성에는 임의로 다른 손으로 전환하지 않는다. 위치·크기·형태 연속성과 안정화/hysteresis를 이용해 매 프레임 선택이 바뀌는 현상을 막는다. 반환 배열 인덱스나 좌우손 라벨만으로 동일 손을 판단하지 않는다.

### 선택 이후 CAPTCHA 연결
- 선택한 손의 landmark만 시작 관문, 수행 기록, 구간 처리, 채점 및 저장으로 전달한다. 화면 테두리만 변경하고 기존 첫 번째 손 데이터가 계속 흐르는 오류를 검사한다.
- 선택된 손이 유지되는 동안 다른 큰 손이 들어와도 진행 중인 시도에 다른 손 데이터를 섞지 않는다.
- 짧은 검출 누락은 기존 prod의 누락 처리와 일관되게 기록한다. 누락 동안 이전 좌표를 정상 새 관측처럼 채우지 않는다.
- 선택 손이 사라지거나 동일 손 여부가 모호해 재선택이 필요하면 현재 시도를 무효화하고 새 손 선택 후 처음부터 재시작한다. 전환 시 hold 누적·기록 버퍼·관문 상태를 함께 초기화한다.
- 크기 임계값 경계에서 상태가 흔들리지 않게 진입/이탈 또는 시간 안정화 정책을 둔다. 선택 해제·재선택 이유를 최소 로그로 남긴다.
- 이 기능은 사용성 개선이며 사용자 신원 인증·가상 카메라 차단의 증거가 아니다.

## 6. 실행 순서

1. 실제 prod 및 기존 관련 구현을 확인하고 기준본을 고정한다.
2. prod 복사본이 같은 자산으로 기존 CAPTCHA 흐름을 실행하는지 확인한다.
3. 원본 카메라 입력과 표시 계층을 구분하고 중첩 주화면을 연결한다.
4. 다중 손 후보·최소 크기·안정 선택·유지·재시작을 기존 CAPTCHA 데이터 경로에 연결한다.
5. 실제 페이지 실행, 자산 로딩, 기록/채점 흐름과 아래 필수 회귀를 확인한다.
6. 같은 실행본의 URL, 시작 명령, 짧은 점검표를 전달한다.
7. 사용자 피드백을 받으면 같은 실행본에서 수정 → 필요한 검증 → 다시 전달한다.

사용자의 첫 피드백 대기 중에 다른 연구 백로그나 새 UI 조합을 자동 진행하지 않는다. 현재 범위의 오류·실행 장애는 계속 해결한다.

## 7. 완료 조건과 검증

- [ ] 목표 영상과 카메라의 손이 함께 보이며 반전·비율·잘림을 확인했다.
- [ ] 최소 크기 미달 / 손 한 개 / 서로 다른 크기의 여러 손 / 후보 순서 변경 / 크기 동률 / 손 교차 / 선택 손 소실·재진입을 확인한다.
- [ ] 선택된 손만 관문·기록·점수에 들어가며 재선택 때 이전 손의 버퍼가 남지 않는다.
- [ ] 기존 점수 계산은 고정 입력에서 유지된다. 의도한 선택/재시작 변경과 산식 회귀를 구분한다.
- [ ] 실제 화면에서 문제 시작→수행→종료→결과 저장 경로를 확인했다.
- [ ] 실행 README와 사용자 5분 점검표가 있다.

선택/재선택의 상태 및 데이터 연결에는 집중적인 자동 검사를 사용하고, 기존 회귀를 재사용한다. 합성 손 검사는 실제 카메라 검증과 분리한다. 카메라 하드웨어가 없는 환경에서는 가능한 페이지/합성 검사를 완료한 뒤 **구현 완료·실제 카메라 확인 대기**로 표시한다. 실제 카메라 테스트나 사용성 효과를 수행했다고 꾸미지 않는다. 전체 연구 테스트를 불필요하게 반복하지 않는다.

## 8. 전달 형식과 하루 5~10분 운영

실행 폴더 README에 다음을 실제 확인한 값으로 기록한다.
- 복사한 prod 경로·버전, 개선본 진입 파일, 자산 의존성.
- Windows PowerShell 기준 실행 위치와 복사 가능한 시작 명령. 기존 실행기를 우선 재사용하고 필요하면 작은 실행 스크립트를 만든다.
- 실제 서버 포트와 기본 진입 URL 하나. 카메라 사용이 가능한 localhost 또는 필요한 보안 컨텍스트로 실행한다. file://로 여는 설명만 남기지 않는다.
- 종료 명령, 재실행 방법, 카메라 권한 및 자산 누락 해결 방법.
- 조절 가능한 최소 손 크기·안정화 시간·투명도와 임시 기본값.
- 확인한 것 / 실제 카메라 확인 대기 / 알려진 한계.

매 전달 보고는 다음 다섯 항목으로 짧게 작성한다.
1. 오늘 바뀐 것.
2. 실행 명령과 클릭할 URL.
3. 사용자가 5분 동안 확인할 행동 2~3개.
4. 자동/브라우저/실제 카메라 검증 결과와 남은 문제.
5. 피드백 이후 다음 수정 한 가지.

첫 사용자 점검은 "혼자 손을 넣어 따라 하기 → 다른 손을 함께 넣어 선택 확인 → 선택 손을 빼고 다시 넣어 재시작 확인"으로 한다. 사용자가 불편한 장면을 말하면 개발자가 재현·수정한다. 초기 값 결정이나 사소한 구현 선택마다 사용자에게 질문하지 않는다.

## 9. 이번 핵심 범위에서 보류하는 것

3D 신규 생성·손 방향 재렌더, 대량 영상 제작, 모호성 참가자 실험, 점수/임계값 최적화, 사람-AI 성능 비교, 공격/운영 보안 구축, 사업성, 광범위 runtime 검증은 이번 UI 전달의 선행 조건으로 삼지 않는다. 기존 재생 가능한 prod 자산으로 먼저 완성한다. 필요해지면 직접 실행을 막는 최소 수정만 하고 사유를 남긴다.

연구 로그·카메라 영상·개인 좌표는 공개 저장소에 추가하지 않는다. 공개 커밋은 코드·실행 안내·비식별 점검 결과만 포함한다. 사용자 피드백 로그는 간단히 유지하고 변경마다 문서를 다수 새로 만들지 않는다.

## 10. 새 Codex 세션에 붙여 넣을 지시문

mukgore/codex와 mukgore/handcaptcha의 work/todo-consolidation-20261103 브랜치를 기준으로 작업해.

현재 목표는 prod 복사본 하나에 목표 영상·카메라 중첩과, 일정 크기 이상인 가장 가까운 것으로 추정되는 손의 안정 선택을 구현하고 그 손 데이터로 실제 CAPTCHA를 끝까지 실행하게 하는 것이야.

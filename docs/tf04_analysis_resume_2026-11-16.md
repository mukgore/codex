# TF-04 보존된 분석 결과의 집계 재개 — 실행 전 보완 v2

v1은256개 고정JS점수·36개 정적raster계산과 저장을 끝냈으나, 계보 내부allocation의set형을JSON으로직렬화하는 마지막단계에서 `PROCESS_ERROR`가 됐다. 전후snapshot은일치했고5개출력은보존/검산된다. 원실행코드도당시manifest hash와정확히같은별도private사본으로보존했다. 실패를종료0으로소급하지않는다.

새v2는기존v1receipt와5개부분출력,원분석manifest의**모든입력 파일**이여전히같은크기/SHA256인지먼저검증한다.256개조건ID와18개후보×2시점의연결이현재기록과정확히일치해야한다. 불일치하면재사용하지않고오류로끝낸다. 점수·raster배열과그시점의측정시간을새출력으로복사하며새점수계산/새raster/SDK/인코딩은0이다.

파일그룹/실제decode/계보는기존영상과native를다시읽어검증한다. 원래제공packet을보존하고set을포함하는내부allocation표현만상세JSON에서제외한다. finding/요약은그대로남기며모든행은diagnostic·기존노출/같은보수적family다. 영상별48개시간표는원생성기록에서내보내며v2집계시간을영상생성시간으로쓰지않는다.

원사전등록/조건/기준을바꾸지않고별도config/immutable결과root/receipt로실행한다. 원입력과부분결과·실행기록/원코드사본·수정코드/전체worktree/환경을새snapshot에연결한다. 실행중편집/커밋하지않는다. 원v1의오류와새집계결과를구분해보고한다.

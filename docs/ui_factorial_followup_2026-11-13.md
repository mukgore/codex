# UI 후속 명세: 초기 노출과 모든 조합 비교 — 2026-11-13

사용자는 초기 약 0.5초 무가림 손을 보여 준 뒤 가림막으로 페이드하는 방안을 문서·코드에 추가하고, 각 UI 수정의 모든 조합을 비교하도록 요청했다. 이어 현재 작업 단위를 마친 뒤 명세 우선순위를 따르도록 지정했다. V05 시간 예산 보완은 `c3ccc8a`로 마무리·push했고 UI 작업을 별도 단위로 진행한다.

## 우선순위와 선행 조건

전체 기준은 [연구 실행 순서](research_goal_followups_2026-11-10.md#실행-순서와-기존-백로그-연결)다. 원본 확보 → 모호성 선별 → 3A 모방/정지 → 3B 채점 → 같은 정보의 사람/모델 비교 → 보안 → 사용성·공급 확대의 실제 실험 순서를 유지한다. 새 촬영·사람 입력이 없는 실험은 완료로 처리하지 않고 독립적인 준비를 진행한다. UI/시작 안내는 원문에 따라 2–3단계 실험을 방해하는 범위에서 먼저 정리할 수 있다. 3D 생성은 G0 우선과 권리·모델·평가 선행 조건을 유지한다.

UI 안에서는 [기존 A1/A2 → B1 → B2 → E1 → E2 묶음](hand_selection_and_overlay_ui_proposal_v0.1_2026-11-02.md#6-구현-작업으로-넘길-묶음)을 따른다. 기존 손 선택·유지 연결을 재사용하고, 중첩을 prod 기반으로 연결한 다음 안내와 초기 노출의 개별 동작 및 모든 결합을 검사한다. 실제 효과와 채택은 관찰 뒤 판단한다.

## 전체 조합 범위

손 선택 연결, 중첩, A 문구, B 비교 그림, C 가이드 손금, 초기 노출을 각각 켜기/끄기로 정의해 **2⁶=64조건**을 만든다. 기준 구성과 각 한 가지 변경을 먼저 확인하고 전체 조합을 검사한다. 기존 A/B/C가 상호 배타적인 세 대안이던 비교 범위를 사용자 요청에 따라 조합까지 확장한 것이다. 단일 수정 효과를 볼 때는 나머지 다섯 조건을 고정한다. 원래 62개 ID는 유지하며 U01–U06·NOW-03·B01/카드 B의 확장으로 추적한다.

초기 노출은 첫 목표의 같은 정지 프레임을 500ms 보여 준 뒤 500ms에 걸쳐 같은 프레임의 가림본으로 바꾼다. 가림이 서서히 나타나는 동안 원본과 가림본은 시간·구도가 대응해야 한다. 끈 조건도 1초 동안 가림본을 표시하고 관문·점수 기록을 기다린다. 이로써 준비 시간의 차이를 초기 힌트의 차이와 구별한다. 처음 0.5초의 움직이는 영상을 재생하는 별도 조건으로 해석하지 않는다. 손 추적은 중간에 멈추지 않는다.

코드는 [handcaptcha의 prod 기반 비교 폴더](https://github.com/mukgore/handcaptcha/tree/work/todo-consolidation-20261103/experiments/prod_ui_factorial)에 둔다. 기본 prod 파일을 교체하거나 공개 운영 배포하지 않는다. 실제 자료는 로컬 파일로 읽고 비공개로 유지한다. 코드/화면 검사, 합성 카메라 경로 검사, 실제 사람 효과를 구분해 기록한다.

## 실제 효과 실험

64조건을 모두 포함하는 배정표를 만들되 같은 사람에게 같은 원동작의 답을 여러 조건으로 반복 노출하지 않는다. 참가자·원동작 계열·기기·좌우손·연습·순서를 통제한다. 수집 전 표본·주 지표·분모·수용 기준을 잠근다. 첫 올바른 시도까지 시간·완료·선택 오류·추적 실패·도움·중단·선호를 기록하며 기술 오류를 동작 실패 점수에 합치지 않는다. 사람과 모델의 입력 비교에서는 초기 노출도 같은 정보로 제공한다.

현재 실제 촬영과 동의한 사람 응답은 없으므로 각 UI 효과·최적 조합·채택은 미확정이다. 64개 코드 조합이 통과해도 64개 사람 실험을 수행했다는 뜻은 아니다.

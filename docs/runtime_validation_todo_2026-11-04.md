# HaMeR·공격 실행시간 다조건 검증 TODO — 2026-11-04

## 1. 목적과 현재 근거

**목표:** 특정 Colab 실행 한 번의 기억에 기대지 않고, 어떤 입력·장비·처리 방식에서 공격이 얼마나 빨리, 어느 판정 단계까지 성공하는지 재검증할 수 있게 한다. 이번 변경은 실행할 일의 설계이며 벤치마크 구현·새 실험·유료 자원 사용·배포를 수행한 기록이 아니다.

과거 “HaMeR 약 10시간”은 정확한 시작·종료·하드웨어·처리 단계 로그가 확보되지 않은 실행시간 회고다. 모델 자체가 본질적으로 느리거나 CAPTCHA가 안전하다는 근거로 사용하지 않는다. Colab에서도 앞으로는 로그를 남길 수 있다. 기존 노트북 출력·저장 파일이 남아 있는지는 먼저 확인하되, 없는 세부 시간을 기억으로 복원하지 않는다.

기존 [실용성 검증 v0.3](practical_validation_requirements_v0.3.md)의 V4(사용자 시간)·V5(공격 비용)를 구체화한다. [G4 프로토콜](../g4_lab/protocol.md)의 fake-clock 관문 재생은 실제 경과시간·카메라·전체 브라우저 인증 측정으로 재해석하지 않는다. 현재 공개 저장소에 과거 HaMeR 실행 환경이 완전히 복원되어 있다고 가정하지 않는다.

## 2. 검증 질문과 서로 다른 측정 종점

| 질문/시험 | 시작 → 종료 | 함께 보고할 것 | 허용되는 해석 |
|---|---|---|---|
| 모델 계산량 | 준비된 입력 → GPU/CPU 계산 완료 | 모델·입력 크기, batch, 정밀도, 검출 실패 | 해당 조건의 추론 성능 |
| 오프라인 전체 처리 | 입력 파일 열기 → 결과·채점·로컬 저장 완료 | 디코딩·전처리·추론·후처리·채점·저장, 처리 프레임 수 | 해당 파일의 처리시간. 온라인 인증시간과 구별 |
| 관측에 따른 온라인 응답 | 프레임 도착 → 그 프레임에 근거한 응답 준비 | 첫 유효 응답 지연, 응답 시점 프레임 나이, 대기열·누락, 관문 | 미래 프레임을 보지 않은 조건의 지연 |
| 격리 환경의 전체 흐름 | 문제 제시 → 제출·서버 판정·보호 시험 동작 | 점수/개별 관문/전체 관문/서버 허용을 별도 기록 | 해당 신규 시험 흐름의 결과. 과거 운영 인증 입증 아님 |

- 환경 설치·다운로드·체크포인트 로드, 최초 응답, 반복 응답을 분리한다. 설치를 제외한 값에는 제외 범위를 적는다.
- 사전 계산·참조 라이브러리 구축 비용과 문제 1회당 조회·제출 비용을 분리한다. 여러 시도에 준비 비용을 나눌 경우 시도 수와 가정을 적는다.
- 현재 시스템의 실제 제한시간·관문 유지시간·재시도 규칙을 먼저 확인한다. 측정 결과에 맞춰 제한시간을 정하지 않는다. 제한시간이 확정되지 않은 경로는 지연만 보고한다.
- 과거 사람 12.7초는 segment.duration 합이다. 모델 파일 처리시간과 직접 나누어 사람 대비 속도·보안 우위를 계산하지 않는다. 향후 비교는 양쪽의 시작·종료·입력 노출·성공 정의를 맞춘 뒤 수행한다.

## 3. 조건표: 작은 기준 시험부터 단계적으로 확장

모든 조건의 전수 조합을 먼저 돌리지 않는다. 기준 조건을 고정하고 한 번에 한 요인을 바꾸며, 후보를 좁힌 뒤 필요한 상호작용만 확인한다. 아래 수량·예산은 파일럿 운영 초안이며 보안 임계값이나 통계적 충분성을 뜻하지 않는다.

| 축 | 기준 조건 | 비교 조건/확장 | 통제·주의사항 |
|---|---|---|---|
| 장비·환경 | 사용 가능한 로컬 CPU | Colab CPU, 실제 할당된 무료 Colab GPU | 실제 CPU/GPU·메모리·드라이버 기록. 특정 GPU 확보를 전제하지 않음 |
| 실행 상태 | 가중치 파일은 로컬, 새 프로세스·모델 로드부터 | 동일 프로세스의 warm 반복, 별도 설치/다운로드 포함 실행 | OS 파일 캐시까지 제거했다고 가정하지 않음. 각 cache 상태 명시 |
| 작업량 | 잠근 짧은 입력의 전 프레임, batch=1 | 같은 원본의 매 2/4번째 프레임, 지원되는 소규모 batch | 프레임별 지연과 batch 처리량 구별. 줄인 프레임 수·보간 비용 포함 |
| 화질·수치 | 현재 코드 기본 입력 크기·정밀도 | 지원되는 낮은 입력 해상도·FP16 등 | crop/resize 단계 명시. 미지원은 unavailable. 빨라져도 판정 성능 저하 보고 |
| 영상·난도 | 사용권·출처를 확인한 기존 서로 다른 동작 2개 | 가림 없음/기존 강한 가림, 원래 길이/짧은 구간, hard cut/fade | 실제 확보된 짝만 사용. 파생본은 같은 source family이며 독립 표본 아님 |
| 공격 경로 | 픽셀 → HaMeR → 좌표 → 기존 판정 | 단순 정지/보간, 알려진 풀 조회·저장 답 재생, 기존 G4 저비용 후보 | 공격별 볼 수 있는 정보와 사전 지식 명시. oracle/reference는 별도 표기 |
| 정보·스케줄 | 전체 파일을 가진 오프라인 처리 | 시간에 맞춰 전달되는 프레임만 처리하는 인과적 스트리밍 | 미래 프레임·전체 영상 식별·전체 구간 보간을 온라인 결과에 섞지 않음 |
| 판정·중단 | 진단용 전체 관문 평가 | 실제 규칙에 맞춘 실패 시 중단, 기한 초과·검출 실패 | stop_on_fail=false/true 별도. 조기 종료가 짧아진 것을 성공적 가속으로 세지 않음 |

다른 장비 사이에는 CPU·라이브러리·공유 자원까지 달라질 수 있다. 장비별 관측 비교로 보고하며 GPU 하나의 순수 효과로 단정하지 않는다. 동일 장비 내 비교는 같은 입력과 버전으로 짝을 맞추고 순서도 균형화한다.

### 최소 실행 순서 초안

1. **로그 시험:** 모델 없는 합성 입력으로 완료·오류·중단·내보내기·복구를 검증한다.
2. **짧은 파일럿:** 서로 다른 기존 원본 2개에서 각 32프레임을 고정해 CPU 기준 1회. 추론 구간은 회당 최대 5분 초안으로 제한한다. 설치/로드에도 별도 시간 상한을 정한다. 완주 못 해도 상한 도달과 마지막 완료 프레임을 남긴다.
3. **기준 측정:** 파일럿 비용을 보고 잠근 입력량에서 cold/warm 각각 5회 독립 실행을 목표로 한다. warm은 새 프로세스마다 별도의 고정 워밍업 5회를 수행한 뒤 측정한다. 5회 워밍업으로 안정되지 않으면 별도 파일럿에서 횟수를 확정하고 본 측정 중 변경하지 않는다.
4. **조건 비교:** 확보된 장비에서 프레임 샘플링·입력 크기·batch 등 한 요인씩 비교한다. 조건당 시간 상한과 전체 실행 예산을 파일럿 후 manifest에 잠근다. 무료 GPU 미할당은 성능 실패가 아니라 unavailable이다.
5. **과제 전체 검증:** 선택한 기준·빠른 후보를 전체 길이 및 확보된 조합으로 평가한다. 단축 파일럿을 전체 CAPTCHA 성공으로 세지 않는다. 기존 28조합 전체 처리는 비용 확인 후 별도 단계로 확장한다.
6. **온라인 검증:** 전체 프레임 접근을 막는 재생기에서 처리 지연·관문을 측정하고, 이후 신규 localhost 전체 흐름과 비교한다. 실제 카메라 시험은 별도 확장 과제로 남긴다.

5회의 반복은 실행 변동 관찰용 최소 목표이며, 독립 영상 수나 보안 성공률의 충분한 표본 수가 아니다. 자원이 부족하면 달성 횟수·중단 사유를 공개하고 수행한 범위만 분석한다. 신규 source family를 확보하기 전에는 알려진 풀의 개발 결과로 표시한다. 가림/전환/해상도 변형만으로 독립 holdout이 생기지 않는다.

## 4. 시간 계측 규칙

- 프로세스 내 경과시간은 Python `time.perf_counter_ns()`의 차이로 측정한다. 시계 구현·해상도를 환경에 남긴다. UTC는 실행 식별·보관용이며 서로 다른 장비의 원시 시각을 직접 빼지 않는다.
- GPU 작업은 비동기다. 전체 벽시계 측정은 시작 전 이전 작업과 종료 시 대상 작업의 완료를 동기화한다. GPU 내부 구간은 완료 대기한 CUDA event로 따로 측정한다. CPU 호출 반환만을 추론 완료로 기록하지 않는다.
- 단계마다 강제로 동기화한 진단 실행과 실제 파이프라인의 전체 실행을 구별한다. 겹치는 디코딩·전송·계산 시간을 더해 전체시간으로 만들지 않는다. 로그·저장의 포함 범위와 계측 오버헤드도 기록한다.
- 오프라인 처리량은 완료 프레임/전체 경과시간으로, 스트리밍 지연은 각 프레임 도착/배치 대기부터 응답 가능 시점까지로 정의한다. batch 처리시간을 batch 크기로 나눈 값은 개별 응답 지연이라고 부르지 않는다.
- 스트리밍은 원본 timestamp와 별개로 실제 전달 시각·응답 시각·queue 정책(drop/latest/FIFO)을 기록한다. 미래 프레임 접근과 전체 영상 lookahead를 차단하는 검사도 둔다.
- 브라우저/서버는 각자의 단조 시계로 구간을 측정한다. 전체 사용자 경과시간은 같은 클라이언트 시계의 문제 제시 → 서버 응답 수신으로 잡고, 서버 내부 시간은 따로 보고한다. 시계 간 정렬이 필요하면 오차도 보고한다.
- peak RAM/VRAM, CPU 시간, 입력/출력 바이트도 수집하되 지원되지 않는 항목은 null과 이유를 남긴다. 정밀한 전력·금전 비용으로 환산하지 않는다.

## 5. 재현에 필요한 기록과 Colab 중단 대응

### 실행 묶음의 필수 항목

| 파일(비공개 작업 영역) | 필수 내용 |
|---|---|
| config.json | run_id, 조건 ID, 공격 정보 범위, seed, 해상도/FPS/프레임 목록, batch/정밀도/스레드, warmup 횟수, cache·중단 정책, 시간·재시도 예산 |
| environment.json | 실제 장비/RAM/VRAM, OS/Python/PyTorch/CUDA/cuDNN, 드라이버·의존성 잠금, 코드 commit·dirty 여부/차이, 모델 버전 |
| manifest.json | 원본·파생본 계보와 split, 입력·모델 가중치·기준 좌표・채점 코드의 해시, 비공개 논리 ID, 실행 순서 |
| events.jsonl | 순차 추가하는 begin/end/heartbeat/checkpoint/error 이벤트, run_id/segment_id/event_id, 단계·프레임·관문, clock_domain, 단조 시각, 판정·오류 |
| summary.json | 계획/시도/완료 수, elapsed/CPU/메모리, 점수·관문·서버 종점, 상태와 제외 이유, 결측 수 |
| export_manifest.json | 내보낸 묶음의 파일 목록·체크섬, 보존 위치의 논리 ID, 복사 검증 결과·마지막 안전 checkpoint |

미리 정한 짧은 주기로 이벤트를 flush하고 clip/실행 경계에서 checkpoint를 남긴다. 처리 중단에도 begin은 있고 end가 없는 구간을 식별할 수 있게 한다. 실행 상태는 completed / failed / interrupted / timeout / unavailable / unknown으로 나누고 모델 검출 실패와 인프라 오류를 별도 필드로 기록한다.

**Colab VM 안에 파일을 쓰고 flush하는 것만으로 영구 보관이 되지는 않는다.** 다음 보관 절차를 구현·시험할 것:

- 짧은 파일럿에서 먼저 비공개 묶음 다운로드 또는 연구자가 선택한 비공개 보관 위치로 복사하고, VM 밖 사본의 체크섬을 확인한다.
- 장시간 실행 전에 clip/실행 경계 또는 고정 주기의 내보내기를 설정한다. 외부 보관 연결을 쓰면 인증과 접근 범위를 연구자가 확인하도록 한다. 코드가 임의로 계정을 연결하거나 공개 저장소에 원로그를 올리지 않게 한다.
- 복사 실패·마지막 안전 checkpoint 이후의 유실 범위를 표시한다. 갑작스러운 VM 삭제로 종료 이벤트가 없으면 다음 검산에서 불완전 상태로 분류하고 실제 종료시각을 추정해 채우지 않는다.
- 재시작은 새 segment_id와 새 시계 구간으로 기록한다. 복구한 처리량을 보고할 수는 있지만 여러 세션의 시간을 하나의 끊김 없는 온라인 지연으로 합치지 않는다.
- 노트북 셀 출력은 보조 자료로만 사용한다. 노트북 저장 여부와 실행 묶음 보존 여부를 별도로 확인한다.

개별 입력·영상·좌표·정답 풀·원로그·환경 전체 덤프·입력 해시·절대 경로는 기존 정책대로 Git에서 제외한다. 공개 결과는 허용된 집계, 공개 코드 버전, 익명 조건 ID, 비식별 장비·설정 정보로 제한하며 집계로 원자료가 노출되는지도 검토한다.

## 6. 비교·보고 규칙

- 조건별로 계획 수, 시도 수, 완료 수, timeout/중단/오류/미할당/로그 유실 수를 먼저 제시한다. 완료된 빠른 실행만 골라 평균 내지 않는다.
- 완료 실행의 median·IQR·범위와 n을 보고하고 성공 실행 시간도 별도 제시한다. 실패·기한 초과는 성공 처리시간에 합치거나 결측을 0초로 바꾸지 않는다. 완료시간 미관측인 경우 제한시간까지의 관측과 이유를 남긴다.
- 프레임 지연 p50/p95는 프레임 수와 실행별 분포를 함께 보고한다. 짧은 32프레임 파일럿에는 p95를 핵심 수치로 쓰지 않는다. 100개 이상 완료 프레임을 후속 기술적 보고 기준으로 삼되, 프레임 간 상관이 있으므로 독립 표본의 신뢰구간으로 해석하지 않는다.
- 환경·동작·가림별 결과를 유지한다. 5회 반복을 서로 다른 5개 문제로 세지 않고 source family와 실행 반복을 구분한다. 통계적 추론이 필요하면 source/실행 단위로 계획한다.
- 빠른 설정은 좌표/검출 품질, 점수 임계값 통과율, 전체 관문 통과율을 같은 입력에서 함께 비교한다. 단축 영상의 계산 검증과 전체 과제 성공 분모를 구별한다.
- 사전 준비 비용과 온라인 1회 비용을 모두 표시한다. 느린 HaMeR 하나로 전체 공격 비용 하한을 주장하지 않는다. 조회·재생 공격이 더 빠르면 그 결과를 보존한다.
- 허용 결론 예: “기록된 장비·설정·알려진 입력에서 전체 관문을 통과한 응답의 지연은 …였다.” 실제 전체 흐름을 시험하지 않았다면 인증 성공·실시간 방어 입증으로 확대하지 않는다.

## 7. 구현할 할 일과 완료 기준

아래 항목은 모두 **미실행 TODO**다. R0–R2로 최소 검증 기반을 만든 다음 실제 계산을 확장한다. 새 사람 실험·유료 GPU·운영 배포는 이 계획에 포함하지 않는다.

### P0 — 실행 근거와 기록 기반

- [ ] **R0. 과거 자료·실행 진입점 점검** — 남은 Colab 노트북/출력/체크포인트와 HaMeR 실행 스크립트를 비공개로 조사한다. 정확한 실행시간·장비가 없는 항목은 미확인으로 남긴다. **완료:** 복구 가능/불가 목록, 재실행 명령 초안, 필수 입력·모델 사용권·가중치 해시와 의존성 잠금. 복구한 실행은 “새 재현 실행”으로 표기.
- [ ] **R1. 기록기·스키마 구현** — `analysis/runtime_benchmark/`에 CPU/GPU 시계 어댑터, 환경 수집, JSONL 기록, 상태·checkpoint·내보내기 검증을 구현한다. **의존:** R0의 인터페이스 확인. **완료:** 모델 없이 완료/예외/강제 종료/로그 일부 손상/복구를 구별하고, VM 밖 보존 묶음 검산으로 summary를 재생성할 수 있음.
- [ ] **R2. 고정 입력·조건 manifest 작성** — `configs/runtime_benchmark/`에 공개 가능한 설정 템플릿만 두고 실제 입력·해시·경로는 ignored `data/work/runtime_benchmark/`에 둔다. **의존:** R0. **완료:** 두 동작·고정 32프레임·조건 ID·cache/warmup·예산·순서·공격 지식·종점이 잠기고 공개 파일에 원자료가 없음.

### P1 — 작은 측정부터 비교

- [ ] **R3. 짧은 CPU 파일럿과 Colab 보관 시험** — R1/R2를 이용해 최소 실행과 내보내기·중단 후 재개를 확인한다. 무료 GPU는 할당될 때만 smoke test한다. **완료:** 시도 전체 상태가 기록되고, 별도 세션에서 보존 묶음을 읽어 완료/중단/미할당을 재판정할 수 있음. 시간 상한에 걸려도 기록 시험과 성능 완주 여부를 분리.
- [ ] **R4. HaMeR 단계별 계측 연결** — 실제 decoder/검출기/전처리/추론/좌표 변환/채점/저장에 계측을 연결한다. **의존:** R0/R1. **완료:** 새 프로세스 cold와 고정 warmup 후 warm 값, GPU 완료 대기, 단계 진단/전체 처리 구분, 검출 실패 분모를 확인.
- [ ] **R5. 장비·처리 설정 비교** — R3/R4 후 파일럿 비용에 맞춰 잠근 동일 입력에서 확보 가능한 조건만 반복한다. **완료:** 장비별 기준 조건과 한 요인 비교표, 실제 반복 n·상한·불가 사유, 속도와 판정 품질이 함께 기록됨.
- [ ] **R6. 저비용 공격·전체 과제 비교** — 기존 `g4_lab` 조회/재생/단순 후보를 별도 어댑터로 비교하고 선택 후보를 원래 길이 과제로 확장한다. fake clock 결과는 경과시간으로 쓰지 않는다. **의존:** R3–R5. **완료:** 같은 정보 범위·과제·판정 규칙의 비교와, 사전 지식이 더 많은 reference 공격의 별도 표, setup/attempt 비용 구분.

### P2 — 온라인 의미와 재검증

- [ ] **R7. 인과적 스트리밍 재생기** — 도착하지 않은 프레임을 읽지 못하게 하고 지연·queue·drop·관문을 기록한다. **의존:** R4/R6. **완료:** 미래 프레임 접근을 탐지하는 합성 검사, batch 대기 포함 지연, 고정된 실제 규칙에 대한 기한 내 전체 관문 성공 여부.
- [ ] **R8. 신규 localhost 전체 흐름 연결** — 기존 G4 서버를 출발점으로 문제 제시/제출/서버 판정/일회 보호 시험 동작의 타이밍을 추가한다. **의존:** R7. **완료:** 점수·관문·서버 허용 각각의 결과와 클라이언트 전체시간을 기록. 실제 카메라/과거 시스템/운영 인증은 별도 미검증으로 표시.
- [ ] **R9. 독립 세션 재실행·집계 보고** — `tests/test_runtime_benchmark.py`에 상태/집계/시계·미래 프레임 차단의 합성 회귀 검사를 만들고, 별도 실행 세션에서 잠근 설정을 재현한다. CI는 모델 다운로드·GPU·비공개 입력 없이 실행한다. **의존:** R1 이후 각 단계에서 검사 추가, 최종 보고는 R5–R8. **완료:** 원로그에서 재계산한 summary 일치, 모든 제외·유실 건 검산, 공개 가능한 `reports/runtime_benchmark/` 집계와 방법·한계 보고서.

새 파일 경로는 구현 예정 위치이며 이번 커밋에 존재하는 실행 명령이 아니다. 외부 원자료가 없어도 합성 기록 시험을 진행할 수 있게 만들고, 모델·입력이 없으면 실제 HaMeR 성능은 INCONCLUSIVE로 남긴다.

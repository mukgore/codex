# handcaptcha 후속 구현 로드맵 — 2026-11-02

> 반영 상태: handcaptcha에 `ROADMAP.md`로 추가하려 했으나 현재 GitHub 연결에서 쓰기 요청이 403 `Resource not accessible by integration`로 거절되어 이 저장소에 보존한다. handcaptcha에는 반영되지 않았다. 접근 권한이 준비되면 이 본문을 반영하고 해당 저장소 README에 연결한다.

조영준 연구자가 희망한 후속 방향을 구현 저장소에 남긴다. **계획 문서이며 구현 완료나 새 실험·배포 승인을 뜻하지 않는다.** 연구 질문·실험 조건·완료 기준은 [codex 연구 로드맵](https://github.com/mukgore/codex/blob/main/docs/research_roadmap_2026-11-02.md)을 함께 읽는다.

## 지금 먼저 할 일

기존 연구·발표를 일차 마무리한다. 가림 생성, 손목 원점 이동과 크기 정규화, 선형 보간, 중간 자세 관문과 최종 점수의 관계를 설명할 수 있도록 정리한다. 기존 결과를 방어하기보다 검증된 결과와 한계를 구별한다.

현재 시제품을 실제 보안 제품으로 표현하지 않는다. codex에는 2026-10-28의 실제 함수·공개 영상·localhost 서버 탐색 및 국소 방어 결과가 있으므로 공격·방어가 전혀 시작되지 않았다고도 쓰지 않는다. 이 결과는 실제 신뢰 카메라, 새 사람·독립 원동작, 과거 운영 시스템 전체의 보안 입증과 구별한다.

## 구현 후보와 검증 조건

| 순서 | 하고 싶은 일 | 먼저 확인할 것 |
|---|---|---|
| P0 | 가림의 모호성·사람 수행 가능성을 시험할 조건과 기록 설계 | 같은 화면에 여러 답이 가능한지, 지각·운동·추적 오류를 어떻게 구별할지 |
| P1 | 기존 채점과 표준 DTW·시간 미분 등의 후보 비교 | 역사적 baseline 보존, 정상/오답 판별, source·사람 분리 및 평가 전 기준 잠금 |
| P1 | 서버 발급·검증·만료·일회성 제출과 보호 동작 연결 | codex 로컬 구현의 재사용 범위, 격리 환경과 종점별 로그 |
| P1 | OBS·리플레이·좌표 위조·통과 신호 위조에 대한 입력 경계 검증 | 카메라 이름만으로 차단을 보장하지 않음. 점수 통과와 보호 동작 허용을 구별 |
| P2 | 영상 풀 확장과 가림·출력 검사 | 사용권·동작 계보·중복, 모든 프레임 가림 및 누락 시 발급 중단 |
| P2 | 생체 제약을 갖춘 3D 손·물체 동작과 랜덤 문제 | 사람 이해·편안함, 복수 정답, 강한 3D 공격, CPU 비용 |
| P2 | 서버에서 문제·정답을 정하고 가린 화면만 전달 | 원본/정답/관절/seed의 클라이언트 노출 방지, 비저장 범위와 재현성 |
| P2 | 사전 생성·요청 시 생성·캐시·실시간 송출 비교 | 무료 환경의 생성 지연·송출 비용과 실제 보안 이득 |

3D 손·물체는 설계 후보다. 처음에는 실제 소품 없이 잡는 손모양을 따라 하는 G0를 검토하며, 영상 속 접촉이 사용자의 실제 접촉을 증명한다고 가정하지 않는다. 물체 단서는 AI에도 도움이 될 수 있다.

전체 화면 순간 가림, 여러 가림막과 시간 변화, 잡기/치기, 랜덤 과제·힌트도 후속 비교 후보로 남긴다. 전부 구현하도록 확정한 요구사항은 아니다.

## 연구·개발 순서

1. 기존 검증과 발표 정리, 남은 한계 및 질문 후보 비교.
2. 연구자가 주 질문과 최소 실험 카드를 선택·검토.
3. 승인된 범위의 분리된 실험 구현과 정상·공격 조건 비교.
4. 독립 사람/source 평가와 비용·접근성 확인.
5. 계속/수정/중단/자료 부족 판정 후 후속 단계 검토.

기존 보고서·원자료와 시제품 baseline을 보존한다. 새 기준을 test 결과에 맞춰 반복 조정한 값을 독립 성능으로 보고하지 않는다. 원자료·개인 좌표·비밀 정답·키를 공개 저장소에 추가하지 않는다. 후속 실험·새 보안 설계·외부 서비스 연결·공개 배포는 연구자 검토 후 진행한다. 이번 커밋은 문서만 추가한다.

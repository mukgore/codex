# G4 비-CUA 로컬 페이지 확인 범위 — 2026-10-26

## 확인한 항목

승인된 작업공간에 있는 두 후보 HTML의 정적 코드 경로를 읽기 전용으로 확인했다. 두 파일 모두 `navigator.mediaDevices.getUserMedia`로 브라우저 카메라 권한을 요청하고, 결과 저장 단계에서 설정된 업로드 주소로 `fetch` POST를 수행한다. 페이지 안에는 점수와 통과 상태를 계산하고 결과 이후 설문 페이지로 이동하는 클라이언트 흐름이 있다.

저장소의 기존 위협 모델은 웹 서버가 발급하는 인증 토큰, 보호 대상 API, 서버 측 판정의 실증 근거를 확인하지 못했다고 기록한다. 따라서 HTML의 클라이언트 점수 흐름만 자동화하거나 모의 입력하는 것은 실제 서비스의 end-to-end 인증을 입증하지 못한다.

## 수행하지 않은 것

외부 업로드 금지 조건을 지키기 위해 페이지의 결과 제출 동작을 실행하지 않았다. 새 서버·브라우저 하네스를 만들거나 원본 HTML을 수정하지 않았다. 브라우저의 카메라 입력을 자동화하거나 CAPTCHA를 통과시키는 동작도 수행하지 않았다. 이 기록은 코드 정적 확인이며 웹 시험 결과가 아니다.

## G4 판정에 미치는 영향

- **확인됨:** 현재 HTML 후보는 카메라 입력 및 결과 전송 경로를 포함한다.
- **확인됨:** 보존된 증거에서 실제 서버의 보호 동작까지 연결되는 L3 endpoint가 입증되지 않았다.
- **미확인:** 이 두 HTML 중 어느 파일이 실제 수집·운영 페이지였는지, 설정된 endpoint가 현재도 같은 용도로 동작하는지.
- **미완료:** 비-CUA 방법으로도 현재 근거만 가지고 실제 end-to-end 인증 평가를 완료할 수 없다. 로컬/오프라인 재생은 기존 점수·추출 계산 검증에 사용할 수 있지만 L3 결과로 부를 수 없다.

실제 L3를 검증하려면 소유자 승인된 테스트 인스턴스, 외부 전송 없는 테스트 endpoint 또는 격리된 staging, 성공/실패를 관찰할 보호 동작, 사전 고정한 challenge와 endpoint 정의가 필요하다. 기존 두 후보 HTML의 코드만으로는 그 증거가 제공되지 않는다.

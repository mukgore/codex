# G4 기존 원영상 추출 재생 확인 — 2026-10-26

## 범위와 방법

승인된 로컬 연구 자료에 이미 존재하는 CAPTCHA용 8개 level-3 소스 클립을 대상으로, 기존 `circle_edge_attack` 단계 1·2 추출 경로를 메모리 내에서 다시 실행하고 저장된 `attack_results.json` 및 기존 reference 결과와 대조했다. 새 입력 영상, 새 공격 조건, 새 데이터를 생성하지 않았고 원본 파일은 읽기만 했다.

대조 항목은 클립별 프레임 수, 추출 bit sequence, Hamming/majority 판정이다. 모든 8개 클립에서 저장 결과와 정확히 일치했다(8/8). 이 확인은 과거에 수행한 오프라인 재구성·score 계산의 픽셀 추출 계보를 보강한다.

## 해석

- **확인됨:** 기존 저장 결과가 현재 보존된 8개 소스 클립과 기존 추출 코드로 재생된다. 프레임 수·bit sequence·판정이 모두 일치했다.
- **확인됨:** 승인된 보조 폴더의 추가 영상 일부는 기존 CAPTCHA 영상과 바이트 단위로 중복됐다. 이 중복본은 독립 표본이나 holdout으로 셀 수 없다.
- **자료 부족:** 다른 별도 영상 집합은 파일 내용상 중복이 없더라도 challenge ID·reference pool·원본 gesture family와 연결하는 계보 증거가 확인되지 않았다. 따라서 독립 holdout으로 취급하지 않았다.
- **조건부 재현:** 이는 오프라인 기존 클립의 추출 재생이다. 독립 held-out 평가, 사람과 동일 challenge의 대응 비교, 라이브 웹 gate 또는 end-to-end 인증 성공을 입증하지 않는다. 기존 8개 원본 동작과 reference library의 중첩도 남는다.
- **미확인:** 과거에 실행된 정확한 HTML/build/browser 버전은 여전히 세션별 manifest가 없어 확정되지 않는다.

## 보존 및 개인정보

개인별 식별자, 원자료, 로컬 절대 경로, 입력 해시 및 프레임별 결과는 이 공개 보고서에 포함하지 않았다. 재생은 기존 로컬 코드와 승인된 입력으로 수행했으며, 독립 실행용 새 verifier나 공개 재현 패키지를 만들었다고 주장하지 않는다. 과거 보고서는 역사 기록으로 보존하며 이 후속 결과가 추출 재현 범위에 한해 보완한다.

## 다음 검증에 필요한 것

동일 challenge 기반의 held-out 성능을 주장하려면 원본 clip family와 challenge/reference label을 연결하는 비공개 manifest, 독립 held-out source, 그리고 평가 전에 고정한 프로토콜이 필요하다. 이 재생 결과만으로는 G4의 실증적 일반화 또는 실사용 인증 우회를 판정할 수 없다.

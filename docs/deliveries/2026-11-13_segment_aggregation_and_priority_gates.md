# 앞 단계 입력 확인과 S06 구간 집계 진단 — 2026-11-13

## 우선순위에 따라 확인한 것

UI 단위를 끝낸 뒤 [연구 실행 순서](../research_goal_followups_2026-11-10.md#실행-순서와-기존-백로그-연결)로 돌아가 필요한 실제 입력을 확인했다. 등록된 촬영 접수 21행 모두 원본 경로가 비어 있고 대기 상태다. 선별 응답 양식은 미기입, 독립 주석 양식 두 개의 채운 좌표는 0개다. 이 확인은 지정된 접수 자료의 현재 상태이며 전체 디스크에서 새 자료가 없음을 증명한 것이 아니다.

HaMeR/Text2HOI 사전 검사도 다시 실행했다. 등록한 모델 입력 루트의 지정 profile 배치에서 각각 3개·10개 항목이 부족해 추론 준비 상태가 아니었다. 별도 MANO intake가 있다는 사실과 완전한 모델이 설치됐다는 사실은 다르다. 가중치를 불러오거나 새로 다운로드하지 않았다. [입력 집계](../../reports/priority_input_gates_20261113.json)는 개인 식별자·경로·해시를 포함하지 않는다.

따라서 1–2단계 실제 수집과 3A 대응 모방/정지·4단계 사람/모델 평가를 완료로 넘기지 않았다. 그 대신 앞선 3B 명세 S06의 **전체 연결 점수 대 구간별 집계**는 현재 저장 좌표로 할 수 있어 실행했다. 이 진단은 기존에 수용된 연구 종료 결정을 다시 여는 작업이 아니다.

## S06 실제 실행과 결과

보존 18세션·126구간·8,782 저장 프레임에 현재 소유 prod의 실제 `computeScores` 함수를 호출했다. 새 `score_saved` bridge 분기는 저장 구간과 기준 keyframe을 그대로 받아 계산하며 페이지·카메라·업로드를 실행하지 않는다. 전체 점수가 저장값과 일치한 경우에만 구간별 비교를 계속했다. 최대 절대 차이는 `1.1102230246251565e-16`이었다. 현재 기준 좌표로 값이 재현된다는 **조건부 재현**이며 역사적 실행 build를 특정하지 않는다.

| 집계 방식 | 18세션 점수 평균 | 기존 0.25 미만 세션 수 |
|---|---:|---:|
| 기존 전체 연결 계산 | 0.663060 | 1 |
| 구간에 같은 비중을 준 평균 | 0.635315 | 0 |
| 저장 프레임 수로 가중한 구간 평균 | 0.666742 | 0 |
| 구간 점수 최솟값 | 0 | 18 |

새 집계의 0.25는 설명용으로 고정해 본 값이며 보정·채택한 기준이 아니다. 평균 점수가 올라갔다고 더 정확해진 것이 아니다. 프레임 가중은 시간 가중이나 독립 표본 가중도 아니다. 모든 구간과 기존 프레임 분모를 보존했다.

### 왜 모든 최솟값이 0인가

| 구간 종류 | 구간 수 | 기준 프레임 수 | 세 지표 모두 계산 불가 | 0점 |
|---|---:|---|---:|---:|
| 같은 영상 안 | 108 | 9–70 | 0 | 0 |
| 서로 다른 영상 사이 | 18 | 모두 2 | 18 | 18 |

영상 사이 전환은 앞 영상 끝과 다음 영상 처음의 두 기준 프레임만 가진다. 기존 세 지표는 이 길이에서 모두 `null`을 반환하고 점수 변환은 0으로 만든다. 완벽히 같은 좌표를 준 자체 합성 반례도 이 조건에서 0점임을 실제 HTML 함수로 확인했다. **이 18개의 0점을 사람의 동작 실패로 해석하면 안 된다.** 같은 영상 안의 계산 가능한 108구간 중 0.25 미만은 2개였지만, 이 두 구간도 실제 수행 영상·독립 정답 주석이 없어 사람 오류라고 확정할 수 없다.

전체 점수가 0.25 이상인데 낮은 구간 점수가 있는 세션은 17개다. 그러나 그 신호에는 위의 ‘기준 부족’이 포함된다. ‘짧은 오동작을 모두 놓쳤다’는 결론은 내리지 않는다. 최솟값을 새 통과 규칙으로 바로 사용하지 않고, 다른 영상 사이 전환의 기준·계산 불가 처리와 새 대응 자료를 먼저 정해야 한다. 기존 prod 산식·가중치·관문은 바꾸지 않았다.

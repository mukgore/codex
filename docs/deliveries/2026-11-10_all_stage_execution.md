# 현재 자료로 실행한 전 단계 작업 — 2026-11-10

사용자의 후속 지시에 따라 새 촬영·사람 응답이 필요한 실험은 입력 대기로 두고, 다른 단계에서 독립적으로 할 수 있는 분석·구현·검증을 계속했다. [원래 실행 순서](../research_goal_followups_2026-11-10.md#실행-순서와-기존-백로그-연결)의 실험 선행 조건을 충족했다고 간주하지 않는다. 실제 수집 대기와 다음 단계 준비를 구분한다.

## 설계·화면 기준 고정

사용자 지시: **UI 수정 단계 전까지 CAPTCHA 설계와 화면은 항상 handcaptcha의 prod 버전을 기반으로 한다.** 이번 기준은 별도 handcaptcha checkout의 `hand_captcha_prod.html`이며 코드 SHA256은 `0d82dd439fe7976f8b860eb82e654e6f5637b2d7a3fcce2d02f2f99e5f5bea11`이다. 파일 해시는 현재 checkout의 실제 바이트 기준이며 줄바꿈 정규화 해시와 구분한다.

이번에 prod HTML·CSS·화면 흐름은 수정하지 않았다. 기존 실험 UI의 회귀 통과를 그 UI의 채택으로 해석하지 않는다. 로컬 G4 페이지는 저장 좌표를 시험하는 도구이며 CAPTCHA 사용자 화면의 설계 기준이 아니다. 새 촬영 자료를 기존 공개 pool URL에 올리거나 현재 prod의 업로드 설정에 넣지 않는다.

## ‘실제 촬영본’의 뜻과 현재 보유 자료

실제 촬영본은 **가림 원을 넣기 전에 카메라로 직접 녹화한 원래 손동작 영상 파일**이다. 예를 들어 스마트폰으로 손바닥을 찍으며 ‘펴기→검지 굽히기→펴기’를 수행한 원본 MP4/MOV가 해당한다. 편집·미러·필터·앱 오버레이가 없는 원파일과 실제 FPS/PTS를 보존한다.

[촬영 목록](2026-11-10_stimulus_intake_and_capture_list.md)의 A01–A06은 18파일이며, [접촉/비접촉 대안 A07](2026-11-10_rights_capture_screening_protocol.md)을 포함하면 21파일이다. 각 파일 8초는 촬영 안내 기준이다. 원본 하나가 여러 가림색·크기·역재생으로 파생되어도 촬영 수는 늘지 않는다.

현재 무가림 실촬영 원본은 **기존 1개**가 있다. 새 A 촬영본은 아직 없다. 사용자에게 확인한 기존 본인 영상의 연구 사용·비공개 영구 보관 방침은 [권리 대장 기록](2026-11-10_rights_capture_screening_protocol.md)을 따른다. 이 원본으로 가능한 개발 비교는 이번에 실제 실행했다.

## 3A·3B — 정지 진단 회귀와 채점 검산

기존 공개 8문제의 좌표 공격 136건을 다시 실행했다. 11개 조건별 시도 수·점수/관문/검증/로컬 보호행위 통과 수·평균 점수가 기존 보고서와 모두 같았다. 실행 시간은 비교에서 제외했다. 독립 Python 계산에서도 점수·점수 통과·관문 통과 불일치는 **각 0/136**, 점수 최대 절대 차이는 `2.22e-16`이었다.

첫/중간/끝 자세를 반복한 좌표는 점수 기준 **24/24**, 오프라인 자세 관문까지 **16/24**가 통과했다. 다른 공개 동작을 넣은 경우 점수 **56/56**, 관문 **37/56** 통과였다. 이는 알려진 원동작의 합성 좌표 대조이며 실제 손·사진·정상 모방을 같은 사람으로 촬영한 비교가 아니다. 현재 자료만으로 새 임계값을 보정하거나 채택하지 않았다.

### prod 채점을 실제 숫자로 검산한 예

아래는 무가림 원본의 새 MediaPipe 추정치를 현재 prod의 순수 함수로 평가한 오프라인 예다. 원본 타임라인→좌표→손목/크기 정규화→특징→부분 점수→가중합을 따른다. 구현상 관문은 38도/200ms, 최종 점수 기준은 0.25를 유지한다.

| 값 | 입력/출력·단위와 계산 |
|---|---|
| 영상 입력 | 720×720, 24fps, 실제 113프레임. 검출 113/113 |
| 좌표·정규화 | 이미지 x/y를 정규화하고 손목을 뺀 뒤 손목–중지 MCP 길이로 나눔. 깊이의 측정 정답 아님 |
| legacy angle | 원오차 0.065834도, 최대값 46.9413도 → 부분 점수 0.9985975 |
| legacy `dtw_angle` | 원오차 5.628667도, 최대값 44.0014도 → 부분 점수 0.8720798. 이름과 달리 현재 `mDA`는 sliding-window 비교 |
| legacy accel | 재표본화된 좌표의 프레임 간 2차 차분 오차 0.00109715, 최대값 0.1926 → 부분 점수 0.9943035. 물리 단위의 초당 가속도가 아님 |
| 감지율 감점 | 부분 점수마다 감지율을 곱하고 [0,1]로 제한. 이 예는 1 |
| 최종 점수 | `0.25×0.9985975 + 0.38×0.8720798 + 0.37×0.9943035 = 0.9489320` |
| 후보 특징 | 전체 시퀀스 각도 MAE 0.053181도, 제한 DTW 경로 RMSE 0.108936도, 실제 초 기반 가속도 오차 0.235976 hand-length/s². 후보 점수·채택 임계값은 미설정 |

이 lab은 3개 구간의 양끝 경계 프레임을 공유하므로 **legacy 내부 채점 분모는 115**다. 실제 디코딩 113프레임과 섞지 않는다. 검정 원은 실제 53/113 검출이지만 내부 score 감지율은 54/115, 피부색 원은 실제 87/113이지만 내부 감지율은 88/115다. 새 후보의 초 기반 특징과 legacy의 프레임 차분을 같은 단위로 비교하지 않는다. 구간 분할·재표본화가 다르므로 두 각도 숫자가 다른 것도 오류라고 단정하지 않는다.

## 4단계 — 같은 영상에서 가림색 비교 실제 실행

[실행 코드](../../analysis/color_controls.py)로 무가림/검정 원/고정 피부색 원을 각각 3회 추출했다. 동일 원본·프레임·중심·반경·불투명도·인코딩이고, 매 배치마다 새 MediaPipe 상태를 사용했다. 조건 순서는 회차별로 회전했다. **9배치·1,017프레임 처리 완료, 실패 0**이다.

환경은 MediaPipe 0.10.14, OpenCV 4.10.0, NumPy 1.26.4, protobuf 4.25.3이다. video mode, 최대 한 손, 모델 복잡도 기본값 1, detection/tracking confidence 0.5를 사용했다. 실제 코드/config 해시는 사후 스냅샷으로 비공개 보존했다. 관측 전에 잠근 preregistration으로 표시하지 않았다.

| 조건 | 검출 프레임(각 반복) | 기존 점수(각 반복) | 오프라인 관문 | 배치 시간 중앙값·범위 |
|---|---:|---:|---|---|
| 무가림 | 113/113 | 0.948932 | 통과 | 3.211초 · 3.078–3.362초 |
| 검정 원 | 53/113 | 0.283350 | 실패 | 3.474초 · 3.145–3.963초 |
| 피부색 원 | 87/113 | 0.574979 | 통과 | 3.208초 · 3.088–3.545초 |

3회에서 각 조건의 검출 수·점수·관문 결과는 같았다. 세 점수 모두 0.25를 넘었으나 검정 원의 관문은 실패했다. 이것은 점수 수용과 관문 수용을 분리해야 하는 실제 개발 사례다. 영상 재생 스케줄을 생략한 오프라인 관문이며 최종 인증 결과는 아니다.

### 좌표 비교의 분모와 한계

아래 거리는 보존된 **MediaPipe 추정 좌표와의 불일치**다. 독립 주석에 대한 정확도가 아니다. 가림 안/밖 구분도 보존 추정 좌표를 원과 대조한 것이다. 무가림 행의 안/밖은 ‘동일한 원을 놓았을 때의 영역’이며 실제 가렸다는 뜻이 아니다.

| 조건 | 원 밖 비교점 / 기준점 | 원 밖 평균 거리 | 원 안 비교점 / 기준점 | 원 안 평균 거리 |
|---|---:|---:|---:|---:|
| 무가림 | 1,253/1,253 | 0.163px | 1,120/1,120 | 0.153px |
| 검정 원 | 752/1,253 | 23.946px | 361/1,120 | 37.672px |
| 피부색 원 | 1,199/1,253 | 16.872px | 628/1,120 | 35.154px |

검출된 점에서만 평균 거리를 계산하고 누락을 0오차로 채우지 않았다. 두 색의 검출 프레임 집합이 다르므로 평균 거리 차이만으로 피부색이 더 정확하다고 결론 내릴 수 없다. 한 원본·한 피부색·한 tracker의 반복이며 독립 원동작 9개가 아니다. 시간도 resource worker·import·디코딩·추적을 포함한 로컬 배치 경과 시간으로, per-frame latency·응답시간·GPU 비교·실시간 인증 속도가 아니다.

### 독립 주석·HaMeR 준비

[주석 준비 코드](../../analysis/prepare_annotation.py)로 원본의 고정 5프레임(0/28/56/84/112) PNG와 평가자 2명의 빈 21점 주석 양식을 만들었다. 모델 좌표를 양식에 넣지 않았고 실제 인간 주석은 **0점**이다. 확인 불가 좌표는 비워 두며 2D 주석으로 깊이를 판정하지 않는 지침을 포함했다.

HaMeR core 사전 검사는 지정 checkpoint 디렉터리에 필요한 설치 구조의 MANO_RIGHT, hamer.ckpt, model_config가 없다는 결과였다. 별도 MANO 좌·우 모델 파일은 기존 private intake에 있지만 이것이 HaMeR checkpoint 확보를 뜻하지 않는다. 확인한 기존 torch 환경은 `2.5.1+cpu`, `cuda_available=False`다. 이 환경 검사로 PC 전체의 GPU 유무를 단정하지 않았다. 새 모델 다운로드·약관 동의·GPU 구매 없이 진행했으며 HaMeR 실행은 보류다.

## 5단계 — 로컬 자원 제한 구현과 보호 경계 검증

[G4 서버](../../g4_lab/server.py)에 실제로 다음 제한을 추가했다. 기존 prod와 SQLite 비공개 송출 core는 수정하지 않았다.

- 세션 기본 수명 300초. 문제·허가의 만료는 세션 만료를 넘지 못한다.
- 요청 처리 시 만료 세션·문제·허가를 정리한다. 유휴 상태에서 timer가 돌지는 않지만 보관량은 상한 이내다.
- 기본 보관 상한은 세션 1,024개 / 문제 4,096개 / 허가 4,096개 / 이벤트 10,000개다. 상한에 도달하면 상태를 더 만들지 않고 HTTP 429로 거부한다.
- 이벤트 앞부분을 지워도 event index는 단조 증가한다. 오래된 이벤트가 없어진다는 점을 유지하며 전수 감사 저장소로 사용하지 않는다.
- 수명·상한 설정의 비유한 값·bool·0·과대 입력을 거부한다. 기존 score/gate/정지 필터 기본값은 바꾸지 않았다.

신규 상태·동시 발급·만료·HTTP 429 검사 **7개**, 실제 prod 함수 기반 G4 통합 **9개**, 기존 비공개 SQLite 송출 **9개**가 통과했다. 보강 뒤 136건 회귀와 독립 검산도 통과했다.

자원 제한은 입력 출처 보호나 CAPTCHA 성능 개선이 아니다. 알려진 정답 재생이 여전히 통과하며, caller별 rate limit·소켓/CPU 부하 통제·운영 인증 gateway·내구성 있는 분산 상태·서버 배포·신뢰 카메라는 남아 있다. 기존 prod 정적 페이지는 공개 pool/정답 좌표를 fetch하고 클라이언트에서 판정한다. 현재 `UPLOAD_URL`은 빈 문자열이므로 설정된 결과 업로드는 없지만, CDN과 공개 영상 요청은 있다. 이 페이지에 비공개 연구 원본·답을 넣어 배포하지 않는다. 과거 공개본 삭제나 이력 변경은 수행하지 않았다.

## 6단계 — prod 사용성 회귀와 공급 비용의 현재 기준선

손 선택·시작/중단·늦은 callback·전체 재시작·원본 카메라 검출·로컬 이벤트 내보내기 관련 Node 검사 **29개**가 통과했다. 이 중 실험 안내/선택 버전의 검사는 기존 구현 회귀이며 prod UI를 그 버전으로 바꾼 것이 아니다. 실제 사용자 완료율·피로·접근성 효과는 사람 입력이 없어 측정하지 않았다.

UI를 바꾸지 않고 준비할 관찰 항목은 prod 시작 시 카메라/목표 표시, 첫 자세 안내 이해, 동작 시작 시점, 관문 대기, 추적 소실, 다시 시작, 도움 요청·중단이다. 고정 카메라 실험과 스마트폰 사용성은 별도 조건으로 둔다. 카메라를 못 쓰는 경우의 손 모형/점 찍기와 비시각적 대체 경로는 이후 UI 단계의 비교 후보다. 현재 화면에 새 입력 방식을 삽입하지 않았다.

| 실제 저장물 | 현재 한 영상의 저장 크기 |
|---|---:|
| 무가림 FFV1 | 11,551,202 bytes |
| 검정 원 FFV1 | 8,063,468 bytes |
| 피부색 원 FFV1 | 7,893,714 bytes |
| 세 조건 합 | 27,508,384 bytes ≈ 26.234MiB |

이는 113프레임짜리 **lossless 연구 중간물** 크기다. 운영 MP4의 전송량이나 다른 길이/조명/동작의 압축률을 추정한 값이 아니다. 21파일×8초=168초는 촬영 지시상 순수 녹화 길이일 뿐, 실제 촬영·재촬영·검수 노동시간은 미측정이다. 저장 공간·파생 인코딩/검수 시간·발급당 바이트·촬영/3D 제작시간·사람 이해도·반복 노출 위험을 동일 원동작 단위로 기록할 비용 항목으로 남겼다. 외부 가격이나 구매비를 임의로 넣지 않았다.

현재 자체 골격/MANO fixture의 기존 결과만으로 실촬영 공급을 대체하지 않는다. 사람 수행·접촉/비관통·최종 가림 검사를 통과한 독립 source가 있어야 촬영 풀과 3D 비용·품질의 비교가 가능하다. 대규모 생성·운영 최적화·고객 연락은 그 입력이 없다.

## 근거·재실행

식별자·원본/좌표/입력 해시를 제외한 [집계 JSON](../../reports/research_followups_20261110.json)을 만들었다. 상세 원자료와 실패·재시도 기록은 저장소 밖 private 경로에 남겼다. 초기 색 비교는 OpenCV 배포 이름 조회에서 실패해 최종 집계가 없었으며, 런타임 버전 조회와 배치별 결과 저장을 고친 `color_controls_20261110_v2`의 완결된 실행만 결과에 사용했다.

```powershell
python -m analysis.session_boundaries --raw-root ../../hand-captcha-research/data/raw --output ../private_artifacts/session_boundaries_NEW
python -m analysis.color_controls --source-root ../handcaptcha --archive '../handcaptcha/left_1_experiment (2).zip' --pair-root ../private_artifacts/stimulus_pair_final_20261110 --output ../private_artifacts/color_controls_NEW --repetitions 3
python -m analysis.prepare_annotation --pair-root ../private_artifacts/stimulus_pair_final_20261110 --output ../private_artifacts/annotation_NEW
python -m g4_lab.run --source-root ../handcaptcha --run-id G4-NEW --run-dir ../private_artifacts/g4_NEW --summary ../private_artifacts/g4_NEW_summary.json
python -m g4_lab.independent_check --source-root ../handcaptcha --run-dir ../private_artifacts/g4_NEW
```

서로 다른 실제 환경에서 baseline Python 74개, 신규 검사 12개(자원 7·경계 3·분모 2), G4 실제 통합 9개, 비공개 송출 9개, JS 29개가 통과했다. 같은 명령으로 한 번에 실행한 단일 suite 수나 사람 표본 수로 합치지 않는다.

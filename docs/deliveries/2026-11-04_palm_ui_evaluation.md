# 손바닥 안내 12개 아이디어의 사전 평가와 3개 구현

**사용자 요구 반영 수정:** 아래는 앞선 독립 hand_selection 시연 기준의 평가다. 사용자는 기존 prod UI를 기반으로 한 수정안을 원했다. 이에 [기존 prod 기반 A/B/C와 12개 재평가](2026-11-04_prod_palm_variants.md)를 추가했으며, 이번 수정안의 선택은 01 문구/A, 02 비교 그림/B, 07 기존 가이드 내부 표시/C다. 아래 03 별도 준비 단계는 prod 수정안에서 제외했다.

사용자 요청에 따라 12개 후보를 평가하고 세 개를 독립 시연에 구현했다. 아래 점수는 코드/명세를 검토한 설계 판단이다. 실제 사람 대상 사용성 시험이나 자동 손바닥 판정 성능이 아니다.

## 평가 기준과 선택

각 열은 1~5점이며 높을수록 좋다. 의미는 방향을 바로 이해할 가능성, 기존 과제와의 호환성(정답 단서 추가/검출 혼합 없음), 낮은 사용 부담, 현재 환경에서의 구현·검증 가능성이다. 총점은 네 열의 단순 합이다. 세 주 기능의 역할이 겹치지 않는지도 함께 판단했다.

## 실제 동작

1. 가림 완료 영상 선택 → 카메라로 손바닥 준비 → 움직임 시작의 순서를 화면에 제시한다.
2. “손금이 보이는 쪽을 카메라 렌즈로 향해 주세요”와 손금/손톱 비교 그림을 보여 준다. 왼손/오른손 선택은 안내 그림을 뒤집는 조작이며 실제 손 소유자/면 판정이 아니다.
3. 준비 단계는 원본 카메라로만 손을 검출하고 선택 손 테두리를 보여 준다. 문제 영상은 재생·중첩하지 않는다.
4. 큰 유효 손이 안정적으로 선택되고 사용자가 손금 쪽을 렌즈로 보였다고 직접 확인해야 “움직임 시작”을 누를 수 있다. 자가 확인만으로 손바닥 자동 판정/인증을 주장하지 않는다.
5. 손 소실은 시연을 중단한다. 다시 준비는 새 trial 번호로 시작하고 손 선택/확인/재생을 초기화한다. 이전·새 손의 수행을 이어 붙이지 않는다.
6. 기기 내 메모리에는 최대 1,000개 허용 이벤트와 상대시간만 저장한다. 버튼을 누를 때만 JSON을 내려받는다. 파일명·영상·좌표·참가자 ID·임의 오류 메시지는 기록 API가 거부한다. 페이지를 닫으면 저장하지 않은 기록은 사라진다.

구현 위치: handcaptcha의 `experiments/hand_selection/index.html`, `demo.js`, `session_log.js`. 기존 prod HTML의 관문·채점·제한시간에는 아직 연결하지 않았다.

## 검사와 한계

Node 검사에서 준비 중 문제 재생 금지, 원본 카메라 검출, 안정 선택+명시 확인 전 시작 금지, 시작 후 중첩, 소실 중단·재시작, 모델 초기화/카메라 획득 중 취소, 로컬 기록 허용 필드·분모/시도 구분을 확인한다.

Computer Use는 `failed to write kernel assets ... os error 3`로 초기화되지 않았다. 기존 Chrome을 별도 headless 프로필로 사용해 1280px·390px의 실제 CSS 배치를 캡처·검토했다. 가로 넘침, 두 비교 그림, 기본 시작 잠금, 좌우손 그림 전환을 확인했다. 실제 카메라 권한·사람의 손·휴대전화 실기·인지 효과 시험은 수행하지 않았다. 모델 다운로드 경로는 유지하지만 정적 화면 QA 중 외부 호스트를 차단했다.

다음 사람 비교는 같은 선택 정책·문제·채점 아래 안내 조건만 바꾼다. 첫 손 면 오류는 관찰 기준으로 별도 주석하고, 올바른 손바닥 제시까지 시간·도움/재시도·포기·전체 시간·불편감을 기록한다. bbox·점수·자가 확인을 손 면의 정답으로 사용하지 않는다. 현재 UI를 좋은 후보로 고른 판단과 실제 개선 효과의 검증은 구분한다.

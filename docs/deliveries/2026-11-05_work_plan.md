## 수행 기록

- 실행 감독기: shell 없이 신뢰하는 로컬 명령을 별도 bootstrap에서 실행한다. Windows Job Object의 kill-on-close를 명령 시작 전에 연결하고, POSIX에서는 process group을 사용한다. 부모가 containment를 설정하지 못하면 명령을 실행하지 않는다.
- 종료 코드와 worker journal 상태를 별도로 저장한다. 강제 종료 후 worker 기록은 INTERRUPTED로 남기고 감독기만 TIMED_OUT을 기록한다. stdout/stderr는 수집하지 않는다. command/cwd/결과는 저장소 밖 private 경로에만 저장한다.
- 검사: 성공/기록 누락, 응답 없는 작업+자식 종료, 정상 leader 뒤 자식 정리, 비정상 종료/덮어쓰기 거부, 부분 journal 보존, 잘못된 timeout 거부의 6개 통과. 실제 GPU/HaMeR·악성 프로세스 격리·VM 재시작 검증은 아니다.

## 추가 실행 결과

- `analysis/runtime_benchmark/extraction_worker.py`가 별도 handcaptcha checkout의 실제 Stage1을 사용한다. 입력/adapter hash·계획 frame·단조 decoder 시각을 확인하고 원좌표를 새로 보존하지 않는다. 전체 영상을 미리 보는 batch 실행이며 frame event는 추출 후 기록한다. 온라인/프레임별 지연/HaMeR/공격 시간으로 읽지 않는다.
- 기존 환경113/113 frame 처리·검출, 감독기4.603초(기록기4.137초). 2초 제한 재실행은 감독기TIMED_OUT/worker INTERRUPTED·불완료로 남았다. Windows job 종료 code가0이어도 감독기/worker 상태를 우선한다. 같은 worker의 잘못된 입력/미설치 dependency 검사2개도 통과했다.
- 새 격리 환경: MediaPipe0.10.14/NumPy1.26.4/protobuf4.25.3/OpenCV-contrib4.10.0.84. 실제113/113 추출, 감독기4.813초/기록기4.375초. cache 통제·반복·동등한 환경 비교가 없으므로 기존 환경보다 빠르거나 느리다고 결론내리지 않는다.
- 26개 binary wheel/230783583byte를 승인 후 내려받아 해시 lock을 만들었다. 별도 두 번째 env를 같은 wheelhouse에서 네트워크 없이 재설치했고 pip check/import와 pipeline108검사가 통과했다. 이후 packet duration 거부 검사1개가 추가됐으므로 최종 회귀는109개를 기준으로 한다. 기존 interpreter/venv/PATH 변경 없음.
- 자체 `middle_touch_sphere`: seed7/24frame/12fps/w3=2.5, 가림 gate24/24, 접촉frame11·12, 관통frame0. capsule20개 대 static sphere proxy이며 palm mesh·자체 충돌·접촉 역학·인체 실측·사람 수행성은 남는다. RESEARCH_FIXTURE_ONLY/release_allowed=false. PNG를 한글 경로에 저장하지 못하던 imwrite 문제도 imencode+명시적 파일 쓰기로 수정했다.
- PrivateDelivery는 공개 PASS endpoint 없이 신뢰 gateway/evaluator용 API와 GET/HEAD만 제공한다. registry/세션/조직/만료/동일 bytes/철회 재검사, no-store, Range/416, 일회 operation을 처리한다. 동시4소비 중1개만 성공하고 여러 grant의 동일 operation 중복도 거부했다. 실제 prod의 video 인증 전달·IdP/TLS·실제 승인·외부 부수효과 outbox는 미완료다.
- cluster bootstrap은 알려진 참가자·촬영·구성 원본 계보의 연결 성분으로 묶고 기술실패/중단을 분모에 보존한다. 한 cluster/퇴화 resampling은 신뢰구간을 만들지 않는다. test로 threshold를 다시 선택하지 않는다. 실제 데이터 결과를 만들어 내지 않았다.
- JS raw 특징은 좌표/시간/미러/block, 15각도·DTW tie path·실제 시간 가속도까지 Python과 합성 parity를 확인했다. score=null이며 운영 점수나 채택 후보의 실제 JS shadow 검증은 아니다.
- 실제 FFmpeg/ffprobe 합성6조건: MPEG4 CFR, 분수30000/1001 H264, B-frame H264는 통과. audio 추가, 미검토 metadata, VFR gap은 거부. packet duration의 양수 여부만 보던 검사를 명시 CFR와의 일치까지 강화했다. 모든 조건이 사전 기대와 일치했다.

## 아직 필요한 입력과 완료 조건

1. MANO·Text2HOI/HaMeR: 본인 계정/허용 범위 확인 후 모델·가중치·필요 dataset/object 자료. 사용자가 직접 접근 가능/안내 필요라고 회신해 [공식 접근 절차](2026-11-05_model_access_steps.md)를 안내했다. 현재 MANO ZIP의 다운로드/경로 회신 대기다. 편입 도구/추가 검사4개를 준비했다. 계정 생성·약관 동의·연락을 대행하지 않았다.
2. 실제 평가: 대응 정상/공격 trial, participant/capture/source family 계보, 사전 split/채택 기준. 새 연구자 판단 없이 공학용 fixture나1회 UI 확인을 사람 성능 자료로 대체하지 않는다.
3. 운영: 서비스 환경·조직 인증 주체·신뢰 검토자와 권리/인체/보안 승인 보고서. 합성 PASS는 임시 test에만 존재한다. 실제 자산 등록부를 허위로 승격하지 않는다.
4. 전체 감사: hidden/deleted/dangling ref와 과거 media/동의·원자료 계보의 의미 검토 범위를 확정해야 한다. 새 lock은 현재 한 플랫폼 환경의 복원이며 과거 연구 build를 증명하지 않는다.

위 실제 연구·운영 요구가 남아 있는 동안 전체 완료로 표시하지 않는다. 구현 가능한 기반을 완료했다는 것과 실제 실험을 완료했다는 것을 분리해 기록한다.

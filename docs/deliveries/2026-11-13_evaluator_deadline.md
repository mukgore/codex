# V05 채점 대기·입출력 예산 보강 — 2026-11-13

## 문제와 수정

기존 `ActualEvaluator.call`은 요청을 Node 프로그램으로 모두 전송한 뒤 응답을 기다리는 시간만 15초로 제한했다. 잠금 대기와 stdin 쓰기는 이 제한 밖이었다. 실제 사람 실험에서 멈춤을 관찰한 결과가 아니라 코드 점검으로 발견하고 고의로 멈춘 로컬 자식 프로세스로 재현한 결함이다.

호출 시작 때 정한 하나의 시간 예산에서 잠금 대기·직렬화 경과·파이프 쓰기·응답 대기를 차감한다. 잠금 대기만 초과한 호출은 다른 호출을 처리하는 프로세스를 종료하지 않는다. 요청 전송이나 응답이 멈추면 자식 프로세스를 종료하고 해당 스트림을 재사용하지 않는다. 뒤늦은 응답을 다음 시행의 결과로 받지 않는다. 종료 시에도 먼저 자식 프로세스를 종료한 뒤 stdin을 닫아, 막힌 쓰기 때문에 close가 대기하는 경우를 피한다.

서비스 상태 잠금도 기본 1초만 기다린다. 포화는 기존과 같이 HTTP 429, 채점 시간 초과·프로세스 불가용은 내용이 고정된 HTTP 503으로 응답한다. 시도는 이미 소비된 상태로 유지하고 통과 권한을 만들지 않는다. 기술 오류를 낮은 모방 점수로 기록하지 않는다. 계산 결과가 돌아왔어도 문제의 수명이 끝났다면 권한을 발급하지 않는다.

CLI는 `--state-wait-timeout`(기본 1초, 최대 20초)과 `--evaluator-timeout`(기본 15초, 최대 60초)을 제공한다. 기존 연결 수/연결 수명 제한과 함께 적용한다. Python 직렬화·JSON 파싱은 같은 예산에서 경과 시간을 차감하지만 실행 중 강제 중단하지 않는다. 기본 HTTP 입력 크기와 프레임 상한을 유지한다. 프로세스 종료 대기와 쓰기 스레드 정리는 각각 최대 1초의 추가 정리 시간을 가진다. OS가 종료를 거부하는 상황까지 실시간 상한을 보장한 것은 아니다. 실패 프로세스는 새 evaluator 인스턴스로 명시적으로 재시작해야 한다.

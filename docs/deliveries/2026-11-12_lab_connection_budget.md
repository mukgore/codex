# V05 로컬 연결 예산 — 2026-11-12

## 완료한 일

격리 G4 실험 서버에 연결 처리 슬롯을 기본 16개로 제한했다. 슬롯이 찼을 때 새 요청은 추가 스레드를 만들지 않고 닫으며 가능한 경우 503을 보낸다. Windows에서 요청 전송과 종료가 겹치면 연결 재설정으로 관찰될 수 있다. 기존 서비스 상태 포화의 429와 구분한다.

연결은 기본 20초의 전체 수명을 가진다. 서버가 연결을 처리하기 시작한 시점부터 시간을 재므로, 헤더를 조금씩 계속 보내 소켓의 유휴 timeout만 피하는 경우에도 연결을 종료한다. 활성 처리 스레드마다 취소 가능한 daemon timer 하나를 두며, 요청 종료 때 timer를 취소하고 슬롯을 반환한다. 수락 대기열에서 보낸 시간이나 클라이언트가 연결을 시도하기 전 시간은 포함하지 않는다.

CLI는 `--max-connections`(1–256), `--request-timeout`(0초 초과, 최대 60초)을 받는다. 기존 로컬 발급 예산 64회, 세션/문제/권한/로그 상한과 만료·단일 소비는 유지한다. 화면·점수·자세 관문은 바꾸지 않았다.

## 검증

전체 `tests` Python 148개가 통과했다. 신규 소켓 테스트 3개는 잘못된 상한 거부, 불완전한 본문의 슬롯 포화와 만료 후 복구, 지속적으로 바이트를 보내는 헤더의 전체 deadline을 확인한다. 과부하 연결이 세션을 만들지 않고, 만료 후 정상 요청은 성공함을 확인했다. 테스트는 로컬 loopback과 가짜 evaluator를 사용했다.

별도로 보존된 실제 prod 채점/관문 Node bridge를 사용하는 `g4_lab.test_integration` 9개도 통과했다. worktree 위치에서 기본 경로가 없어 건너뛴 것을 확인한 뒤, 테스트가 `HANDCAPTCHA_SOURCE_ROOT`를 받도록 하고 실제 보존 소스 경로를 지정해 재실행했다. 사람·카메라·운영 시스템 검증은 아니다.

## 필요한 입력과 다음 경계

연결을 닫아도 이미 시작한 CPU 계산을 강제로 중단하지는 않는다. evaluator의 대기열·입출력·실행 전체 예산 검토는 다음 개발 작업으로 남긴다. 세션 발급 예산도 계정·사람별 한도가 아니며 새 세션으로 우회할 수 있다. 실제 계정/tenant, 다중 worker, TLS·gateway·인증된 입력, 운영 부하 조건이 있어야 운영 인수를 할 수 있다. 이 구현만으로 운영 보안이나 서비스 거부 방어를 완료했다고 판단하지 않는다.

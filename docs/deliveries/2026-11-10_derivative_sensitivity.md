# S03 — 기존 추정열의 FPS·노이즈·평활화 민감도

현재 가능한 3B 작업으로 [실행 코드](../../analysis/derivative_sensitivity.py)를 추가하고 기존 무가림 원본 1개의 보존 MediaPipe 추정 좌표에 적용했다. 새로운 사람·카메라·물리 가속도 정답을 측정한 결과가 아니다. UI와 prod 채점식·가중치·0.25 기준은 변경하지 않았다.

## 고정한 비교

720×720, 명목 24fps의 완전 검출 113프레임 좌표를 사용했다. 원래 frame index/fps로 시각을 만들고, 매 1/2/4프레임을 취해 24/12/6Hz 추정열을 만들었다. 각 113/57/29개 표본이고 처음·끝 시각은 같다. 실제 다른 FPS의 재촬영이 아니며, 누락 프레임의 보간이나 VFR 시간축 교정도 아니다.

원래 픽셀 좌표에 축별 표준편차 0/0.5/1/2px의 독립 Gaussian 합성 노이즈를 먼저 더했다. seed 7/19/43의 같은 전체 해상도 노이즈를 각 sampling에서 골라 썼다. 이후 실제 adapter의 손목 이동·손목–중지 MCP 크기 정규화를 적용했다. 노이즈는 실측 손떨림/추적 오류의 모형으로 검증된 것이 아니다.

평활화 없음과 정규화 후 Savitzky–Golay 5표본/2차식/`interp` 경계를 비교했다. 실제 초를 넣은 `numpy.gradient`를 두 번 써 미분했다. 평활화는 균일 시각에서만 허용하고 비균일 시각을 조용히 균일 grid로 바꾸지 않았다. 5표본의 처음–끝 span은 24Hz에서 0.167초, 12Hz에서 0.333초, 6Hz에서 0.667초이므로 **같은 시간 대역폭의 필터 비교가 아니다.**

24개 인자 조합×3seed=72개 계산이다. 노이즈 0의 세 seed는 동일 대조이므로 독립 표본 72개로 세지 않는다. 데이터는 한 source family이며 입력이 된 추정열 자체에도 이미 tracker 오차가 있을 수 있다.

## 결과

각 값은 관절별 2D 벡터 크기의 RMS를 취한 뒤 세 seed를 평균했다. 속도 단위는 hand-length/s, 가속도 및 가속도 차이 단위는 hand-length/s²다. 물리적인 m/s²가 아니다.

| 빈도 | 필터 | 추가 노이즈 | 속도 RMS | 가속도 RMS | 같은 sampling/필터의 무추가노이즈 대조와 가속도 차이 | 24Hz 무평활 추정과 가속도 차이 |
|---|---|---:|---:|---:|---:|---:|
| 24Hz | 없음 | 0px | 0.7141 | 7.9699 | 0.0000 | 0.0000 |
| 24Hz | 없음 | 1px | 0.7265 | 8.7088 | 3.1717 | 3.1717 |
| 24Hz | SG-5 | 0px | 0.6885 | 6.6135 | 0.0000 | 2.8763 |
| 24Hz | SG-5 | 1px | 0.6933 | 6.8327 | 1.6515 | 3.3371 |
| 12Hz | 없음 | 0px | 0.6317 | 3.9337 | 0.0000 | 5.6743 |
| 12Hz | SG-5 | 1px | 0.6109 | 3.5260 | 0.4422 | 6.3276 |
| 6Hz | 없음 | 0px | 0.5400 | 2.0502 | 0.0000 | 7.8503 |
| 6Hz | SG-5 | 1px | 0.5045 | 1.7499 | 0.1102 | 8.2163 |

24Hz의 1px 조건에서 필터는 추가 노이즈에 따른 차이를 3.1717에서 1.6515로 줄였다. 동시에 노이즈를 추가하지 않았어도 필터 자체가 24Hz 기준 가속도를 2.8763만큼 바꿨다. 6Hz로 표본을 줄이면 추가 노이즈에 덜 민감해 보이지만, 노이즈 없는 추정조차 24Hz 무평활 기준과 7.8503 차이 난다. 이것은 baseline 추정에 대한 민감도이며 어느 추정이 실제 손에 더 정확한지 판정한 값이 아니다.

따라서 낮은 가속도 오차만으로 좋은 모방 또는 좋은 필터라고 판정하지 않는다. 실제 올바른/잘못된 동작과 독립 주석에서 정보 손실·정지/오답 거부·느린 정상 수용의 추가 이득을 비교하기 전에는 가속도 가중치와 필터를 채택하지 않는다. 선택을 하더라도 validation에서 잠그고 독립 자료로 평가한다.

## 검증·산출물·남은 조건

이차식의 해석적 미분, 시간 2배의 속도 1/2·가속도 1/4, 고주파 좌표 잡음의 미분 변화, 비균일 시각/미승인 창 거부의 신규 검사 3개가 통과했다. 실제 72개 계산은 오류 없이 완료했다. [공개 집계](../../reports/derivative_sensitivity_20261110.json)에는 좌표·원본 경로·입력 해시가 없다. 입력 해시와 최종 상세 기록은 `private_artifacts/derivative_sensitivity_verified_20261110`에 따로 보관했다. 첫 실행의 72개 수치와 최종 코드 결과도 일치했다.

```powershell
python -m analysis.derivative_sensitivity --archive '../handcaptcha/left_1_experiment (2).zip' --output ../private_artifacts/derivative_sensitivity_NEW
python -m unittest discover -s tests -p test_derivative_sensitivity.py
```

이번에 S03의 원본 기반 sampling/합성 잡음 민감도는 실행했다. 실제 다른 기기의 원본, 불규칙 시각의 tracker 오차, 독립 손동작 기준과 대응 정상/오답 자료는 여전히 필요하다. S06 저장/재로드 검증과 V00/V02 공통 사전 검사 작업으로 이어간다.

# 보존 가림 수준·미디어 비용·모호성 개발 검산

## M02 보존 영상 재추적

handcaptcha 작업 브랜치 `e21a974`의 기존 ZIP에서 같은 실험 폴더에 속한 원본과 MCP/PIP/DIP 세 조건을 사용했다. 저장소 최상위의 이름이 비슷한 MP4와 ZIP 속 MP4의 바이트는 일치하지 않아 서로 대체하지 않았다. 실험 입력은 기존 본인 촬영의 비공개 연구 처리 범위에서 사용했다. 보고값은 집계뿐이다.

MediaPipe 0.10.14, OpenCV 4.11.0, Python 3.12, CPU를 사용했다. 기존 `dataset_pipeline.stage1_extract.extract_landmarks`를 video mode·최대 한 손·confidence 0.5·native 모드로 조건마다 새로 실행했다. 순서를 세 번 회전했다. 각 실행에서 실제 디코딩한 프레임 전체를 분모로 삼았다. 해상도 720×720, 표시 FPS 24, 113프레임 및 도구가 반환한 증가 타임스탬프 조건을 12회 모두 확인했다.

| 보존 조건 | 각 반복 검출 / 전체 | 반복 중앙 경과 초 |
|---|---:|---:|
| 무가림 | 113 / 113 | 1.426 |
| MCP | 113 / 113 | 1.417 |
| PIP | 88 / 113 | 1.470 |
| DIP | 52 / 113 | 1.639 |

반복 3회는 같은 파일을 세 번 읽은 것으로 독립 동작 수는 하나다. 검출률은 추적기의 출력 유무다. 원본 추적의 정확도, 사람의 모방·해석, HaMeR 성능, 인증 결과는 여기서 측정하지 않았다. 보존본은 역사적 제작 조건이 묶인 자료이므로 가림 위치만 바꾼 독립 실험으로 해석할 수 없다. 다음 실제 비교에는 새 원본·프레임 대응·독립 주석이 필요하다.

## M01/M03·D01/B02 컨테이너 경계와 분리 계측

handcaptcha의 기존 `tools/container_smoke.py`를 FFmpeg/ffprobe 7.1.5에서 실행했다. CFR MPEG4, 분수 FPS H.264, B-frame H.264 세 파일은 통과했고, 추가 음성·미검토 메타데이터·VFR 간격 세 파일은 해당 이유로 거부됐다. 별도로 기존 **자체 합성** middle-flex 연구 preview에 두 번째 비디오 트랙을 붙인 경우와, 원래 24프레임 중 23프레임만 담은 경우를 만들었다. 전자는 단일 트랙 규칙, 후자는 기간과 패킷 개수 검사로 거부됐다.

같은 합성 preview(512×420, 12fps, 24프레임)를 5회 재인코딩했다. 입력은 이미 가림이 적용된 합성 preview이며, 인코딩에는 libx264 CRF18, yuv420p, B-frame 0, 1 thread, faststart를 사용했다. 동일 기대값으로 별도 `inspect_container`를 호출해 트랙·PTS·길이를 확인했다.

| 구간 | 중앙값 또는 출력 |
|---|---:|
| FFmpeg 프로세스 시작부터 인코딩 종료 | 0.164초 |
| ffprobe 기반 컨테이너 검사와 진단 기록 | 0.115초 |
| 재인코딩한 영상 1개의 바이트 | 16,576 |

이 수치는 작은 자극의 로컬 준비비 일부다. 파일 크기는 완전 전송 1회의 미디어 payload를 계산하는 데 쓸 수 있으나 실제 네트워크 전송, 요청 단위 검증, Range 중복, CDN, 촬영·주석·검수 인건비는 별도 계측 대상이다. 화면의 poster·thumbnail·대체 rendition은 최종 제공 자산이 정해진 뒤 목록 및 응답을 각각 검수한다.

## G04·G05 가림의 대안과 시각적 단서

`python -m analysis.occlusion_counterfactual`로 손끝 접촉과 1픽셀 간격이 있는 4프레임의 장난감 장면을 비교했다. 두 원본 사이의 차이는 1픽셀이고, 그 위치를 가리면 전체 영상 픽셀이 같아졌다. 가림 밖에 실제 접촉 여부에 따라 움직이는 표시를 모사하자 1픽셀 차이가 다시 생겼다. 필요한 동작 차이가 가려졌을 때 보이는 정보만으로 답을 정할 수 없다는 구성 예이며, 실제 사람이 그 단서를 알아보는지나 실제 그림자·반사·윤곽에서 정보가 드러나는지는 별도 영상과 응답이 필요하다.

## N03 채택 가능한 설명 범위

- InterHand2.6M은 여러 수행자의 단일·상호작용 손 주석을 갖춘 데이터와 단일 RGB 이미지 기반 추정 기준선을 제시한다. 손 자세 추정 방법과 데이터 구성의 참고 근거로 사용할 수 있다. 여기서의 비교 종점인 가려진 동영상의 사람 해석, 실제 카메라 모방, 인증은 각각 자체 데이터로 측정한다. [Moon 등, ECCV 2020](https://www.ecva.net/papers/eccv_2020/papers_ECCV/html/3540_ECCV_2020_paper.php)
- HaMeR의 원 논문은 단안 입력의 3D 손 복원과 2D 키포인트가 있는 HInt 평가를 보고한다. 본 연구가 HaMeR과 비교할 때 프레임별 추정 가능성, 검출 실패, 공통 주석에서의 오차, 동작을 따라 하는 과제의 완료율을 별도 지표로 둔다. [Pavlakos 등, CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Pavlakos_Reconstructing_Hands_in_3D_with_Transformers_CVPR_2024_paper.html)

## 다음 실제 실행의 입력

1. A01–A06의 통제 촬영 원본 18개, 접촉·비접촉 비교를 포함할 경우 A07까지 21개. 새 파일은 비공개로 접수한다.
2. 원본을 서로 독립적으로 볼 주석자 2명과 사전 기준. 실제 사람 선별 및 모방·정지 비교에는 별도 동의와 대응 기록이 필요하다.
3. 모델 비교에는 확정된 모델 자산·실행 환경, 운영 평가에는 승인된 배포 자산과 검증 환경이 필요하다.

이번 결과로 새 참가자의 선별·모방, 모델 간 성능 순위, 운영 승인 또는 사업성 판정을 내리지 않는다.

## G07 비교 범위와 분모

[기존 3D 비교안](../3d_hand_object_challenge_requirements_v0.1.md)의 16개 셀을 이번 실행 기록과 분리했다. 아래 각 셀은 **실제 독립 비교 미실행**이며 성능 분모를 갖지 않는다.

| 자극 | A1 | A2 | A3 | A4 | 현재 근거 |
|---|---|---|---|---|---|
| B0 2D 가림 | 대기 | 대기 | 대기 | 대기 | 알려진 2D 개발 자료와 다른 목적의 국소 기록 |
| B1 3D 손 | 대기 | 대기 | 대기 | 대기 | 합성 영상의 렌더·컨테이너 개발 검사 |
| B2 물체 단서 숨김 | 대기 | 대기 | 대기 | 대기 | 장난감 가림 예시 |
| B3 물체 단서 표시 | 대기 | 대기 | 대기 | 대기 | 장난감 단서 예시 |

공통 자료에 비교 가능한 영상·가림·시간 기준과 독립 source family를 먼저 정한다. 예산은 준비 비용과 한 시행에서 허용하는 실행 시간·장비·시도 수를 분리해 실험 전에 기록한다. 결과표는 배정 전체, 실행 성공, 기술 실패, 중단, 각 종점 관측 수를 분리한다. 측정된 값이 없으면 공란 또는 미실행 상태로 남긴다. B2와 B3의 픽셀 차이 하나나 기존 B0 진단으로 이 표를 채우지 않는다.

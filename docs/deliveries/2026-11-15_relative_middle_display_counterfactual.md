# 같은 표시에서 다른 상대 중지 동작이 가능한지 — 2026-11-15

[원래 실행 순서](../research_goal_followups_2026-11-10.md#실행-순서와-기존-백로그-연결)를 유지하며 등록 촬영/사람 입력을 먼저 확인한다. 현재 실제 입력을 기다리는 동안 가능한 독립 개발이다. [합집합 보호의 제작 연결](2026-11-15_author_union_generation_guard.md) 이후, 보호 통과와 정답을 하나로 정할 수 있는지는 구분해 검증한다.

## 실행 전 고정한 대조 계획

현재 가림/H.26416시점의 부모인8개 모델 동작 모두를 대상으로 한다. 같은 형상·색·좌우손·root 자세·시간·다른 손가락 입력을 유지하고, 중지의 MCP/PIP/DIP bend만 기존 공학 연동1/.85/.55 비율로 바꾼다. 변경량은 **0·-5·+5·+10도** 네 가지다.0은 실제 SDK/렌더/codec가 기존 원본을 정확히 재현하는 양성 대조다.

원래2/3초 동작에서 `max(T/3,1초)`부터 `2T/3`까지 quintic 상승/복귀 pulse를 더한다. 동작 영상의 첫1초와 시작/끝 입력은 유지한다. 이는 변수를 줄이는 추가 공학 대조이고 안전 속도/가속도/편안함의 근거가 아니다. 관절 값을 clipping하거나 model 범위를 재보정하지 않는다. 새 난수는 뽑지 않는다.

기존 UI의 초기500ms 무가림+500ms fade는 첫 **정지 프레임**을 보여 주는 별도 준비 구간이다. 이 대조에서 첫 프레임은 같고 source 동작 첫1초까지 추가로 고정하지만, 이를 UI 시간축이라고 해석하거나64조합을 새로 실행한 결과로 표시하지 않는다. prod UI는 그대로다.

계획한 SDK 계산은 중립2개 +8부모×4조건×25프레임 =802개다. 기존 정확한 CPU 모델 환경에서 원본 neutral/0대조의 실제 SDK 출력이 일치하는지 먼저 확인한다. BIO-09 고정 모델 제약·샘플 삼각형 교차·현재 pending BMC를 각각 검사하고 모든 대안을 연구용 격리한다. **모델 제약을 만족한 대안도 사람의 생물학적/편안한 유효 정답으로 확정하지 않는다.**

이후 기존26pin 영상 환경에서8부모×4조건×두시점 =64개/1600프레임을 실제 렌더한다. 카메라·구도·부모의 가림 반경/원 픽셀·형상/색·시간·효과를 다시 맞추지 않는다. 현재 actual author-union 보호 면을 그대로 사용하며 Stage7·ROI·2픽셀 codec core·비목표 tip patch·채널30·외부MAE2.0 기준도 유지한다. 허용된 경우만 가림/H.264를 만들고 전체 프레임을 부모와 비교한다.

## 무엇을 근거로 판단하는가

- source(무가림), 가림 후보, 최종 H.264를 각각 실제 decode해서 픽셀 차이/변경 프레임·원 안/밖 차이와 전체 파일 바이트의 정확한 일치 여부를 기록한다. ‘비슷해 보임’이나 임의 오차 허용값을 동일 화면의 증명으로 쓰지 않는다.
-0대조의 실제 native 출력과 source/최종 decode가 부모와 다르면 재현 문제로 실행을 거부한다. 모델이 반환한 pose/root와 실제 숨은 관절 좌표 변화도 확인한다. 전체 손의 단순 깊이 평행이동을 대안으로 세지 않는다.
- 비zero 대안에서 상대 중지 좌표가 실제 바뀌고 모델/표면·가림 관문을 만족하면서 최종 픽셀이 정확히 같다면, **이 생성기/조건의 표시가 단일 모델 답을 유일하게 정하지 못한 사례**로 기록한다. 사람에게 유효한 복수 정답이나 실제 공격 성공으로 승격하지 않는다.
- 최종 픽셀이 다르더라도 사람이 그 차이로 동작을 이해할 수 있다는 증거는 아니다. 반대로 특정한 유한 대조에서 같은 픽셀이 없었다고 역문제의 정답 유일성/보안을 입증하지 않는다.

source 동작 첫1초 입력을 고정해도 lossy codec의 rate control/lookahead가 이전 프레임에 영향을 줄 수 있으므로, 실제 decode의 첫1초 일치 여부도 별도로 기록한다. 현재 실험은 고정 full-mask rendition 비교이며 실제64 UI 조건·기기·참가자 효과는 별도 입력/관문이다.

## 기록·선행 조건

원 모델 사용 범위·부모 SDK와 기본 보호 제작의 완료 receipt·원출처/환경을 실행 전에 묶는다. 새 출력/record만 사용하고 이전 원본/receipt를 수정하지 않는다. native 좌표 생성 시간32행과 이후 source/가림/H.264 영상별 시간을 분리한다. 공통 모델 준비·캐시·별도 프로세스 사이 보관/대기·자체 CPU와 FFmpeg 자식CPU 미측정을 구분하고, 임의로 더한 운영 end-to-end 지연을 만들지 않는다.

근거/현 생체 한계의 미확인 범위는 [학술 색인](../academic_reference_index.md), 채점/관측 한계는 [3D 채점 설명](../3d_scoring_baseline_explanation_2026-11-14.md)에 연결한다. 원래 촬영·사람·독립 주석·모델/운영 입력이 들어오면 앞 단계부터 우선하며 풀/브라우저 채택·신규 독립 family는0개다. 실제 결과와 필요한 다음 입력은 실행 뒤 추가한다.

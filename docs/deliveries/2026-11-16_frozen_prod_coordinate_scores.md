# 고정 prod 원문 좌표 채점 진단 — 2026-11-16

## 실행 전 명세

인계 순서에 따라 등록 촬영21행의 원본 경로0개와 비어 있는 선별 응답 양식을 확인했다. 현재 연구 HEAD는 `ec7aec0`, 시작 작업트리는 깨끗했다. 완료한 계보/native/display receipt 세 건의 등록 출력1104개는 `RECORDED_FILES_MATCH`/`EXITED_ZERO`였다. 기존 모델 생성·렌더를 재실행하지 않는다.

질문은 같은 최종 파일에 연결된 다른 모델 답, 정지/부분 동작과 결측이 **현재 좌표 채점 수치**에서 어떻게 취급되는지다. 실제 모방·검출·UI 시간·200ms hold·인증 시험은 아니다. 가중치와 기준을 보정하지 않는다. 결과는 개발 진단이며 독립 평가/사람 타당성/공격 성공으로 해석하지 않는다.

입력은 기존 display64시점의 `reference.private.json`이다. 각 프레임은 `known_model_reference_no_detector`인25프레임 모델 투영이다. 각 parent/view의 delta0을 기준으로 쓴다. exporter의 `source_info`를 명시적으로 prod가 읽는 `video_info`로 연결해 실제512×420 너비/높이를 적용하고 mirror=false로 고정한다. 좌우손은 이미 저장된 각각의 투영을 쓴다. prod의720×720 fallback과 구분하며 실제 UI 자료 적재를 검증했다는 주장이 아니다.

prod SHA256은 인계의 `0d82dd439fe7976f8b860eb82e654e6f5637b2d7a3fcce2d02f2f99e5f5bea11`과 정확히 같아야 한다. [JS 실행기](../../validation_v03/frozen_prod_score.cjs)는 constants·랜드마크 변환·keyframes·각도·METRICS/computeScores를 원문 그대로 추출하고 구간과 hash를 남긴다. Python 수식 재구현을 사용하지 않는다.

64시점 각각에 다음8조건×2구간 방식을 적용해1024개 수치를 계획한다. self·정지 등은 같은 부모의 반복 진단이며 독립1024표본이 아니다.

구간은 전체0–24 한 구간과 prod `findKeyframes` 결과의 인접 구간 두 방식이다. 기준 slice의 양끝 포함 규칙을 쓰고 응답 경계 프레임도 양쪽 진단 구간에 포함한다. 이는 합성 구간 상태이며 실제 사용자 세션 분할/이벤트 재현이 아니다. `computeScores`의 검출 필터·3개 미만 구간 건너뛰기·index resampling을 그대로 따른다. 결측을 시간 보간/복구하지 않는다.

점수≥0.25와 동기 인덱스/각 keyframe의 각도<38도를 별도로 기록한다. 각도는 `ppSingle` 후 `angleErr`이며 hold를 추정하지 않는다. mDA는 sliding window, mAc는 index 이차 차분이며 SI 가속도/진짜 DTW가 아니다. self 점수를1로 강제하지 않는다.

Node v24.18.0, 기존 offline Python26pin을 쓰고 새 설치는 없다. 실행 예산300초·Node호출별30초, 새 비공개 `fpsd_20261116_v1` 출력과 별도 `frozen_prod_score_record_20261116_v1` 기록을 사용한다. 전체 worktree/코드·prod/Node·등록 입력·기존 display receipt/출력을 사전 snapshot에 묶는다. 진행/상세1024행·추출구간·집계를 보존하고 실패 시 같은 root를 재사용하지 않는다. wall과 Python 자체CPU를 기록하며 Node자식CPU는 미측정이다. 실행 중 worktree 편집/커밋은 하지 않는다.

이 단위 뒤에는 [원형 없는 생성](../template_free_constrained_generation_2026-11-16.md)의 TF-01 적용표와 TF-02 사전등록을 진행한다. 실제 촬영/사람 입력이 접수되면 원래1→2→3A 우선이다.

### 실행 준비 실패와 새 실행 ID

v1은 subprocess 시작 전 snapshot 단계에서 거부됐다. 상속한 완료 receipt의 빈 stderr파일을 별도 입력으로 나열했는데, 기존 `snapshot_file`은0byte 입력을 거부한다. 원본·검사기를 수정하지 않고 v1설정/준비 실패 기록을 보존한다. 실험 실행시간/완료 결과는 없다. v2에서는 빈 이전 로그1개를 snapshot 직접 입력에서 제외하고, 원래 receipt와 `bound`의 전체 산출물/기록 검산으로 해당 빈 로그까지 확인한다.914개 입력과 v2설정 자체가 새 snapshot 대상이다. 새 실행/결과 root는 각각 `frozen_prod_score_record_20261116_v2`, `fpsd_20261116_v2`이며 조건/판정은 같다.

# 두 접촉 모형과 깊이 대안쌍 — 2026-11-13

## 완료 범위

[실행 순서](../research_goal_followups_2026-11-10.md)의 6단계 G02/G04와 [3D 도입 관문 1–2](../3d_hand_object_challenge_requirements_v0.1.md)를 위한 부분 개발이다. 앞 단계의 촬영·선별·실제 모방/정지·독립 주석/모델 입력은 대기다.

handcaptcha 코드 `7f86a97`에 두 작성 접촉 모형을 추가했다. `opposed_two_tip`은 엄지/검지 끝, `three_tip_front`는 엄지/검지/중지 끝을 구에 접촉시킨다. 접근→유지→이동→해제 중 20개 뼈 capsule과 구의 간격·고정 뼈 길이·시간 순서·처음/마지막 이격·유지 구간 접촉을 검사한다. 안정적 grasp나 해부학적 손을 입증하지 않는다. 손바닥 mesh·자기 충돌·중력·마찰·force closure는 없다.

## 비교와 실제 결과

| 경우 | 변경 | 결과와 해석 |
|---|---|---|
| 원래 모형 | 작성한 손과 구 | 접촉 proxy 통과 |
| 손만 깊이 반전 | 손 z만 반전, 물체의 실제 3D 위치 고정 | 접촉/비관통 실패. 물체의 실제 깊이를 아는 조건부 검사 |
| 손·물체 깊이 반전 | 손과 구 z를 함께 반전 | 접촉 proxy 통과, 화면 픽셀 동일. 복수 3D 설명 가능 |

첫 대조는 일반 영상에 없는 물체 깊이를 정답으로 제공하므로 같은 영상만 받는 사람/AI의 공격 성능 비교가 아니다. 두 번째는 이 렌더러에서 단일 3D 정답을 강요하면 안 되는 반례다. XY 정사영 뼈 그림·구의 선 윤곽에는 depth buffer·표면 가림·그림자가 없다. 실제 장면에서도 구분 불가능하다는 결론은 낼 수 없고, 깊이 단서를 추가하면 픽셀 동일성이 깨지는지 다시 검사해야 한다.

픽셀 검사 분모는 서로 다르며 같은 산출물의 반복 검사다. 합쳐 독립 표본으로 세지 않는다. seed 7/19도 독립 촬영 계열·사람 수가 아니다. 실패한 네 사례에는 유효 후보/rendition을 발급하지 않았다. 모든 recipe/프레임의 반경 교집합을 사용했고 gate를 완화하지 않았다.

실행 전 코드·입력 도구·26-pin 환경 snapshot과 실행 후 확인은 일치했다. 실행 코드 기준은 `7f86a97`이며 이후 문서 커밋으로 당시 기록을 덮어쓰지 않는다. 대표 원본/가림 프레임도 비공개 추출해 정사영 선 그림의 모습을 확인했다. [공개 집계](../../reports/grasp_counterexamples_20261113.json)만 Git에 남긴다. 영상·좌표·개별 해시/보고서는 비공개 영구 보관한다. 새 모델 추론·외부 업로드·root prod 변경·운영 승인은 없다.

## 다음 순서와 필요한 입력

1. 원래 1단계 촬영 21개 접수, 2단계 처음 보는 사람의 선별 응답/독립 주석, 3A 같은 사람·문제·카메라의 모방/정지 자료, 3B 독립 보정/평가 자료가 우선이다. 등록 입력을 재확인하고 없는 실제 실험은 대기로 남긴다.

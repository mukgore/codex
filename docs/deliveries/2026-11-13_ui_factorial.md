# prod 기반 UI 초기 노출·가림 페이드와 전체 조합 — 2026-11-13

## 실행 순서

기존 단위인 V05 채점 대기/전송/응답 예산을 `c3ccc8a`로 완료·push한 뒤, 명세를 다시 읽고 UI 작업을 진행했다. 연구 실행 순서와 실제 실험의 선행 조건을 유지하며, UI에서는 A1/A2 손 선택·유지 → B1 중첩 → B2 안내 → E1 개별/조합 검사 순서를 따랐다. E2 실제 관찰·효과·채택은 아직 입력 대기다. [추가 명세](../ui_factorial_followup_2026-11-13.md)에 사용자 요청과 64조건을 연결했다.

## 완료한 코드와 개발 검사

구현 커밋은 handcaptcha `c2ee863`이며 지정 `work/todo-consolidation-20261103`에 push했다. 별도 worktree를 원격 기준에서 만들어 원래 checkout의 다른 로컬 커밋은 함께 push하지 않았다.

handcaptcha의 [prod_ui_factorial](https://github.com/mukgore/handcaptcha/tree/work/todo-consolidation-20261103/experiments/prod_ui_factorial)은 root prod에서 만든 비교본이다. 손 선택 연결·중첩·A 문구·B 그림·C 가이드 손금·초기 노출의 모든 64조합을 선택하고 조건표를 저장할 수 있다. 기존 A/B/C 안내도 결합할 수 있게 했으며, 단일 기존 버전은 유지한다.

첫 목표의 같은 정지 프레임을 무가림으로 500ms 보여 주고, 가림본으로 500ms 동안 페이드한다. 끈 조건도 같은 1초 동안 가림본을 보여 주며 관문·점수 기록을 기다린다. 선택 손 추적은 계속한다. 중첩은 카메라 표시용 복사본에만 그리며 검출 입력은 원래 카메라 영상이다. root 점수 산식, native 관문/기록 함수 본문, 원래 inline CSS는 비교본과 동일함을 검사했다. 실제 배포본을 교체하지 않았다.

## 현재 원본으로 준비한 비공개 검토 자료

기존 무가림 원본의 ZIP 해시와 보존 FFV1 세 조건의 해시를 대조했다. 같은 원동작의 무가림/검정/손가락색을 브라우저용 H.264 CRF18·yuv420p로 만들고 같은 ZIP의 대응 좌표를 비공개 묶음에 준비했다. 모두 720×720·24Hz·113프레임, 비디오 단일 트랙과 프레임별 PTS를 ffprobe로 확인했다. 손실 인코딩이므로 원래 FFV1의 픽셀 완전 일치 검사를 이 파생본에 소급하지 않는다.

이 묶음은 새 원본이 아니라 알려진 개발 원본 **1개**의 파생본이다. 원본·좌표·개별 해시는 공개하지 않으며 운영 공개를 허용하지 않는다. 새 UI는 로컬 파일로만 이를 읽는다. 영상과 사람 응답을 외부로 업로드하지 않는다. 현재 실제 카메라·사람이 이 자료로 수행한 새 결과는 없다.

## 필요한 입력과 다음 단계

64조합을 포함하는 실제 배정은 동의한 사람·독립 원동작·기기·주 지표·표본/수용 기준이 필요하다. 같은 사람에게 같은 원동작 답을 여러 조건으로 반복 보여 주지 않는다. 초기 노출은 추가 정보이므로 사람/모델 비교에서 둘 다 같은 표시 프레임만 받도록 한다. 연구용 화면에 선택한 전체 무가림 파일을 공격 모델의 비교 입력으로 넘기지 않는다.

원래 우선순위의 신규 통제 촬영 21개와 모호성 선별, 실제 대응 모방·정지 자료, 독립 주석·모델 실행, 운영 환경은 여전히 입력 대기다. 3D 생성의 G0 우선·공급 비용/강한 공격 비교도 전체 범위에 남는다. 실제 응답이 있어야 E2 채택 결정과 다음 단계 효과 평가를 할 수 있다.

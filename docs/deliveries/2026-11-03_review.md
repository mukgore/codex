- handcaptcha: Stage6/7 가림 검증 보강, 회귀 테스트, 큰 손 선택·분리/중첩 화면 시연, README·ROADMAP·gitignore.

- 새 파일과 패치 내용을 검토하고 키·토큰·비밀번호 패턴을 검사했다. 이번 전달본에서 공개하면 안 되는 키나 참여자 원자료를 발견하지 않았다. 기존 저장소 전체 이력 감사는 수행하지 않았다.

## 적용과 검사

기준은 codex `6cfe1b14683b908d7ad47ae864ca20545e279404`, handcaptcha `b4d96d1e84324edd5376f9258f9863a0b6282a5a`이며 확인한 원격 main과 일치했다. 기존 사용자 작업본을 보존하고 별도 복제본의 `work/todo-consolidation-20261103` 브랜치에서 작업했다.

두 패치 모두 실제 `git apply --check`에 통과했다. 적용 결과 10개/14개 파일은 줄바꿈 차이를 제외하고 전달 파일 사본과 전부 일치했다. 이후 codex 문서의 이전 업로드 실패 표시를 과거 시점 기록으로 구분하고 이 기록·원본 manifest를 추가했다.

| 검사 | 결과 |
|---|---|
| codex 수학 primitive | 12/12 통과 |
| codex 새 점수 비교 CLI | 7/7 통과 |
| handcaptcha 기존 함수 검사 | 17/17 통과 |

합계 58개이며 같은 검사 반복을 중복 계산하지 않았다. 기존 함수 17개는 무인자 함수를 실제 `unittest.FunctionTestCase`로 실행했다. codex 전체 unittest 탐색에서는 기존 `test_calculations` 모듈의 `openpyxl` 의존성이 없어 import 오류가 발생했다. 해당 기존 검사 4개는 이번 통과 수에 포함하지 않았다. 추가 의존성 설치는 완료하지 않았으며 필수 조건으로 삼지 않았다.

실행 환경은 Python 3.10.3, NumPy 2.2.6, OpenCV 4.12.0, Node v24.18.0이다. 실제 카메라·사용성·운영 배포·새 사람 또는 독립 공격 실험은 수행하지 않았다.

일반 변경 파일의 `git diff --check`는 통과했다. codex에 보관하는 원본 unified diff의 빈 context 줄은 공백 한 글자가 필요한 패치 형식이므로 해당 `.patch` 파일을 공백 검사에서 제외했다. 원본 패치의 내용·해시는 보존했다.
